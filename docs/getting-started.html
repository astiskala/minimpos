Guide

Getting started

From an Adyen account to your first payment on the terminal. Most of it is done once, in your Adyen Customer Area and in Mini mPOS's Settings. Allow about half an hour, plus the time Adyen takes to deploy the app.

1. Before you start

  • An Adyen account with in-person payments (Terminal API), and a user for the Customer Area that can see device settings, upload apps and manage payments.
  • Adyen Android terminals running Android 9 or later, for example the S1F2, S1F4Pro, S1E4Pro, S1E2L, AMS1, S1U2 or SFO1. Printing needs a model with a printer; scanning receipts, barcodes and setup codes from another terminal needs a camera.
  • Or an Android tablet or phone, to take payments on a terminal over your network or the internet, or with Tap to Pay (see From a tablet or phone).
  • Optional: an SMTP mail server (host, port, user and password) if you want to email receipts.
  • Optional: an API credential for Adyen's Checkout API, if the app should capture tips on the receipt and pre-authorizations itself (see Captures and the Checkout API).

Mini mPOS is an independent project, not an Adyen product. Try everything on TEST terminals before you take live payments.

2. Try it without a terminal

On an Android emulator or phone, Mini mPOS takes payments with its built-in simulator, so you can explore every screen first. Install it from the source code:

git clone https://github.com/astiskala/minimpos.git
cd minimpos
./gradlew :app:installDebug

Under Settings › Simulator you choose how simulated payments end: approved, declined, canceled, timed out or with a busy terminal. The simulator also stands in for the Checkout API, so tips and captures can be tried too.

3. Create a shared key

Mini mPOS encrypts every request to the terminal with a shared key, which you create in the Customer Area:

  1. Go to Devices › Device settings › Integrations › Terminal API › Encryption key, for the terminals (or the store or account) that will run Mini mPOS.
  2. Create the key, and note its key identifier, passphrase and version. Select the pencil icon to see them again later.

4. Put the app on your terminals

  1. Download minimpos-<version>.apk from the latest release. It is signed by the maintainer, which Adyen requires (an unsigned APK uploads, but the terminal refuses to install it).
  2. Upload it and deploy it to your terminals as described in Adyen's app deployment guide. Adyen converts the app for the terminals and installs it on the ones you choose.

Building and signing your own APK works too; see the README. Whichever you choose, stick to it: the Customer Area only accepts later versions signed with the same key.

5. Connect it to the terminal

  1. Open Mini mPOS on the terminal and tap Connect to this terminal on Home (or go to Settings › Terminal).
  2. Enter the key identifier and passphrase, and the version if it isn't 1.
  3. Tap Save and test (or the keyboard's Done key). The result is shown straight away.

The terminal's ID (POIID), its address and whether it is a TEST or LIVE terminal are detected, so there is nothing else to enter. Settings › About shows what was found; a TEST terminal also shows TEST in its own status bar. While the currency follows the device's region, the result also names it: check that it is the one your Adyen account takes payments in (Settings › Payments).

To try a real terminal from a phone or emulator instead, choose Payments go to › A terminal on your network and also enter the terminal's IP address and POIID (as on its Device info screen).

From a tablet or phone

Mini mPOS also runs on Android tablets and phones: install the same APK there, then choose under Settings › Terminal › Payments go to:

A terminal on your network
The recommended way for a tablet at the counter. The tablet sends requests to the terminal over your local network, encrypted with the shared key, so no API key is needed. Enter the terminal's IP address and POIID as well as the shared key. Mini mPOS does not have to be installed on the terminal.
A terminal over the internet (cloud)
For a tablet and a terminal on different networks. Requests go through Adyen's Cloud device API, with an API key instead of the shared key. In the Customer Area, under Developers › API credentials, create a credential for this device with the Cloud Device API role (and the Checkout webservice role if the app should capture tips and pre-authorizations). Enter the merchant account and API key under Adyen API, then tap Find connected terminals and choose the terminal (or type its POIID). Whether the key is TEST or LIVE, and the data center to use, are found when it connects.
Tap to Pay on this phone
Shoppers tap their card or phone on the phone itself, in the Adyen Payments app; there is no printer, so receipts are emailed. The phone needs NFC and Android 12 or later, and must be Google-certified. Ask Adyen Support to enable Tap to Pay on Android and the Adyen Payments app role, and install Adyen Payments Test (TEST) or Adyen Payments (LIVE) from Google Play. Enter the shared key and the merchant account, then under Tap to Pay the Payments app API key (a credential with only the Adyen Payments app role) and, to set it up for one store, its store ID. Tap Set up Tap to Pay: the Payments app opens to register the phone. Each payment then opens the Payments app and returns to Mini mPOS. To stop, tap Remove this phone.

Until everything is entered, Home says what is still missing and opens Settings › Terminal.

In the cloud and for Tap to Pay, an Adyen API key is stored on the device, encrypted with the Android Keystore. Adyen advises keeping API keys on a server, and Mini mPOS has none: use a credential for this device only, set an admin PIN, and revoke the key in the Customer Area if the device is lost.

6. Set up your business

Everything below is in Settings.

Payments
The currency (any of the 138 Adyen processes; automatic follows the device's country), whether checkout asks for a transaction reference (off at first) and a reference prefix, saving cards (off at first: choose whether the shopper reference comes from a customer reference or the email, then whether Save card starts switched on, for sales and for pre-authorizations, and the recurring model), when to ask for the shopper's email, and whether Tip on the receipt starts switched on at checkout.
Tax
Your named tax rates (such as GST 10% and GST-free 0%), whether prices include tax, the default rate for new products, and a Charge tax switch. A new installation starts with the standard rate of the device's country where the app knows it (in Japan also the reduced 8% rate), and a 0% rate; in the US and Canada only the 0% rate, with tax added on top of prices. Check them before you add products.
Receipts
Business name, address, tax ID, phone, title and footer; what the receipt shows (tax breakdown, references, refund QR code); whether the terminal has a printer (detected automatically), printing automatically (on at first), the merchant copy and the characters per line.
Email (SMTP)
Your mail server, sender, an optional blind copy and the subject, with a test email.
Security
An admin PIN for Settings and Products, and how soon they lock again. Set one before the terminal goes on the counter.
Data
How long sales and refunds are kept, clearing the history, and setting up other terminals from this one (see More terminals).

Language and receipts

Mini mPOS supports English, Simplified Chinese and Japanese. On Android 12 or earlier, it follows the device language. On Android 13 or later, choose a language in Android's system app-language settings.

New installations use localized receipt defaults and sample labels. Changing language does not translate existing receipt titles, footers, tax names, email subjects or transferred product catalogs. Review them in Settings › Receipts, Settings › Tax, Settings › Email (SMTP) and Products, especially if you already have settings or import them from another terminal.

Adyen-generated payment receipt data is kept verbatim and follows the payment terminal's own configured receipt language. Wide Chinese and Japanese characters use two columns in plain-text receipt layout. Japanese receipts also show taxable amounts by tax rate, marked 税込 (tax-inclusive) or 税抜 (tax-exclusive). Check the printed layout with Settings › Receipts › Print test receipt.

Mini mPOS receipts are not official Chinese 发票 and are not guaranteed to qualify as Japanese 適格請求書 (qualified invoices) or 適格簡易請求書 (qualified simplified invoices). Per-rate totals alone are not a complete invoice system. Separately verify reduced-rate item marking, tax rounding, registration and all other applicable requirements. For context, see the Japan National Tax Agency's qualified simplified invoice guidance and the China State Taxation Administration's VAT invoice verification service. These links are reference material, not a claim of compliance or legal advice.

7. Add your products

In Products, tap + and enter a name, price and tax rate, and optionally a category and a barcode (type it or scan it). Categories, on the second tab, group the products on the sale screen.

A product can also be a pre-authorization product, such as a deposit or a hire bond; see Pre-authorizations.

To copy the catalog to another terminal, see More terminals.

8. Sell and refund

  • New sale: tap products, scan a barcode or add a custom amount, then Charge. At checkout, add a reference and (with the shopper's consent) save the card, if switched on in Settings › Payments, then Pay and follow the terminal.
  • Receipts print as one slip with your header, the items, tax, the card receipt and a refund QR code, and can be emailed. On a tablet or phone, Share receipt sends it as an image through Android's share sheet, to a messaging app for example.
  • Refund: scan the QR code on the receipt, or open the sale in History. Refund everything, some items, or an amount. Adyen processes refunds asynchronously, so the app shows them as requested; the final outcome is in your Customer Area.
  • History groups transactions by day with daily totals (and tips). Needs attention lists payments whose result was not confirmed, which you can check again with the terminal.
  • Find a transaction by typing in History's search field (on small terminals, tap the search icon first): a merchant or PSP reference, auth code, customer reference, shopper email, the card's last 4 digits, or an amount such as 34 or 34.50. Every word must match, so visa 34 finds Visa payments of $34.00, and a refund shows up with its sale's shopper and card. Payment method, at the start of the filters, narrows the list to one card brand or a wallet (Apple Pay, Google Pay, Samsung Pay).

9. Captures and the Checkout API

Tips on the receipt and pre-authorizations are taken with manual capture: the amount is only held until it is captured. Mini mPOS can capture them (and adjust what they hold) through Adyen's Checkout API, or leave the capture to you in the Customer Area.

  1. In the Customer Area, go to Developers › API credentials and create a credential for the terminals with only the Checkout webservice role. Generate its API key.
  2. In Mini mPOS, go to Settings › Terminal and tap Checkout API to open it, enter your merchant account and the API key, and tap Save and test API key. The key is stored encrypted on the terminal; the test changes nothing.
  3. LIVE terminals also need your live URL prefix, from Developers › API URLs; the field appears once the terminal is known to be LIVE. Whether a terminal is TEST or LIVE is detected from its certificate (in the cloud, from the API key; with Tap to Pay, from the Payments app installed).
  4. Optional: ask for synchronous adjustments with Devices › Developer › Additional data › Return adjust authorisation data. The app then knows straight away whether a higher amount was authorized; otherwise adjustments are confirmed later, in the Customer Area.

Adyen confirms captures asynchronously, so the app shows them as Capture requested; Mini mPOS has no backend for webhooks, so the final outcome is in your Customer Area. A capture whose result is unknown can be sent again from History without capturing twice.

Without an API key, the app records what to capture (Capture in Customer Area) and you capture it under Payments › Payment list: select the PSP reference shown in History, then Capture payment.

Payment links

With the Checkout API set up, a sale can also be paid with an Adyen payment link instead of on the terminal: the customer pays on Adyen's payment page, on their own phone or computer.

  1. Before the first LIVE link, add your terms and conditions in the live Customer Area under Payments › Payment link settings.
  2. In Mini mPOS, switch on Settings › Payments › Offer payment links and choose how long links work (24 hours by default, up to 70 days).
  3. At checkout, tap Send payment link under Pay. The customer scans the QR code shown, or you Email link (with an unpaid receipt), Print link or, on a tablet or phone, Share link.

While the link is shown the app checks every few seconds whether it was paid, and again when you tap Check payment. History lists the sale as Awaiting payment until it is paid, it expires or you Cancel link. Adyen only sends a paid link's PSP reference to a webhook, which Mini mPOS has no backend for, so refund a paid link in the Customer Area (Payments › Payment list). Payment links are for sales only, and not available with the simulator.

10. Tips on the receipt

Where customers add a tip after paying, as in restaurants and bars, Mini mPOS follows Adyen's tipping on the receipt flow: the bill is pre-authorized, the customer writes a tip on the printed receipt and signs it, and the bill plus tip is captured.

With Adyen, once

  • Ask Adyen Support to set up pre-authorization for your payment methods, and to enable overcapture: tips up to 20% of the bill are captured on top of the amount authorized. Wallets and debit cards may not support the flow.
  • Optional but recommended: the Checkout API, so the app captures the tips itself.

In Mini mPOS

  1. At checkout, switch on Tip on the receipt (shown on terminals with a printer; make it the default under Settings › Payments › Tipping), then Pay.
  2. The result shows Awaiting tip. Print the receipt: it has blank TIP and TOTAL lines, and the merchant copy (printed after it under the default merchant copy setting) a SIGNATURE line.
  3. When the customer has filled it in, tap Enter tip, on the result screen or later from History (the Awaiting tip filter lists them). Type the tip or the total, or tap No tip, and confirm.

The app then captures bill plus tip. A tip above 20% of the bill is authorized first; if the card issuer refuses it, nothing is captured and you can enter a smaller tip (or none). Once entered, a tip cannot be changed, and the sale can be refunded like any other, tip included. Until then it can only be canceled, from its History entry.

Holds expire, so enter tips promptly, for example at the end of each shift.

11. Pre-authorizations

A pre-authorization holds an amount on the shopper's card without charging it, for example a deposit for an event, a room or equipment hire. You capture it later (the amount actually owed, up to the amount held), or cancel it to release the hold.

With Adyen, once

  • Ask Adyen Support to set up pre-authorization for your payment methods. Whether a card allows it depends on the card scheme and your business's merchant category code (MCC); see Adyen's pre-authorization guide.
  • You do not need to switch your account to manual capture: Mini mPOS asks for manual capture on each pre-authorization only (authorisationType=PreAuth with manualCapture=true), so normal sales are still captured as your account is set up.
  • Optional: smart pre-authorization (Customer Area, Devices › Device settings › Payment features) lets the terminal ask for another card when the one presented does not support it.

In Mini mPOS

  1. In Products, edit (or add) the product and switch on Pre-authorization product. It then no longer appears in New sale.
  2. Home now shows Pre-authorize beside New sale. A pre-authorization holds a single item, so tapping a product (or adding a custom amount, or scanning a barcode) goes straight to checkout; tap Pre-authorize there.
  3. Once saving cards is switched on (Settings › Payments › Saving cards), Save card starts switched on at checkout, so late costs can be charged once the pre-authorization has been captured. The receipt is titled PRE-AUTHORIZATION and shows the amount held.

Capture, adjust or cancel

  • Capture: open the pre-authorization in History and tap Capture. It proposes the amount held; capturing less releases the rest, and capturing more first asks the card issuer to authorize it. Once captured, it can be refunded from History.
  • Adjust amount changes what it holds without capturing (the same amount extends the authorization).
  • Both need the Checkout API. Without it, capture in the Customer Area (Payments › Payment list, select the PSP reference, then Capture payment), and tap Record capture in the app so History shows it.
  • Cancel: tap Cancel pre-authorization. If it has already been captured in the Customer Area, Adyen refunds it in full instead.

Holds expire, after as little as a few days for some card schemes, and the shopper sees the amount as pending on their statement until then. Capture or cancel promptly; History's Pre-auths filter lists them, and the day totals show what is still held.

12. More terminals

Once one terminal is set up, set up the others from it with a few QR codes instead of entering everything again. Install the same version of Mini mPOS on all of them.

  1. On the terminal that is set up, go to Settings › Data › Share with another terminal (or the menu in Products). Choose what to copy: the catalog, the settings, and the passwords and keys (shared key passphrase, Checkout API key, Payments app API key, SMTP password and admin PIN). Tap Show QR codes.
  2. On the new terminal, choose Set up from another terminal in the same places and point its camera at the codes, in any order.
  3. Choose whether the catalog is merged into the new terminal's or replaces it. To bring the passwords and keys, type the transfer code the first terminal shows above the codes; without it, the rest is imported and they are skipped. Tap Import.
  4. Check the connection under Settings › Terminal with Test connection.

The settings replace the new terminal's, except where payments go, its own address and ID, its Tap to Pay setup, its TEST/LIVE environment and the simulator. The shared key only works on both terminals if the Customer Area assigns the same key to them (for example at store or merchant account level); otherwise enter each terminal's own key. The transfer code is new each time and only shown on the first terminal, so a photo of the QR codes does not reveal the passwords.

13. Before you go live

  • Run a few sales, refunds and (if you use them) tips and pre-authorizations on a TEST terminal with Adyen's test cards.
  • Check the receipt layout with Settings › Receipts › Print test receipt.
  • Set an admin PIN, then deploy the same version to your LIVE terminals and enter their shared key.

14. If something goes wrong

Home says “Payments cannot reach the terminal”
Check the key identifier, passphrase and version in Settings › Terminal against the Customer Area, and tap Save and test.
The terminal refuses to install the app
An error such as INSTALL_PARSE_FAILED_NO_CERTIFICATES means the APK was not signed. Upload the signed minimpos-<version>.apk from the releases page.
A payment's result is unknown
Open it from History (Needs attention) and tap Check result again. Check the Customer Area before charging the shopper again.
A capture failed or its result is unknown
History shows why. Fix the Checkout API settings if needed, then tap Retry capture: sending it again cannot capture twice.
Tap to Pay comes back without a result
The payment's result is then unknown, and the Payments app cannot be asked for it again: check the Customer Area (Payments › Payment list) before charging the shopper again.
“The codes could not be read”
The other terminal may run a newer Mini mPOS. Update both to the same version and scan again.
