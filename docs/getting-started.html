Guide

Getting started

From an Adyen account to your first payment. Most of it is done once, in your Adyen Customer Area and in Mini mPOS's Settings. Allow about half an hour, plus the time Adyen takes to deploy the app to your terminals.

1. Before you start

  • An Adyen account with in-person payments (Terminal API), and a user for the Customer Area that can see device settings, upload apps and manage payments.
  • Adyen Android terminals running Android 9 or later, for example the S1F2, S1F4Pro, S1E4Pro, S1E2L, AMS1, S1U2 or SFO1, to run Mini mPOS on. Printing needs a model with a printer; scanning receipts, barcodes and setup codes needs a camera.
  • Or an Android tablet or phone, to take payments on a terminal over your network or the internet, or with Tap to Pay (see On a tablet or phone).
  • Optional: an SMTP mail server or a mailbox at a common email provider, if you want to email receipts.
  • An API credential for Adyen's Checkout API, which every payment needs: the app captures tips on the receipt and pre-authorizations and sends payment links through it (see The Checkout API and captures).

Mini mPOS is an independent project, not an Adyen product. Try everything on TEST terminals before you take live payments. This guide only covers what Mini mPOS needs; for how your Adyen account, Customer Area and terminals work, follow the links to Adyen's own documentation, which stays up to date.

2. Try it without a terminal

On any Android phone or emulator, Mini mPOS takes payments with its built-in simulator, so you can explore every screen first. Download minimpos-<version>.apk from the latest release and open it on the phone (Android asks you to allow installing apps from your browser or file manager), or build it from the source code:

git clone https://github.com/astiskala/minimpos.git
cd minimpos
./gradlew :app:installDebug

Under Settings › Simulator you choose how simulated payments end (approved, declined, canceled by the shopper, timed out, a busy terminal, or at random), how long they take and whether there is a printer; printed receipts then appear on the screen. The simulator also stands in for the Checkout API, so tips, captures and pre-authorizations can be tried too. Payment links are not simulated.

3. Create a shared key

Mini mPOS encrypts every request to a terminal (and to the Adyen Payments app) with a shared key, which you create in the Customer Area under Devices › Device settings › Integrations › Terminal API › Encryption key, as Adyen's local integration guide describes. Note its key identifier, passphrase and version.

Setting the key at store or merchant account level lets every terminal there use the same key, which makes setting up more devices quicker. Not needed in the cloud, which uses an API key instead.

4. Put the app on your terminals

  1. Download minimpos-<version>.apk from the latest release. It is signed by the maintainer, which Adyen requires (an unsigned APK uploads, but the terminal refuses to install it).
  2. Upload it and deploy it to your terminals as described in Adyen's app deployment guide. Adyen converts the app for the terminals and installs it on the ones you choose.

Building and signing your own APK works too; see the README. Whichever you choose, stick to it: the Customer Area only accepts later versions signed with the same key. On a tablet or phone, install the same APK directly; there is nothing to deploy.

5. Connect it

Mini mPOS needs the shared key and the Checkout API (a merchant account and an API key); payments wait for both, and Home says what is still missing. The quickest way to enter them is from a computer, where the Customer Area is open anyway:

  1. Open the setup helper on your computer, choose On an Adyen terminal, paste the key identifier, passphrase, merchant account and API key, and click Make QR codes.
  2. In Mini mPOS on the terminal, open Settings › Data › Set up from another device and point the camera at the codes.
  3. Type the transfer code the setup helper shows, and tap Import.

Or type them on the terminal: tap Connect to this terminal on Home (or go to Settings › Terminal), enter the key identifier, passphrase and, if it isn't 1, the version, then tap Save and test; then enter the Checkout API in step 2 below it.

The terminal's ID (POIID), its address and whether it is a TEST or LIVE terminal are detected, so there is nothing else to enter. Settings › About shows what was found; a TEST terminal also shows TEST in its own status bar. While the currency follows the device's region, a connection test also names it: check that it is the one your Adyen account takes payments in (Settings › Payments).

6. On a tablet or phone

Mini mPOS also runs on Android tablets and phones. Install the same APK there (there is nothing to deploy in the Customer Area), then choose under Settings › Terminal › Payments go to and follow the numbered steps below it. The setup helper fills in all of it, where payments go included, from your computer.

A terminal on your network
The recommended way for a tablet at the counter. The tablet sends requests to the terminal over your local network, encrypted with the shared key. Enter (1) the terminal's IP address and POIID (as on its Device info screen), (2) the shared key and (3) the Checkout API. Mini mPOS does not have to be installed on the terminal.
A terminal over the internet (cloud)
For a tablet and a terminal on different networks. Requests go through Adyen's Cloud device API, with an API key instead of the shared key, which the Checkout API uses too. In the Customer Area, under Developers › API credentials, create a credential for this device with the Cloud Device API and Checkout webservice roles. Enter (1) the merchant account and API key under Adyen account, then (2) tap Find connected terminals and choose the terminal (or type its POIID), and Test connection, which tests both the terminal and the Checkout API. Whether the key is TEST or LIVE, and the data center to use, are found when it connects.
Tap to Pay on this phone
Shoppers tap their card or phone on the phone itself, in the Adyen Payments app; there is no printer, so receipts are emailed or shared. The phone needs NFC and Android 12 or later, and must be Google-certified. Ask Adyen Support to enable Tap to Pay on Android and the Adyen Payments app role, then: (1) install Adyen Payments Test (TEST) or Adyen Payments (LIVE) from Google Play (Mini mPOS has a button for each while neither is installed); (2) connect the Checkout API, whose merchant account the phone is registered for; (3) under Tap to Pay, enter the Payments app API key (a credential with only the Adyen Payments app role) and, to set it up for one store, its store ID, and tap Set up Tap to Pay: the Payments app opens to register the phone; (4) enter the shared key, which encrypts every payment request to the Payments app. Each payment then opens the Payments app and returns to Mini mPOS. To stop, tap Remove this phone.

Until everything is entered, Home shows Finish setting up payments, says what is still missing and opens Settings › Terminal. The rest of this guide applies as it does on a terminal.

Adyen API keys are stored on the device, encrypted with the Android Keystore: the Checkout API key wherever payments go, and for Tap to Pay also the Payments app API key. Adyen advises keeping API keys on a server, and Mini mPOS has none: use a credential for this device only, set an admin PIN, and revoke the key in the Customer Area if the device is lost.

7. Set up your business

A new installation is ready to sell: checkout asks for nothing but payment, and receipts print by themselves where there is a printer. Everything below is in Settings, in the order the app shows it.

Payments
  • Pricing: the currency, any of the 138 Adyen processes. Automatic follows the device's region.
  • References: a prefix for the references the app generates, and whether checkout asks for a transaction reference (off at first).
  • Shoppers and saved cards: the shopper reference sent with every payment: none at first, a customer reference typed at checkout, or the shopper's email (hashed by default; use the same salt on every device). With one, Offer to save cards decides whether checkout shows Save card, whether it starts switched on (for sales and for pre-authorizations), the recurring processing model, and whether the shopper's email goes to Adyen with the saved card.
  • Tipping: whether Tip on the receipt starts switched on at checkout (see Tips on the receipt).
  • Email receipts: when to ask for the shopper's email (never, before or after payment, or both) and whether the receipt is emailed automatically.
  • Payment links: whether checkout offers them, and how long they work (see Payment links).
Tax
Your named tax rates (such as GST 10% and GST-free 0%), whether prices include tax, the default rate for new products, and a Charge tax switch. A new installation starts with the standard rate of the device's country where the app knows it (in Japan also the reduced 8% rate), and a 0% rate; in the US and Canada only the 0% rate, with tax added on top of prices. Check them before you add products.
Receipts
Business name, address, tax ID, phone, title and footer; what the receipt shows (tax breakdown, references, refund QR code); whether there is a printer (detected automatically), printing automatically after payment (on at first), the merchant copy and the characters per line. A preview shows the result, and Print test receipt prints it.
Email (SMTP)
Your mail server, sender, an optional blind copy and the subject, with a test email. Buttons fill in the server for these providers (or Other, to type your own) and say what password they need (usually an app password). Their help pages explain how to get it; on a tablet or phone the app links to them too:
  • Gmail
  • Microsoft 365
  • iCloud Mail
  • Yahoo Mail
  • Fastmail
  • Zoho Mail
  • Proton Mail
Security
An admin PIN for Settings and Products, and how soon they lock again. Set one before the device goes on the counter. Repeated wrong PINs lock entry for a while; a forgotten PIN can only be cleared with the app's data, from the device's settings. An optional Manager PIN, separate from the admin PIN, gates refunds, cancellations, captures and adjustments. Set the admin PIN first so staff cannot change this protection. Removing the admin PIN also removes the Manager PIN.
Data
How long settled sales and refunds are kept (90 days at first), clearing settled history, setting up other devices from this one and this one from the setup helper (see More devices).
About
The app version, the TEST or LIVE environment, whether there is a printer, the device, and what the app tells Adyen about itself with each payment.

Language and receipts

Mini mPOS supports English, Simplified Chinese and Japanese. On Android 12 or earlier, it follows the device language. On Android 13 or later, choose a language in Android's system app-language settings.

New installations use localized receipt defaults and sample labels. Changing language does not translate existing receipt titles, footers, tax names, email subjects or transferred product catalogs. Review them in Settings › Receipts, Settings › Tax, Settings › Email (SMTP) and Products, especially if you already have settings or import them from another device.

Adyen-generated payment receipt data is kept verbatim and follows the payment terminal's own configured receipt language. Wide Chinese and Japanese characters use two columns in plain-text receipt layout. Japanese receipts also show taxable amounts by tax rate, marked 税込 (tax-inclusive) or 税抜 (tax-exclusive). Check the printed layout with Settings › Receipts › Print test receipt.

Mini mPOS receipts are not official Chinese 发票 and are not guaranteed to qualify as Japanese 適格請求書 (qualified invoices) or 適格簡易請求書 (qualified simplified invoices). Per-rate totals alone are not a complete invoice system. Separately verify reduced-rate item marking, tax rounding, registration and all other applicable requirements. For context, see the Japan National Tax Agency's qualified simplified invoice guidance and the China State Taxation Administration's VAT invoice verification service. These links are reference material, not a claim of compliance or legal advice.

8. Add your products

In Products, tap + and enter a name, price and tax rate, and optionally a category and a barcode (type it or scan it). Items without tax get a 0% rate. Categories, on the second tab, group the products on the sale screen.

A product can also be a pre-authorization product, such as a deposit or a hire bond; see Pre-authorizations.

To copy the catalog to another device, see More devices.

9. Sell and refund

  • New sale: tap products, scan a barcode or add a custom item, then Charge. Checkout shows the items and tax. Depending on Settings › Payments, it also asks for a transaction or customer reference or the shopper's email, and offers Save card (with the shopper's consent), Tip on the receipt and Create payment link. Tap Pay and follow the terminal.
  • Receipts print as one slip with your header, the items, tax, the card receipt and a refund QR code: automatically, or with Print receipt on the result screen. With email set up, Email receipt sends it too. On a tablet or phone, Share receipt sends it as an image through Android's share sheet, to a messaging app for example.
  • Refund: tap Refund on Home and scan the QR code on the receipt, or open the sale in History. Refund everything, some items, or an amount (a sale taken on another device only in full or by amount). Adyen processes refunds asynchronously, so the app shows them as requested; the final outcome is in your Customer Area.
  • History groups transactions by day with daily totals of sales, tips, refunds and amounts held. Filters list sales, transactions awaiting a tip, pre-authorizations, refunds, and Needs attention: payments whose result was not confirmed, which you can check again with the terminal.
  • Find a transaction by typing in History's search field (on small screens, tap the search icon first): a merchant or PSP reference, auth code, customer reference, shopper email, the card's last 4 digits, or an amount such as 34 or 34.50. Every word must match, so visa 34 finds Visa payments of $34.00, and a refund shows up with its sale's shopper and card. Payment method, at the start of the filters, narrows the list to one card brand or a wallet (Apple Pay, Google Pay, Samsung Pay).

10. The Checkout API and captures

Every payment needs Adyen's Checkout API: through it Mini mPOS captures tips on the receipt and pre-authorizations (and adjusts what they hold), and sends payment links. Until it is set up, Home says what is missing and payments wait.

  1. In the Customer Area, go to Developers › API credentials and create a credential (see Adyen's API credentials guide) with only the Checkout webservice role. Generate its API key.
  2. Enter your merchant account and the API key in the setup helper, or in Mini mPOS under Settings › Terminal, in the Checkout API step, and tap Save and test API key. The key is stored encrypted on the device; the test changes nothing. In the cloud, the API key under Adyen account does this, as its credential also has the Checkout webservice role.
  3. LIVE accounts also need your live URL prefix (Adyen's live endpoints); in the app, the field appears once the terminal is known to be LIVE. Whether it is TEST or LIVE is detected from the terminal's certificate (in the cloud, from the API key; with Tap to Pay, from the Payments app installed).
  4. Optional: ask for synchronous adjustments with Return adjust authorisation data (see Adyen's authorization adjustment guide). The app then knows straight away whether a higher amount was authorized; otherwise adjustments are confirmed later, in the Customer Area.

How captures work

Tips on the receipt and pre-authorizations are taken with manual capture: the amount is only held until it is captured. Adyen confirms captures asynchronously, so the app shows them as Capture requested; Mini mPOS has no backend for webhooks, so the final outcome is in your Customer Area. A capture whose result is unknown can be sent again from History without capturing twice.

11. Payment links

With the Checkout API set up, a sale can also be paid with an Adyen payment link instead of on the terminal: the customer pays on Adyen's payment page, on their own phone or computer.

  1. Before the first LIVE link, check what Adyen's Pay by Link needs on your account, such as your terms and conditions.
  2. In Mini mPOS, switch on Settings › Payments › Offer payment links and choose how long links work (24 hours by default, up to 70 days).
  3. At checkout, tap Create payment link under Pay. The customer scans the QR code shown, or you Email link (with an unpaid receipt), Print link or, on a tablet or phone, Share link.

The link carries the items, the shopper's email and reference, and (with Save card on) the offer to save the card. While it is shown the app checks every few seconds whether it was paid, and again when you tap Check payment. History lists the sale as Awaiting payment until it is paid, it expires or you Cancel link; an unpaid link counts in no day total. Adyen only sends a paid link's PSP reference to a webhook, which Mini mPOS has no backend for, so refund a paid link in the Customer Area (Payments › Payment list). Payment links are for sales only, and not available with the simulator.

12. Tips on the receipt

Where customers add a tip after paying, as in restaurants and bars, Mini mPOS follows Adyen's tipping on the receipt flow: the bill is pre-authorized, the customer writes a tip on the printed receipt and signs it, and the bill plus tip is captured.

With Adyen, once

  • Ask Adyen Support to set up pre-authorization for your payment methods, and to enable overcapture: tips up to 20% of the bill are captured on top of the amount authorized. Wallets and debit cards may not support the flow.
  • The Checkout API, through which the app captures the tips.

In Mini mPOS

  1. At checkout, switch on Tip on the receipt (shown while a printer is available; make it the default under Settings › Payments › Tipping), then Pay.
  2. The result shows Awaiting tip. Print the receipt: it has blank TIP and TOTAL lines, and the merchant copy (printed after it under the default merchant copy setting) a SIGNATURE line.
  3. When the customer has filled it in, tap Enter tip, on the result screen or later from History (the Awaiting tip filter lists them). Type the tip or the total, or tap No tip, and confirm.

The app then captures bill plus tip. A tip above 20% of the bill is authorized first; if the card issuer refuses it, nothing is captured and you can enter a smaller tip (or none). Once entered, a tip cannot be changed, and the sale can be refunded like any other, tip included. Until then it can only be canceled, from its History entry.

Holds expire, so enter tips promptly, for example at the end of each shift.

13. Pre-authorizations

A pre-authorization holds an amount on the shopper's card without charging it, for example a deposit for an event, a room or equipment hire. You capture it later (the amount actually owed, which may be less or more than the amount held), or cancel it to release the hold.

With Adyen, once

  • Ask Adyen Support to set up pre-authorization for your payment methods. Whether a card allows it depends on the card scheme and your business's merchant category code (MCC); see Adyen's pre-authorization guide.
  • You do not need to switch your account to manual capture: Mini mPOS asks for manual capture on each pre-authorization only (authorisationType=PreAuth with manualCapture=true), so normal sales are still captured as your account is set up.
  • Optional: smart pre-authorization, described in the same guide, lets the terminal ask for another card when the one presented does not support it.

In Mini mPOS

  1. Optional: for amounts you hold often, such as a deposit, edit (or add) the product in Products and switch on Pre-authorization product. It then no longer appears in New sale.
  2. On Home, tap New pre-authorization. A pre-authorization holds a single item, so tapping a product (or adding a custom amount, or scanning a barcode) goes straight to checkout; tap Pre-authorize there. Without pre-authorization products, it starts with a custom amount.
  3. With a shopper reference and Offer to save cards on (Settings › Payments › Shoppers and saved cards), Save card starts switched on for pre-authorizations, so late costs can be charged once the pre-authorization has been captured. The receipt is titled PRE-AUTHORIZATION and shows the amount held.

Capture, adjust or cancel

  • Capture: open the pre-authorization in History and tap Capture. It proposes the amount held; capturing less releases the rest, and capturing more first asks the card issuer to authorize it. Once captured, it can be refunded from History.
  • Adjust amount changes what it holds without capturing (the same amount extends the authorization).
  • Both go through the Checkout API.
  • Cancel: tap Cancel pre-authorization. If it has already been captured in the Customer Area, Adyen refunds it in full instead.

Holds expire, after as little as a few days for some card schemes, and the shopper sees the amount as pending on their statement until then. Capture or cancel promptly; History's Pre-auths filter lists them, and the day totals show what is still held.

14. More devices

Once one device is set up, set up the others from it with a few QR codes instead of entering everything again.

  1. On the device that is set up, go to Settings › Data › Share with another device (or the menu in Products). Choose what to copy: the catalog, the settings, and the passwords and keys (shared key passphrase, Checkout API key, Payments app API key, SMTP password and admin PIN). Tap Show QR codes.
  2. On the new device, choose Set up from another device in the same places and point its camera at the codes, in any order.
  3. Choose whether the catalog is merged into the new device's or replaces it. To bring the passwords and keys, type the transfer code the first device shows above the codes; without it, the rest is imported and they are skipped. Tap Import.
  4. Check the connection under Settings › Terminal with Test connection.

The settings replace the new device's, except where payments go, the address and ID of its terminal, its Tap to Pay setup, its TEST/LIVE environment and the simulator. The shared key only works on both terminals if the Customer Area assigns the same key to them (for example at store or merchant account level); otherwise enter each terminal's own key. The transfer code is new each time and only shown on the first device, so a photo of the QR codes does not reveal the passwords.

The setup helper makes the same kind of codes on a computer, for the connection only: where payments go, the shared key, the Checkout API and Tap to Pay. Only what you fill in changes on the device.

15. Before you go live

  • Run a few sales, refunds and (if you use them) payment links, tips and pre-authorizations on a TEST terminal with Adyen's test cards.
  • Check the receipt layout with Settings › Receipts › Print test receipt, and the email settings with Send test email.
  • Set an admin PIN, then deploy the app to your LIVE terminals and enter their shared key, a live Adyen API key and your live URL prefix (the setup helper has a LIVE choice).
  • Check that Settings › About shows the LIVE environment.

16. If something goes wrong

Home says “Payments cannot reach the terminal”
Check the key identifier, passphrase and version in Settings › Terminal against the Customer Area, and tap Save and test. On a tablet or phone, also check the terminal's IP address and that both are on the same network.
The terminal refuses to install the app
An error such as INSTALL_PARSE_FAILED_NO_CERTIFICATES means the APK was not signed. Upload the signed minimpos-<version>.apk from the releases page.
A payment's result is unknown
Open it from History (Needs attention) and tap Check result again. Check the Customer Area before charging the shopper again.
The terminal is busy
Finish what the terminal is doing (another payment or its admin menu), or tap Cancel the terminal’s current transaction on the result screen, then try again.
A capture failed or its result is unknown
History shows why. Fix the Checkout API settings if needed, then tap Retry capture: sending it again cannot capture twice.
Checkout has no Create payment link
Payment links need the merchant account and Adyen API key in Settings › Terminal, and Settings › Payments › Offer payment links switched on. They are not offered for pre-authorizations or with the simulator.
Tap to Pay comes back without a result
The payment's result is then unknown, and the Payments app cannot be asked for it again: check the Customer Area (Payments › Payment list) before charging the shopper again.
Receipts do not print
Check Settings › Receipts › Printer (detected automatically, or set it to always available) and Settings › About, which shows whether a printer was found.
The admin PIN is forgotten
Clear the app's data from the device's settings. Its settings, products and history on that device are then lost, so set it up again from another device.
