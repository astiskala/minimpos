はじめに

Adyen アカウントから、最初の決済まで。多くの設定は Adyen Customer Area と Mini mPOS の設定で一度だけ行います。約 30 分と、Adyen による端末へのアプリ配布の時間を見込んでください。

1. 始める前に

  • 対面決済（Terminal API）が有効な Adyen アカウントと、端末設定の閲覧、アプリのアップロード、決済の管理ができる Customer Area のユーザーが必要です。
  • Android 9 以降を搭載した Adyen Android 決済端末。例：S1F2、S1F4Pro、S1E4Pro、S1E2L、AMS1、S1U2、SFO1。Mini mPOS をこの上で動かします。印刷にはプリンター搭載モデルが必要です。領収書、バーコード、設定用 QR コードの読み取りにはカメラが必要です。
  • または Android のタブレットやスマートフォン。ネットワークやインターネット経由で端末を使うか、Tap to Pay で支払いを受け付けます（タブレットやスマートフォンで使うを参照）。
  • 任意：領収書をメールで送る場合は、SMTP メールサーバーか、一般的なメールサービスのメールボックスを用意してください。
  • Adyen Checkout API の API 認証情報。すべての支払いに必要です。アプリはこれを通じて領収書のチップとプリオーソリゼーションをキャプチャし、支払いリンクを送ります（Checkout API とキャプチャを参照）。

Mini mPOS は独立したプロジェクトであり、Adyen の製品ではありません。本番の決済を受け付ける前に、TEST 端末ですべての操作を試してください。このガイドでは Mini mPOS に必要なことだけを説明します。Adyen アカウント、Customer Area、端末の使い方は、リンク先の Adyen の公式ドキュメント（常に最新）を参照してください。

2. 端末なしで試す

どの Android スマートフォンやエミュレーターでも、Mini mPOS の内蔵シミュレーターで決済を再現し、すべての画面を試せます。最新リリースから minimpos-<version>.apk をダウンロードしてスマートフォンで開くか（ブラウザーやファイルマネージャーからのアプリのインストールを許可するよう求められます）、ソースコードからインストールしてください。

git clone https://github.com/astiskala/minimpos.git
cd minimpos
./gradlew :app:installDebug

設定 › シミュレーターで、決済結果（承認、拒否、購入者によるキャンセル、タイムアウト、端末の使用中、ランダム）、処理にかかる時間、プリンターの有無を選べます。印刷した領収書は画面に表示されます。シミュレーターは Checkout API も再現するため、チップ、キャプチャ、プリオーソリゼーションも試せます。支払いリンクはシミュレーターでは使えません。

3. 共有キーを作成する

Mini mPOS は共有キーで端末（と Adyen Payments アプリ）へのすべてのリクエストを暗号化します。Adyen のローカル統合ガイドのとおり、Customer Area の Devices › Device settings › Integrations › Terminal API › Encryption key でキーを作成し、キー識別子、キーのパスフレーズ、キーバージョンを控えてください。

店舗やマーチャントアカウント単位でキーを設定すると、その配下のすべての端末で同じキーを使えるため、デバイスの追加が簡単になります。クラウドでは APIキーを使うため、共有キーは不要です。

4. 端末にアプリをインストールする

  1. 最新リリースから minimpos-<version>.apk をダウンロードします。Adyen の要件に従ってメンテナーが署名したファイルです。未署名の APK はアップロードできますが、端末にはインストールできません。
  2. Adyen のアプリ配布ガイドに従ってアップロードし、端末に配布します。Adyen がアプリを端末向けに変換し、選択した端末にインストールします。

自分で APK をビルドして署名することもできます。README を参照してください。どちらを選んでも、途中で変更しないでください。Customer Area は、同じキーで署名した後続バージョンのみを受け付けます。タブレットやスマートフォンには同じ APK を直接インストールします。配布は不要です。

5. 接続する

Mini mPOS には共有キーと Checkout API（マーチャントアカウントと APIキー）が必要です。両方がそろうまで決済は保留され、ホームに不足している項目が表示されます。Customer Area を開いているパソコンから入力するのが最も簡単です。

  1. パソコンでセットアップヘルパーを開き、Adyen 端末で動かすを選んで、キー識別子、パスフレーズ、マーチャントアカウント、APIキーを貼り付け、QRコードを作成をクリックします。
  2. 端末の Mini mPOS で設定 › データ › 別のデバイスから設定を開き、カメラでコードを読み取ります。
  3. セットアップヘルパーに表示された転送コードを入力し、インポートをタップします。

端末で直接入力することもできます。ホームのこの端末に接続をタップし（または設定 › 端末を開き）、キー識別子、キーのパスフレーズ、1 でない場合はキーバージョンを入力して保存してテストをタップします。続いて、その下のステップ 2 で Checkout API を入力します。

端末 ID（POIID）、アドレス、TEST／LIVE 環境は自動検出されるため、ほかの入力は不要です。設定 › アプリ情報で検出結果を確認できます。TEST 端末のステータスバーには TEST と表示されます。通貨がデバイスの地域に従っている場合は、接続テストの結果にその通貨も表示されます。Adyen アカウントで決済を受け付ける通貨であることを確認してください（設定 › 決済）。

6. タブレットやスマートフォンで使う

Mini mPOS は Android のタブレットやスマートフォンでも動作します。同じ APK をインストールし（Customer Area での配布は不要です）、設定 › 端末 › 決済先で次のいずれかを選び、その下の番号付きの手順に従います。セットアップヘルパーを使えば、決済先を含めてすべてパソコンから入力できます。

ネットワーク上の端末
カウンターのタブレットにおすすめの方法です。タブレットはローカルネットワーク経由で端末にリクエストを送り、共有キーで暗号化します。(1) 端末の IP アドレスと POIID（端末の Device info 画面に表示）、(2) 共有キー、(3) Checkout API を入力します。端末に Mini mPOS をインストールする必要はありません。
インターネット経由の端末（クラウド）
タブレットと端末が別のネットワークにある場合に使います。リクエストは Adyen の Cloud device API を経由し、共有キーの代わりに APIキーを使います。このキーは Checkout API にも使われます。Customer Area の Developers › API credentials で、このデバイス用に Cloud Device API ロールと Checkout webservice ロールを持つ認証情報を作成します。(1) Adyenアカウントにマーチャントアカウントと APIキーを入力し、(2) 接続中の端末を検索をタップして端末を選び（POIID を入力しても構いません）、接続をテストをタップすると、端末と Checkout API の両方をテストします。キーが TEST か LIVE か、どのデータセンターを使うかは、接続時に自動で判別されます。
このスマートフォンでTap to Pay
お客様はこのスマートフォンの Adyen Payments アプリで、カードやスマートフォンをタッチして支払います。プリンターはないため、領収書はメールで送るか共有します。NFC 対応で Android 12 以降を搭載し、Google の認定を受けたスマートフォンが必要です。Adyen サポートに Tap to Pay on Android と Adyen Payments app role の有効化を依頼してから、次の手順で設定します。(1) Google Play から Adyen Payments Test（TEST）または Adyen Payments（LIVE）をインストールします（どちらも未インストールの間は、Mini mPOS にそれぞれのボタンが表示されます）。(2) Checkout API を接続します。スマートフォンはそのマーチャントアカウントに登録されます。(3) Tap to Pay で PaymentsアプリのAPIキー（Adyen Payments app role のみを持つ認証情報）と、1 店舗だけに設定する場合はその店舗 ID を入力し、Tap to Payを設定をタップします。Payments アプリが開いてスマートフォンを登録します。(4) 共有キーを入力します。Payments アプリへの支払いリクエストはすべてこのキーで暗号化されます。以降、支払いのたびに Payments アプリが開き、Mini mPOS に戻ります。やめるときはこのスマートフォンを削除をタップします。

すべての入力が終わるまで、ホームに決済の設定を完了と不足している項目が表示され、タップすると設定 › 端末が開きます。このガイドのほかの部分は、端末で使う場合と同じです。

Adyen の APIキーはデバイスに保存されます（Android Keystore で暗号化）。決済先にかかわらず Checkout API キーが、Tap to Pay では PaymentsアプリのAPIキーも保存されます。Adyen は APIキーをサーバーで管理することを推奨していますが、Mini mPOS にはサーバーがありません。このデバイス専用の認証情報を使い、管理者 PIN を設定し、デバイスを紛失した場合は Customer Area でキーを無効にしてください。

7. 店舗情報を設定する

新規インストール直後から販売できます。会計では決済だけを行い、プリンターがあれば領収書は自動で印刷されます。以下はすべて設定にあり、アプリでの表示順に並んでいます。

決済
  • 価格設定：通貨。Adyen が扱う 138 通貨から選べます。自動設定は端末の地域に従います。
  • 参照ID：アプリが生成する参照IDの接頭辞と、会計時に取引参照IDの入力を求めるかどうか（初期状態はオフ）。
  • 購入者とカードの保存：すべての決済で送信する購入者参照ID。初期状態はなしで、会計時に入力する顧客参照IDか購入者のメールアドレス（初期設定ではハッシュ化。すべてのデバイスで同じソルトを使ってください）を選べます。購入者参照IDがある場合は、カード保存の選択肢を表示で、会計時にカード保存を表示するかどうか、その初期状態（通常販売とプリオーソリゼーションそれぞれ）、継続課金モデル、カード保存時に購入者のメールアドレスを Adyen に送るかどうかを設定します。
  • チップ：会計時に領収書にチップを記入を初期状態でオンにするかどうか（領収書のチップを参照）。
  • 領収書のメール送信：購入者にメールアドレスを尋ねるタイミング（尋ねない、決済前、決済後、両方）と、領収書を自動でメール送信するかどうか。
  • 支払いリンク：会計時に支払いリンクを使えるようにするかどうかと、リンクの有効時間（支払いリンクを参照）。
税
名前付きの税率（例：GST 10%、GST-free 0%）、税込価格か税抜価格か、新商品の初期税率、税を適用するかどうかを設定します。新規インストール時は、アプリが端末の国の標準税率を把握していればその税率（日本では軽減税率 8% も）と 0% の税率が用意されます。米国とカナダでは 0% の税率のみで、税は価格に上乗せされます。商品を追加する前に確認してください。
領収書
店舗名、住所、税務番号、電話番号、タイトル、フッター、表示内容（税額内訳、参照ID、返金用 QR コード）、プリンターの有無（通常は自動検出）、決済後の自動印刷（初期状態はオン）、加盟店控え、1 行の文字幅を設定します。プレビューで仕上がりを確認でき、テスト領収書を印刷で印刷できます。
メール（SMTP）
メールサーバー、差出人、任意の BCC、件名を設定し、テストメールを送信できます。ボタンで次のサービスのサーバーを入力でき（その他を選ぶと手動で入力できます）、必要なパスワード（通常はアプリパスワード）が案内されます。パスワードの取得方法は各サービスのヘルプページをご覧ください。タブレットやスマートフォンではアプリからもリンクされます。
  • Gmail
  • Microsoft 365
  • iCloud Mail
  • Yahoo Mail
  • Fastmail
  • Zoho Mail
  • Proton Mail
セキュリティ
設定と商品管理を保護する管理者PINと、再ロックまでの時間を設定します。デバイスをカウンターに置く前に PIN を設定してください。PIN を何度も間違えると、しばらく入力できなくなります。PIN を忘れた場合は、デバイスの設定からアプリのデータを消去するしかありません。
データ
販売と返金の保存期間（初期状態は 90 日）の設定、取引履歴の消去、このデバイスを元にしたほかのデバイスの設定、セットアップヘルパーからのこのデバイスの設定（デバイスを追加するを参照）を行えます。
アプリ情報
アプリのバージョン、TEST／LIVE 環境、プリンターの有無、デバイスの情報、決済ごとにアプリが Adyen に送るアプリケーション情報を確認できます。

言語と領収書

Mini mPOS は英語、簡体字中国語、日本語に対応しています。Android 12 以前では端末の言語に従います。Android 13 以降では、Android のシステム設定にあるアプリの言語設定から選択できます。

新規インストール時は、領収書の初期値やサンプルの表示名も選択した言語になります。言語を変えても、保存済みの領収書タイトル、フッター、税率名、メールの件名、転送した商品カタログは翻訳・上書きされません。既存の設定を使う場合や別のデバイスから取り込んだ場合は、設定 › 領収書、設定 › 税、設定 › メール（SMTP）、商品で確認・変更してください。

Adyen が生成する決済の領収書データは原文のまま使用し、決済端末側で設定した領収書の言語に従います。プレーンテキストの領収書では、中国語や日本語の全角文字を 2 桁分として配置します。日本語の領収書は、税率別の対象金額を税込または税抜で表示します。設定 › 領収書 › テスト領収書を印刷で実際の印字を確認してください。

Mini mPOS の印刷物が適格請求書や適格簡易請求書の要件を満たすことは保証していません。税率別合計の表示だけでインボイス制度に完全対応するものではありません。軽減税率対象商品の表示、税額の端数処理、登録番号など、適用される要件は別途確認してください。また、中国の正式な税務発票を発行する機能ではありません。参考資料として、国税庁の適格簡易請求書の説明と中国国家税務総局の増値税発票確認サービスを参照できます。これらは参考情報であり、法令適合の保証や法律上の助言ではありません。

8. 商品を追加する

商品で + をタップし、名前、価格、税率を入力します。カテゴリーとバーコードは任意です。バーコードは入力するかスキャンできます。税のかからない商品には 0% の税率を使います。2 つ目のタブにあるカテゴリーで、販売画面の商品をグループ分けできます。

商品をプリオーソリ商品として設定することもできます。予約金やレンタル保証金などに利用します。プリオーソリゼーションを参照してください。

商品カタログを別のデバイスにコピーする方法は、デバイスを追加するを参照してください。

9. 販売と返金

  • 新規販売：商品をタップするか、バーコードをスキャンするか、任意の商品を追加して、…を会計ボタンをタップします。会計画面には商品と税額が表示されます。設定 › 決済の内容によっては、取引参照ID、顧客参照ID、購入者のメールアドレスの入力を求められ、カードの保存（購入者の同意が必要）、領収書へのチップ記入、支払いリンクの送信も選べます。…を決済ボタンをタップして端末の案内に従います。
  • 領収書には店舗のヘッダー、商品、税金、カード決済の領収書、返金用 QR コードをまとめて印刷します。自動で印刷されるほか、結果画面の領収書を印刷でも印刷できます。メールを設定していれば領収書をメール送信も使えます。タブレットやスマートフォンでは、領収書を共有で Android の共有シートから画像として送れます（メッセージアプリなど）。
  • 返金：ホームの返金をタップして領収書の QR コードをスキャンするか、取引履歴から販売を開きます。全額、商品単位、または指定金額で返金できます（別のデバイスで行った販売は、全額か指定金額のみ）。Adyen は返金を非同期で処理するため、アプリでは返金要求済みと表示されます。最終結果は Customer Area で確認してください。
  • 取引履歴は取引を日別にまとめ、販売、チップ、返金、確保額の日計を表示します。フィルターで販売、チップ入力待ちの取引、プリオーソリゼーション、返金、要確認（結果が未確定の決済。端末に結果を再照会できます）を一覧にできます。
  • 取引を検索：取引履歴の検索欄に入力します。小さな画面では先に検索アイコンをタップしてください。加盟店参照ID、PSP参照ID、承認コード、顧客参照ID、購入者のメールアドレス、カード番号の下 4 桁、または 34 や 34.50 のような金額で検索できます。すべての検索語が一致する必要があるため、visa 34 は $34.00 の Visa 決済を見つけます。元の販売の購入者やカード情報でも返金が見つかります。フィルターの先頭にある決済方法では、カードブランドやウォレット（Apple Pay、Google Pay、Samsung Pay）で絞り込めます。

10. Checkout API とキャプチャ

すべての支払いに Adyen の Checkout API が必要です。Mini mPOS はこれを通じて領収書のチップとプリオーソリゼーションをキャプチャし（確保額の調整も含む）、支払いリンクを送ります。設定するまで、ホームに不足している項目が表示され、支払いは受け付けられません。

  1. Customer Area の Developers › API credentials で認証情報を作成します（Adyen の API 認証情報ガイドを参照）。付与するロールは Checkout webservice role のみにして、APIキーを生成してください。
  2. セットアップヘルパー、または Mini mPOS の設定 › 端末の Checkout API のステップでマーチャントアカウントと APIキーを入力し、APIキーを保存してテストをタップします。キーはデバイスに暗号化して保存されます。このテストでは決済は変更されません。クラウドでは、Adyenアカウントの APIキーの認証情報に Checkout webservice role も付与されているため、そのキーで処理されます。
  3. LIVE アカウントでは live URL prefix も必要です（Adyen の LIVE エンドポイントを参照）。アプリでは、この欄は端末が LIVE と判明してから表示されます。TEST／LIVE 環境は端末の証明書から自動検出されます（クラウドでは APIキーから、Tap to Pay ではインストールされた Payments アプリから判別します）。
  4. 任意：Return adjust authorisation data で同期的なオーソリゼーション調整を有効にします（Adyen のオーソリゼーション調整ガイドを参照）。有効な場合、増額が承認されたかどうかをアプリですぐに確認できます。無効な場合、調整結果は後から Customer Area で確認します。

キャプチャの仕組み

領収書のチップとプリオーソリゼーションは手動キャプチャで処理します。キャプチャするまでは金額を確保するだけです。Adyen はキャプチャを非同期で確定するため、アプリではキャプチャ要求済みと表示されます。Mini mPOS には webhook を受信するバックエンドがないため、最終結果は Customer Area で確認してください。結果が不明なキャプチャは、取引履歴から再送しても二重にキャプチャされません。

11. 支払いリンク

Checkout API を設定すると、端末の代わりに Adyen の支払いリンクで販売の代金を受け取れます。お客様はご自身のスマートフォンやパソコンで Adyen の決済ページから支払います。

  1. 最初の LIVE リンクを作成する前に、利用規約など、Adyen の Pay by Link がアカウントに求める設定を確認してください。
  2. Mini mPOS の設定 › 決済 › 支払いリンクを使うをオンにし、リンクの有効時間を選びます（既定は 24 時間、最長 70 日）。
  3. 会計画面で、決済ボタンの下の支払いリンクを送信をタップします。お客様が表示された QR コードを読み取るか、リンクをメール送信（未払いの領収書付き）、リンクを印刷、またはタブレットやスマートフォンでリンクを共有します。

リンクには、商品、購入者のメールアドレスと参照ID、（カード保存をオンにした場合は）カード保存の選択肢が含まれます。リンクを表示している間、アプリは数秒ごとに支払い済みかどうかを確認します。支払いを確認をタップしても確認できます。支払われるか、期限が切れるか、リンクを取り消すまで、取引履歴では支払い待ちと表示され、未払いのリンクはどの日計にも含まれません。Adyen は支払い済みリンクの PSP参照IDを webhook にしか送らず、Mini mPOS には webhook を受信するバックエンドがないため、支払い済みリンクの返金は Customer Area（Payments › Payment list）で行ってください。支払いリンクは販売のみに使え、シミュレーターでは使えません。

12. 領収書のチップ

レストランやバーなど、決済後にチップを追加する場面では、Mini mPOS は Adyen の領収書でチップを受け取るフローに従います。請求額をプリオーソリゼーションし、お客様が印刷した領収書にチップを記入して署名した後、請求額とチップの合計をキャプチャします。

Adyen で一度だけ設定

  • Adyen Support に、決済方法のプリオーソリゼーション設定と overcapture（承認額を超えるキャプチャ）の有効化を依頼します。請求額の 20% までのチップは、承認額に上乗せしてキャプチャできます。ウォレットやデビットカードは、このフローに対応しない場合があります。
  • Checkout API。アプリはこれを通じてチップをキャプチャします。

Mini mPOS での操作

  1. 会計時に領収書にチップを記入をオンにし、…を決済ボタンをタップします。プリンターを使える場合にのみ表示されます。設定 › 決済 › チップで初期状態をオンにできます。
  2. 結果はチップ入力待ちと表示されます。領収書を印刷すると、チップと合計の空欄が印刷されます。加盟店控えにはご署名欄も付きます。初期設定では、お客様用の領収書の後に加盟店控えが印刷されます。
  3. お客様が記入したら、結果画面、または後から取引履歴でチップを入力をタップします。チップ入力待ちフィルターで対象の取引を一覧にできます。チップ額か合計額を入力するか、チップなしを選び、確定します。

アプリは請求額とチップの合計をキャプチャします。請求額の 20% を超えるチップは、先に追加の承認を求めます。カード発行会社が拒否した場合は何もキャプチャされず、より少ないチップかチップなしで再入力できます。一度入力したチップは変更できません。その後は通常の販売と同様、チップを含めて返金できます。それまでは、取引履歴からのキャンセルのみが可能です。

確保した金額には有効期限があります。各シフトの終了時など、速やかにチップを入力してください。

13. プリオーソリゼーション

プリオーソリゼーションは、購入者のカードに金額を確保し、すぐには請求しません。イベント、客室、機器レンタルの予約金などに利用できます。後から実際に必要な金額（確保額より少なくても多くても構いません）をキャプチャするか、キャンセルして確保を解除します。

Adyen で一度だけ設定

  • Adyen Support に、決済方法のプリオーソリゼーション設定を依頼します。利用可否はカードスキームと加盟店カテゴリーコード（MCC）によって異なります。Adyen のプリオーソリゼーションガイドを参照してください。
  • アカウント全体を手動キャプチャに切り替える必要はありません。Mini mPOS はプリオーソリゼーションごとにのみ手動キャプチャを指定します（authorisationType=PreAuth と manualCapture=true）。通常の販売は、アカウントの設定どおりにキャプチャされます。
  • 任意：同じガイドで説明されている smart pre-authorization を有効にすると、提示されたカードが対応していない場合に、端末が別のカードを求められます。

Mini mPOS での操作

  1. 任意：予約金など、よく確保する金額は、商品で商品を編集または追加し、プリオーソリ商品をオンにします。その商品は新規販売には表示されなくなります。
  2. ホームの新規プリオーソリをタップします。1 件につき 1 商品の金額を確保するため、商品の選択、任意の金額の追加、バーコードのスキャンから直接会計画面に進みます。そこで…をプリオーソリをタップします。プリオーソリ商品がない場合は、任意の金額から始まります。
  3. 購入者参照IDを設定してカード保存の選択肢を表示をオンにすると（設定 › 決済 › 購入者とカードの保存）、プリオーソリゼーションの会計ではカード保存が初期状態でオンになります（購入者の同意が必要です）。プリオーソリゼーションをキャプチャした後に、追加費用を請求するために利用できます。領収書のタイトルはプリオーソリゼーションで、確保額が表示されます。

キャプチャ、調整、キャンセル

  • キャプチャ：取引履歴からプリオーソリゼーションを開き、キャプチャをタップします。初期値は確保額です。少ない金額をキャプチャすると残額が解放され、増額する場合は先にカード発行会社へ承認を求めます。キャプチャ後は取引履歴から返金できます。
  • 金額を調整では、キャプチャせずに確保額を変更します。同じ金額での調整はオーソリゼーションを延長します。
  • どちらも Checkout API を通じて行います。
  • キャンセル：プリオーソリをキャンセルをタップします。Customer Area ですでにキャプチャされていた場合は、Adyen が全額を返金します。

確保には有効期限があり、カードスキームによっては数日で失効します。それまでは購入者の明細に保留中として表示されます。速やかにキャプチャまたはキャンセルしてください。取引履歴のプリオーソリフィルターで一覧を確認でき、日計にはまだ確保されている金額が表示されます。

14. デバイスを追加する

1 台の設定が済んだら、いくつかの QR コードでほかのデバイスを設定できます。同じ情報を再入力する必要はありません。

  1. 設定済みのデバイスで設定 › データ › 別のデバイスに共有、または商品のメニューを開きます。コピーするカタログ、設定、パスワードとキー（共有キーのパスフレーズ、Checkout API キー、PaymentsアプリのAPIキー、SMTP パスワード、管理者PIN）を選び、QRコードを表示をタップします。
  2. 新しいデバイスで同じ場所から別のデバイスから設定を選び、カメラでコードを読み取ります。順番は問いません。
  3. カタログに統合またはカタログを置換を選びます。パスワードとキーも移すには、最初のデバイスのコード上部に表示される転送コードを入力してください。入力しない場合は、それらを除く情報だけが取り込まれます。インポートをタップします。
  4. 設定 › 端末の接続をテストで接続を確認します。

設定は新しいデバイスの設定を置き換えますが、決済先、その端末のアドレスと ID、Tap to Pay の設定、TEST／LIVE 環境、シミュレーター設定は変わりません。共有キーが両方の端末で使えるのは、Customer Area で同じキーが割り当てられている場合だけです（店舗やマーチャントアカウント単位での設定など）。異なる場合は、それぞれのキーを入力してください。転送コードは毎回新しく生成され、最初のデバイスだけに表示されます。QR コードの写真だけではパスワードはわかりません。

セットアップヘルパーは同じ種類のコードをパソコンで作成します。対象は接続情報（決済先、共有キー、Checkout API、Tap to Pay）だけで、デバイスでは入力した項目だけが変わります。

15. 本番運用の前に

  • TEST 端末で Adyen のテストカードを使い、販売、返金、利用する場合は支払いリンク、チップ、プリオーソリゼーションも何件か試してください。
  • 設定 › 領収書 › テスト領収書を印刷でレイアウトを、テストメールを送信でメール設定を確認します。
  • 管理者PIN を設定してから、アプリを LIVE 端末に配布し、それぞれの共有キー、LIVE の Checkout API キー、live URL prefix を入力します（セットアップヘルパーに LIVE の選択肢があります）。
  • 設定 › アプリ情報に LIVE 環境と表示されることを確認します。

16. 問題が起きたら

ホームに「決済端末に接続できません」と表示される
設定 › 端末のキー識別子、パスフレーズ、バージョンを Customer Area と照合し、保存してテストをタップしてください。タブレットやスマートフォンでは、端末の IP アドレスと、両方が同じネットワークにあることも確認してください。
端末にアプリをインストールできない
INSTALL_PARSE_FAILED_NO_CERTIFICATES などのエラーは APK が未署名であることを示します。リリースページの署名済み minimpos-<version>.apk をアップロードしてください。
決済結果が不明
取引履歴の要確認から決済を開き、結果を再確認をタップします。購入者に再請求する前に、Customer Area を確認してください。
端末が使用中
端末で進行中の操作（別の決済や管理メニュー）を終えるか、結果画面の端末の現在の取引をキャンセルをタップしてから、もう一度お試しください。
キャプチャが失敗した、または結果が不明
取引履歴に理由が表示されます。必要に応じて Checkout API の設定を修正し、キャプチャを再試行をタップします。再送しても二重にキャプチャされません。
会計画面に「支払いリンクを送信」がない
支払いリンクを使うには、設定 › 端末でマーチャントアカウントと Checkout API キーを入力し、設定 › 決済 › 支払いリンクを使うをオンにする必要があります。プリオーソリゼーションとシミュレーターでは使えません。
Tap to Pay から結果なしで戻った
この場合、決済結果は不明で、Payments アプリに再度問い合わせることはできません。お客様に再度請求する前に、Customer Area（Payments › Payment list）で確認してください。
領収書が印刷されない
設定 › 領収書 › プリンター（自動検出、または常に使用可能）と、設定 › アプリ情報でプリンターが検出されているかを確認してください。
管理者PIN を忘れた
デバイスの設定からアプリのデータを消去してください。そのデバイスの設定、商品、取引履歴は失われるため、別のデバイスから設定し直してください。

解決しない場合は、GitHub で issue を作成してください。
