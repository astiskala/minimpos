アカウントなしで、まず試す

初回起動時にサンプルでシミュレーターを試す、設定 QR コードを読み込む別のデバイスから設定、または端末を設定を選びます。シミュレーターを選ぶと、Adyen アカウントなしでサンプル商品と読み取り専用のデモ履歴を追加します。履歴と領収書にはデモと表示され、日次合計には含まれません。

設定 › データでサンプルデータを追加またはサンプルデータを削除を選べます。編集済みのサンプル商品も削除対象ですが、ご自身の商品、履歴、税率、設定、およびご自身の商品が使うサンプルカテゴリは残ります。ここで追加しても支払先は変わりません。

最新リリースから minimpos-<version>.apk をダウンロードし、Android 9 以降のスマートフォンやエミュレーターで開きます。Android の案内に従い、ブラウザーやファイルマネージャーからのインストールを許可してください。

Adyen 端末以外では、初期状態でシミュレーターを使い、カードに請求しません。設定 › シミュレーターで承認、拒否、使用中、タイムアウトの結果、待ち時間、プリンターの有無を選べます。領収書は画面に表示され、予約金、チップ、キャプチャも試せます。オフラインのデモリンクは支払いリンクを参照してください。

ソースからビルドする場合は、貢献者向けガイドを参照してください。

構成を選ぶ

デバイスが Mini mPOS を動かし、端末がカードを読み取ります。同じ機器でも構いません。

Adyen 端末で動かす
1 台で会計を完結できます。Android 9 以降の Adyen Android 端末（S1F2、S1F4Pro、S1E4Pro、S1E2L、AMS1、S1U2、SFO1 など）が必要です。
タブレットやスマートフォンとネットワーク上の端末
カウンターのタブレットにおすすめです。Android 9 以降のデバイスと端末を同じネットワークに接続します。その端末への Mini mPOS のインストールは不要です。
タブレットやスマートフォンとクラウドの端末
別々のネットワークで使う構成です。Adyen Cloud device API を通して端末に決済を送ります。
スマートフォンの Tap to Pay
別の端末は不要です。Google 認定の NFC 対応 Android 12 以降のスマートフォン、Adyen Payments アプリ、Adyen サポートによる有効化が必要です。Adyen の要件と対応国・決済方法を確認してください。

印刷にはプリンター搭載端末、バーコード・領収書・設定コードの読み取りにはカメラが必要です。Tap to Pay にはプリンターがないため、領収書をメール送信または共有してください。

Mini mPOS は独立したプロジェクトで、Adyen による製品、推奨、サポートではありません。本番決済には必要なサービスが有効な Adyen アカウント、Customer Area へのアクセス、Checkout API の認証情報が必要です。アカウントやプラットフォームの手順はリンク先の Adyen 文書に従ってください。

アプリをインストールする

すべての構成で、最新リリースの署名済み APK を使います。

  • Adyen 端末：Adyen のアプリ配布ガイドに従い、Customer Area でアップロード・配布します。ユーザーにはアプリのアップロード・配布権限が必要です。
  • タブレットやスマートフォン：デバイスで APK を開き、インストールを許可します。Adyen 経由の配布は不要です。

更新時も同じ署名元を使ってください。端末が受け付ける後続バージョンは、同じキーで署名したものだけです。自分でビルドして署名する場合は、貢献者向けガイドを参照してください。

Adyen に接続する

該当する構成の手順だけを進めます。設定 › 端末でQRコードによるかんたんセットアップを使えます。タブレットやスマートフォンで手入力する場合は決済先を選びます。アプリの番号付き手順に必要事項が表示され、ホームには不足項目が表示されます。

認証情報を用意する

Developers › API credentials で認証情報を作成し、APIキーを生成します。Adyen の認証情報ガイドを参照してください。Checkout webservice role は初期設定で付与されます。構成に必要な追加ロールだけを設定してください：

  • Cloud Device API role：クラウド決済に必要です。
  • Management API — Terminal actions read：端末、アカウント、最後に報告されたネットワークアドレスの任意の自動取得。
  • Management API — Terminal settings read：この端末やネットワーク上の端末の共有キー設定の任意の取得。
  • Management API — Terminal settings Advanced read and write：これらの決済先の共有キーパスフレーズの任意の取得。

この端末、ネットワーク上の端末、Tap to Pay では共有キーも用意します。Devices › Device settings › Integrations › Terminal API › Encryption key から識別子、パスフレーズ、バージョンを取得します。Adyen のローカル統合ガイドを参照してください。クラウドではこのキーは使いません。

ネットワークやクラウドの端末では、手順1は環境です。テストカードにはTEST、実際の決済にはLIVEを選びます。同じ環境の端末、アカウント、認証情報を使用してください。Mini mPOSは別の環境でAPIキーを試しません。Adyen端末で動く場合はデバイスの検証済み証明書を読み、Tap to PayではインストールしたPaymentsアプリの環境を使います。

物理端末ではAdyen APIキーの保存して設定を取得でキーを暗号化して保存し、その環境の端末を取得します。アプリは Adyen の設定やキーを変更しません。Adyen の端末一覧と端末設定の API リファレンスを参照してください。取得できない項目は手動で入力できます。キーは保存されたままで、手動設定にManagement権限は不要です。アドレスが古い可能性があるため確認してください。Tap to Payでは物理端末を検索せず、キーだけを保存します。

パソコンからキーを入力する

信頼できるパソコンでセットアップヘルパーを開き、決済先とTEST/LIVEを選びます。自動（推奨）ではAPIキーを入力します。取得権限があればデバイスが端末のアカウント、アドレス、共有キーを調べます。スマートフォンやタブレットでは端末を選んで結果を確認してください。手動では接続情報をすべてパソコンで入力します。LIVEではどちらもlive URL prefixが必要です。Tap to Payの共有キーは手動で入力します。インストールとスマートフォンの登録はデバイスで行います。設定手順を参照してください。

領収書メール用のSMTP設定も任意で含められます。プロバイダーの要件はメール設定を参照してください。インポート後に設定 › メールを確認し、テストメールを送ります。

QRコードを作成をクリックします。アプリの設定 › 端末で設定コードを読み取るか右上のQRスキャンアイコンをタップします。決済先や環境を先に選ぶ必要はありません。全コードを読み取り、決済先と環境を確認し、転送コードを入力してインポートします。自動では設定を続ける、手動では設定を確認をタップします。保存済み情報は折りたたまれ、手順をタップすると確認・編集できます。不足する情報を補い、下の手順で接続とAPIキーをテストしてください。取得できなくてもインポートしたキーは保存されます。デバイスで入力するか、ヘルパーの手動を使ってください。設定 › 端末ですべて直接入力することもできます。

Adyen 端末で動かす

先にアプリをインストールし、認証情報を用意してください。

セットアップヘルパー（推奨）
信頼できるパソコンでセットアップヘルパーを開き、Adyen端末で動かす、端末のTEST/LIVE環境、自動を選びます。Adyen APIキーと、LIVEの場合はライブURLプレフィックスを入力します。QRインポート手順に従い、端末で設定を続けるをタップします。取得権限があれば、Mini mPOSはこの端末に一致するマーチャントアカウントと共有キーを調べます。情報を確認し、不足を補ってから接続とAPIキーをテストしてください。ヘルパーで手動を選ぶと詳細を自分で入力できます。
手動
  1. 設定 › 端末 › Adyen APIキーでキーを保存します。共有キーなしでこのデバイスの証明書を読み、TEST／LIVEを判別します。取得権限があれば、この端末に一致するマーチャントアカウントと共有キーを入力します。
  2. 共有キーを確認または入力し、接続をテスト（パスフレーズを入力した場合は保存してテスト）をタップします。アドレスと POIID はデバイスから検出します。
  3. Checkout API のマーチャントアカウントを確認または入力し、APIキーをテストをタップします。

ネットワーク上の端末を使う

先にアプリをインストールし、認証情報を用意してください。

セットアップヘルパー（推奨）
信頼できるパソコンでセットアップヘルパーを開き、タブレットまたはスマートフォンと同じネットワークの端末、端末のTEST/LIVE環境、自動を選びます。Adyen APIキーと、LIVEの場合はライブURLプレフィックスを入力します。QRインポート手順に従い、デバイスで設定を続けるをタップして端末を選びます。POIID、マーチャントアカウント、IPアドレス、共有キーを確認し、不足を補ってから接続とAPIキーをテストしてください。取得できない場合や自分で入力したい場合は、ヘルパーで手動を選びます。
手動
  1. ネットワーク上の端末を選び、手順1の環境で端末に合うTESTまたはLIVEを選びます。
  2. その環境のAdyen APIキーを保存します。取得できれば一覧から端末を選びます。
  3. POIID、マーチャントアカウント、IP アドレス、共有キーを確認し、不足項目は手動で入力します。端末の「Device info」に現在のアドレスと POIID が表示されます。
  4. 共有キーで接続をテストし、Checkout API のマーチャントアカウントを確認してAPIキーをテストをタップします。

接続時に端末の証明書が選択した環境と一致するか検証します。一致しなければ接続を拒否し、環境は自動変更しません。

インターネット経由で端末を使う

先にアプリをインストールし、認証情報を用意してください。

セットアップヘルパー（推奨）
信頼できるパソコンでセットアップヘルパーを開き、タブレットまたはスマートフォンとインターネット経由の端末（クラウド）、端末のTEST/LIVE環境、自動を選びます。Cloud Device API roleを持つAdyen APIキーと、LIVEの場合はライブURLプレフィックスを入力します。QRインポート手順に従い、デバイスで設定を続けるをタップして端末を選びます。マーチャントアカウントとPOIIDを確認し、不足を補ってから接続をテストで端末とCheckout APIを確認してください。ヘルパーで手動を選ぶと詳細を自分で入力できます。
手動
  1. クラウドの決済先を選び、手順1の環境で端末に合うTESTまたはLIVEを選びます。
  2. その環境でCloud Device API roleを持つAdyen APIキーを保存します。取得できれば一覧から端末を選びます。
  3. Adyenアカウントのマーチャントアカウントを確認または入力します。LIVEではCheckoutライブURLプレフィックスも入力します。
  4. 端末のPOIIDを確認または入力し、接続をテストで端末とCheckout APIを確認します。

選択した環境内でデータセンターを検索します。クラウド決済はローカル決済より端末の応答を長く待つ場合があります。

Tap to Pay を使う

Tap to Pay on Androidを使うには、AdyenによるサービスとAdyen Payments app roleの会社向け有効化が必要です。先にAdyenサポートに連絡してください。

先にアプリをインストールし、認証情報を用意してください。

  1. Google Playから、TEST用のAdyen Payments TestかLIVE用のAdyen Paymentsをインストールします。両方は入れないでください。
  2. Mini mPOSの設定 › 端末でこのスマートフォンでTap to Payを選びます。

インストールしたPaymentsアプリの環境の認証情報を、次のどちらかで入力します。

セットアップヘルパー（推奨）
信頼できるパソコンでセットアップヘルパーを開き、Tap to Payと一致するTEST/LIVEを選びます。Adyen APIキー、マーチャントアカウント、別のPaymentsアプリのAPIキーを入力します。共有キーはここで入力するか、後でスマートフォンで入力してください。LIVEではライブURLプレフィックスも必要です。店舗IDは任意です。QRインポート手順に従い、スマートフォンで設定を確認をタップします。
手動

設定 › 端末でAdyen APIキーを保存します。Checkout APIにマーチャントアカウントと、LIVEの場合はライブURLプレフィックスを入力します。Tap to Payに別のPaymentsアプリのAPIキー（Adyen Payments app roleのみ）を保存し、任意で店舗ID（referenceではありません）を入力します。共有キーに識別子、パスフレーズ、バージョンを入力します。

どちらもAPIキーをテストしてからTap to Payを設定をタップし、Paymentsアプリで登録を完了します。Checkoutとスマートフォンの登録には同じマーチャントアカウントを使います。

Mini mPOSはTap to Payの共有キーを取得しません。ヘルパーまたはスマートフォンで入力し、接続をテストしてください。ヘルパーからの設定では保存済み情報が折りたたまれ、手順をタップすると確認・編集できます。

Mini mPOSはAdyenのPaymentsアプリガイドの登録フローを実行します。登録状態を確認し、ワンタイム登録トークンを取得してPaymentsアプリに渡します。トークンをコピーする必要はありません。PaymentsアプリのAPIキーは登録の認証に、別のAdyen APIキーはCheckout操作に使います。共有キーはAdyenの要件に従って決済メッセージを暗号化するもので、登録しても必要です。

決済時は Payments アプリが開き、Mini mPOS に戻ります。インストールしたアプリが TEST／LIVE を決めます。後で登録を解除するにはこのスマートフォンを削除を使います。

APIキーはこのデバイスに暗号化して保存します。Adyen はサーバーでの保管を推奨していますが、Mini mPOS にはサーバーがありません。必要最小限の権限を持つ、このデバイスや端末群専用の認証情報を使い、管理者PINを設定してください。漏えいや紛失時は認証情報を無効にします。セキュリティポリシーも確認してください。

最初の TEST 決済を行う

  1. 設定 › 端末で、選択または検出された環境がTESTであることを確認し、接続とAPIのテストを完了します。
  2. 設定 › 決済で Adyen アカウントが受け付ける通貨を、設定 › 税で税率と税込・税抜設定を確認します。
  3. 新規販売から任意の金額を入力して会計に進み、決済ボタンをタップして Adyen のテストカードを使います。
  4. 結果、領収書、取引履歴を確認し、返金も試します。結果が不明な場合は、別の決済を試す前に復旧手順に従ってください。

本番決済の前に

  • 予約金、チップ、支払いリンクなど、使うすべてのフローをテストしてください。シミュレーターは Adyen でのテストの代わりにはなりません。
  • プリンターがあれば実際のテスト領収書を印刷し、メール送信を使う場合はテストメールも送ります。
  • 管理者PINと、必要ならマネージャーPINを設定します。店舗設定を確認してください。
  • LIVEの端末またはPaymentsアプリとLIVE認証情報を使います。ネットワークやクラウドの端末では手順1でLIVEを選びます。CheckoutにはDevelopers › API URLsのlive URL prefixが必要です。AdyenのLIVE エンドポイントを参照してください。LIVEを選択または検出すると欄が表示されます。
  • 接続とAPIをテストし、設定 › 端末でLIVEを確認します。ヘルパーはネットワークやクラウド端末の環境選択をインポートしますが、Adyen端末の証明書やインストールしたPaymentsアプリの環境は上書きしません。

困った場合はトラブルシューティングへ。
