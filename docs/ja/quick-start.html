前提条件を確認する

設置日より前に確認してください。デバイスが Mini mPOS を動かし、端末がカードを読み取ります。同じ機器でも構いません。

デバイス構成を選ぶ

Adyen 端末で動かす
1 台で会計を完結できます。Android 9 以降の Adyen Android 決済端末が必要です。現在のモデルは Adyen Android 端末ガイドで確認してください。
タブレットやスマートフォンとネットワーク上の端末
カウンターにおすすめです。Android 9 以降のタブレットやスマートフォンを Adyen 端末と同じローカルネットワークに接続します。その端末への Mini mPOS のインストールは不要です。
タブレットやスマートフォンとクラウドの端末
デバイスと端末が別々のネットワークにある場合の構成です。どちらもインターネット接続が必要で、決済は Adyen を経由して端末に届きます。
スマートフォンの Tap to Pay
別の端末は不要です。近距離無線通信（NFC）に対応したスマートフォンと、Adyen サポートが有効化した Adyen Payments アプリを使います。Adyen のスマートフォン要件と Adyen の対応国・決済方法を確認してください。
  • 印刷にはプリンター内蔵の端末が必要です。AMS1 端末と Tap to Pay のスマートフォンにはプリンターがないため、領収書をメール送信または共有してください。
  • バーコード、返金用 QR コード、設定コードの読み取りにはカメラが必要です。

ネットワークを準備する

店舗のネットワーク管理者に、次の通信の許可を依頼してください。

インターネット（すべての実決済構成）
デバイスと端末から *.adyen.com と *.adyenpayments.com への TCP 443 の HTTPS 送信を許可します。Adyen の IP アドレスは変わるため、IP アドレスではなくドメイン名で許可してください。
ローカルネットワーク（ネットワーク上の端末）
タブレットやスマートフォンから端末の IP アドレスの TCP 8443 に接続できる必要があります。両方を同じネットワークに接続し、Wi-Fi のクライアント分離（ゲストネットワークでよく使われます）で隔てられていないことを確認してください。
領収書のメール送信（任意）
SMTP サーバーへの送信を許可します。通常は TCP 587（STARTTLS）または 465（SSL/TLS）です。

ネットワーク上の端末には、ルーターの DHCP 予約で固定 IP アドレスを割り当ててください。クラウドと Tap to Pay の構成ではタブレットやスマートフォンでモバイルデータを使えますが、ネットワーク上の端末とは使えません。端末自体の要件は Adyen のネットワーク設定ガイドを参照してください。

Adyen の認証情報を用意する

Adyen で構成を確認するには、有効なテスト用マーチャントアカウント、対面決済の有効化、Customer Area へのアクセスが必要です。まず TEST の認証情報と TEST 端末または Adyen Payments Test を使います。本番運用では、対応する LIVE のアカウント、認証情報、端末または Payments アプリを使います。通常の販売を含め、すべての実決済構成に Checkout API へのアクセスが必要です。

認証情報を作成・編集するには、Customer Area のユーザーに Manage API credentials または Merchant admin が必要です。これらはユーザー権限であり、APIキーのロールではありません。

Adyen の支払い方法設定ガイドに従って、受け付ける POS 決済方法を有効にしてください。Mini mPOS は端末に設定された決済方法を使います。

  1. Customer Area の Developers › API credentials で Mini mPOS 用の認証情報を作成し、APIキーを生成します。Adyen の API 認証情報ガイドを参照してください。
  2. メインの APIキーには、次のロールを有効にします。
    • Merchant PAL webservice role — 決済 API へのアクセス
    • Checkout webservice role — API 確認、キャプチャ、金額調整、支払いリンク
    • Management API — Terminal actions read — 端末へのアクセス確認
    • Management API — Terminal settings read and write — 端末設定と共有キーの作成
    • Management API — Terminal settings Advanced read and write — 共有キーなどの機密設定
    • Cloud Device API role — クラウドの端末のみ
    Mini mPOS は、手入力、クラウド、Tap to Pay を含むすべての実決済構成で、3 つの Management ロールを確認します。認証情報はご自身の Company アカウントに属し、決済先のマーチャントアカウントへのアクセス権が必要です。Adyen の API ロールガイドを参照してください。
  3. 任意：支払いリンクでカードを保存する場合は、Merchant Recurring role も有効にします。Adyen のオンライン決済トークン化ガイドを参照してください。
  4. 任意：領収書の店舗情報を取り込む場合は、Management API — Stores read（店舗名、住所、電話番号）または Management API — Account read（法人名のみ）も追加します。
  5. 任意：お客様のウォレットをスキャンする決済には Management API — Payment methods read を追加します。この読み取り権限は照会だけに影響し、通常の支払いを妨げません。
  6. マーチャントアカウントを控えます。LIVE では Developers › API URLs の LIVE URLプレフィックスも控えます。
  7. Devices › Device settings › Integrations › Terminal API › Encryption key で共有キー（識別子、パスフレーズ、バージョン）を確認します。物理端末では自動設定で取得できますが、Tap to Pay では入力が必要です。クラウドの端末では使いません。
  8. Tap to Pay のみ：スマートフォンの登録用に、Adyen Payments app role だけを持つ別の認証情報を作成します。

重要

Mini mPOS にはサーバーがないため、APIキーはデバイスに暗号化して保存します。ご自身の構成に必要な API ロールだけを持つ Mini mPOS 専用の認証情報を作成してください。管理者PINを設定してください。デバイスを紛失したら認証情報を無効にします。セキュリティポリシーも確認してください。

注記

Mini mPOS は独立したプロジェクトで、Adyen による製品、推奨、サポートではありません。アカウントやプラットフォームの手順はリンク先の Adyen 文書に従ってください。

アプリをインストールする

最新リリースから署名済みの minimpos-<version>.apk をダウンロードします。

Adyen 端末
  1. Customer Area で APK をアップロードし、端末に配布します。Adyen のアプリ配布ガイドを参照してください。ユーザーにはアプリのアップロード・配布権限が必要です。
  2. 端末で Mini mPOS を開き、端末を設定を選びます。
タブレットやスマートフォン
  1. デバイスで APK を開き、Android の案内に従ってブラウザーやファイルマネージャーからのインストールを許可します。
  2. Mini mPOS を開き、端末を設定を選びます。

重要

更新は毎回同じ署名元からインストールしてください。端末は別のキーで署名した更新を拒否します。自分でビルドして署名する場合は貢献者向けガイドを参照してください。

Adyen に接続する

接続により、Mini mPOS を端末または Adyen Payments アプリとペアリングし（端末ペアリング）、Adyen APIキーを確認します。該当する構成の手順だけを進めてください。どの構成にも、セットアップヘルパー（推奨）と設定 › 端末での手入力の 2 つの方法があります。

設定 › 端末では手順が 1 つずつ表示され、テストが成功すると次に進めます。Adyen から端末情報を補完する設定を取得は、APIテストが成功した後にだけ表示されます。不足している項目はホームに表示されます。

パソコンから設定コードを読み取る

  1. 信頼できるパソコンでセットアップヘルパーを開きます。オフラインで動作し、何も送信しません。
  2. Mini mPOS を動かす場所と、環境（TEST または LIVE）を選びます。
  3. 自動（推奨）では Adyen APIキーだけを入力し、残りはデバイスが取得します。手動では接続情報をすべて入力します。LIVE ではどちらも LIVE URLプレフィックスが必要です。
  4. 任意で、領収書の情報とメール（SMTP）設定を含めます。
  5. QRコードを作成をクリックします。12 文字の転送コードが表示されるため、ページは開いたままにします。
  6. Mini mPOS の設定 › 端末で設定コードを読み取るか右上の QR アイコンをタップし、すべてのコードを読み取ります。
  7. 決済先と環境を確認し、転送コードを入力して確認してインポートをタップします。
  8. 案内があれば端末を選ぶか、Tap to Pay のスマートフォンを登録します。すべての確認に成功するまで何も保存されず、成功するとホームに戻ります。Tap to Pay や店舗情報についてのお知らせがある場合は、ホームに戻らずに表示します。

情報が不足しているとインポートで表示された場合は、手動で新しいコードを作成してください。SMTP 設定を含めた場合はテストメールを送ります。メール設定を参照してください。

Adyen 端末を接続する

前提条件

  • Mini mPOS を端末に配布済み
  • 端末と同じ環境の Adyen APIキー
  • 端末のインターネット接続
セットアップヘルパー（推奨）
セットアップヘルパーでAdyen 端末で動かす、端末の TEST または LIVE 環境、自動を選びます。APIキーを入力し、コードを読み取ります。Mini mPOS がこの端末のマーチャントアカウントと共有キーを取得します。
手動
  1. 設定 › 端末 › Adyen APIで Adyen APIキーとマーチャントアカウントを入力し、LIVE では LIVE URLプレフィックスも入力します。APIをテストをタップし、任意で設定を取得をタップして共有キーを補完します。
  2. 共有キーを確認または入力し、接続をテストをタップします。

端末の ID、アドレス、環境は自動で検出されます。

ネットワーク上の端末をペアリングする

前提条件

  • タブレットやスマートフォンに Mini mPOS をインストール済み
  • 端末と同じ環境の Adyen APIキー
  • デバイスと端末が同じネットワークにあり、相互に TCP 8443 で通信できること
セットアップヘルパー（推奨）
セットアップヘルパーでタブレットやスマートフォンで動かす（同じネットワーク上の端末）、端末の TEST または LIVE 環境、自動を選びます。APIキーを入力し、コードを読み取ります。複数の端末が見つかった場合は、使う端末を選びます。
手動
  1. 設定 › 端末で決済先をネットワーク上の端末にします。環境で端末に合う TEST または LIVE を選びます。
  2. Adyen APIで Adyen APIキーとマーチャントアカウントを入力し、LIVE では LIVE URLプレフィックスも入力します。APIをテストをタップし、任意で設定を取得をタップして端末を選びます。
  3. 端末の IP アドレスと端末ID（POIID）を確認または入力します。どちらも端末の「Device info」画面に表示されます。
  4. 共有キーを確認または入力し、接続をテストをタップします。

端末の環境が選択と一致しない場合、接続は拒否されます。

クラウドの端末を接続する

前提条件

  • タブレットやスマートフォンに Mini mPOS をインストール済み
  • 端末と同じ環境で Cloud Device API role を持つ Adyen APIキー
  • デバイスと端末のインターネット接続
セットアップヘルパー（推奨）
セットアップヘルパーでタブレットやスマートフォンで動かす（インターネット経由の端末（クラウド））、端末の TEST または LIVE 環境、自動を選びます。Cloud Device API role を持つ APIキーを入力し、コードを読み取ります。複数の端末が見つかった場合は、使う端末を選びます。
手動
  1. 設定 › 端末で決済先をインターネット経由の端末（クラウド）にします。環境で端末に合う TEST または LIVE を選びます。
  2. Adyen APIで Adyen APIキーとマーチャントアカウントを入力し、LIVE では LIVE URLプレフィックスも入力します。APIをテストをタップし、任意で設定を取得をタップして端末を選びます。
  3. 端末ID（POIID）を確認または入力し、接続をテストをタップします。

クラウド決済は、ローカルの決済より端末に届くまで少し時間がかかる場合があります。

Tap to Pay を設定する

前提条件

  • Adyen が会社向けに Tap to Pay と Adyen Payments app role を有効化済み。Adyen サポートに連絡してください
  • Mini mPOS をインストールした対応スマートフォン
  • Adyen APIキー、別の Payments アプリの APIキー、共有キー
  1. Google Play から、TEST 用の Adyen Payments Test か LIVE 用の Adyen Payments をインストールします。両方は入れないでください。
  2. Mini mPOS の設定 › 端末でこのスマートフォンでTap to Payを選びます。
セットアップヘルパー（推奨）
セットアップヘルパーでスマートフォンで動かす（Adyen Payments アプリの Tap to Pay）と、インストールしたアプリの TEST または LIVE 環境を選びます。Adyen APIキー、マーチャントアカウント、Payments アプリの APIキー、共有キー、任意で店舗IDを入力します。コードを読み取り、案内に従ってスマートフォンを登録します。
手動
  1. 設定 › 端末 › Adyen APIで Adyen APIキーとマーチャントアカウントを入力します。LIVE では LIVE URLプレフィックスも入力し、APIをテストをタップします。
  2. Tap to Payで、Adyen Payments app role のみを持つPaymentsアプリのAPIキーを入力します。店舗IDは任意です。
  3. Tap to Payを設定をタップし、Payments アプリで登録を完了します。
  4. Mini mPOS で共有キーを入力します。

Mini mPOS がスマートフォンを Adyen に登録（オンボーディング）するため、登録トークンをコピーする必要はありません。共有キーは引き続き決済メッセージを暗号化するもので、登録しても必要です。

Payments アプリは接続テストに対応しないため、TEST の構成を確認するで設定を確認してください。決済中は Payments アプリが開き、終わると Mini mPOS に戻ります。後で登録を解除するにはこのスマートフォンを削除を使います。

不足している暗号化キーを作成する

物理端末に暗号化キーがまだない場合、認証情報とアカウントの確認後に暗号化キーを作成が表示されます。

  1. 表示された端末IDと環境を確認してから確定します。作成中は、他の場所でこの端末の設定を変更しないでください。
  2. 接続がまだ確認されていない場合は、端末の設定を更新します。キー設定の復旧を参照してください。
  3. 作成が中断した場合はキー設定を再開をタップします。QR 設定では、同じコードとその転送コードをもう一度読み取ります。

Mini mPOS は Adyen の既存のキーを再利用し、置き換えることはありません。クラウドの端末と Tap to Pay ではこの操作は使いません。

目次に戻る

TEST の構成を確認する

  1. 設定 › 端末で、環境が TEST であることを確認します。APIをテストを実行し、成功を確認します。
    • 物理端末：接続をテストを実行し、成功を確認します。
    • Tap to Pay：スマートフォンが Adyen Payments Test に登録されていることを確認します。接続テストはありません。以下の決済で構成を確認します。
  2. 設定 › 決済で通貨を、設定 › 税で税率と税込・税抜の設定を確認します。
  3. ホームで新規販売をタップし、任意の商品を追加して会計ボタンをタップします。
  4. 決済ボタンをタップし、Adyen の POS テストガイドに従って成功する決済を行います。
  5. 結果が承認済みで、領収書の金額、通貨、税額が正しいことを確認します。取引履歴で販売を開き、PSP参照IDで TEST Customer Area の決済と照合します。
  6. この決済を返金し、TEST Customer Area で最終結果を確認します。返金要求済みは最終確認ではありません。
  7. Adyen の POS テストガイドの拒否シナリオで販売をもう一度試します。Mini mPOS が承認ではなく拒否を表示することを確認します。決済の拒否を参照してください。

警告

結果が不明な場合は、もう一度決済しないでください。先に復旧手順に従います。

次はMini mPOS の使い方で、商品、領収書、スタッフの権限を設定します。

目次に戻る

本番運用を始める

  1. 使う予定の任意のフローだけを TEST で試します：予約金、領収書のチップ、支払いリンク、ウォレットのスキャン。予約金と領収書のチップは、キャプチャまで金額を確保します。最終的なキャプチャ結果は Customer Area で確認します。シミュレーターは Adyen テストの代わりになりません。
  2. 使う予定の領収書の渡し方をテストします。実際のプリンターで印刷するか、テストメールを送信するか、領収書を共有します。
  3. 管理者PINと、必要ならマネージャーPINを設定します。スタッフの権限を参照してください。
  4. LIVE の端末または LIVE 版 Payments アプリと、LIVE の認証情報に切り替えます。ネットワークやクラウドの端末では環境で LIVE を選びます。LIVE URLプレフィックスを入力します。Adyen の LIVE エンドポイントガイドを参照してください。
  5. 設定 › 端末でAPIをテストを実行し、成功を確認します。環境が LIVE であることを確認します。
    • 物理端末：接続をテストを実行し、成功を確認します。
    • Tap to Pay：スマートフォンが LIVE 版 Adyen Payments アプリに登録されていることを確認します。接続テストはありません。

警告

TEST、LIVE、シミュレーターを切り替えると、未完了の決済の復旧データを含め、デバイスのすべての決済履歴が削除されます。先に要確認の決済をすべて解決してください。

日々の確認と照合は締め作業を参照してください。アプリや Adyen の問題はサポートの範囲を確認してください。

シミュレーターを試す

Adyen アカウントや端末がなくても Mini mPOS を試せます。カードへの請求はありません。

  1. Android 9 以降のスマートフォンかエミュレーターにアプリをインストールします。
  2. ようこそ画面でサンプルでシミュレーターを試すを選びます。ほかに、設定 QR コードを読み込む別のデバイスから設定と、端末を設定があります。
  3. 設定 › シミュレーターで、決済結果、待ち時間、プリンターの有無を選びます。

サンプルの商品と履歴にはデモと表示されます。サンプルはデモの日次合計とレポートに含まれますが、実際の決済ではありません。設定 › データでサンプルデータを追加またはサンプルデータを削除を使えます。削除しても、ご自身の商品、履歴、設定は残ります。オフラインのデモリンクは支払いリンクを参照してください。ソースからビルドする場合は貢献者向けガイドを参照してください。
