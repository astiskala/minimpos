決済や返金が「結果不明」になった

警告

応答がないという理由だけで、もう一度請求・返金しないでください。リクエストは Adyen に届いている可能性があります。

  1. 取引履歴を開いて要確認で絞り込み、元の決済または返金を開きます。
  2. 結果を再確認をタップします。端末の場合、アプリはその取引の結果を端末に問い合わせます。
  3. それでも不明なら、参照ID、時刻、金額でCustomer Area › Payments › Payment listから決済を探します。確認してから次の操作を決めてください。

クラッシュや再起動で中断した操作は、不明として取引履歴に残ります。消すためにアプリデータを消去しないでください。

Tap to Pay では、Payments アプリに状態を問い合わせられません。結果を再確認は、すでに届いている遅れた応答だけを使います。応答がなければ、再請求の前に Customer Area を確認してください。

目次に戻る

決済が拒否された、または処理されなかった

結果画面には、状態、Adyen の理由、対処の案内が表示されます。案内に従ってください。

「このカードで再試行しないでください。別のカードまたは決済方法を購入者にお願いしてください。」

原因カード発行会社が、変わることのない理由（カードの停止や制限、不正の疑いなど）でこのカードを拒否したか、このカードはこの決済に使えません。

対処別のカードか決済方法をお願いします。拒否の理由はお客様の銀行が説明できます。表示された理由は Adyen の拒否理由で確認できます。

「再試行できます。」

原因決済がキャンセルされた、PIN が誤っていた、または残高不足など繰り返さない可能性のある理由でカードが拒否されました。

対処再試行をタップするか、別のカードをお願いします。

「端末で別の取引または管理メニューの操作中です。」

原因端末が別の決済を処理しているか、管理メニューを表示しています。

対処別の決済を終えるかメニューを閉じてから再試行します。画面に端末の現在の取引をキャンセルがある場合は、その取引を止めるときだけ使い、再試行の前に結果を確認します。

「現在、端末を使用できません。」

原因端末またはカードリーダーが一時的に使用できません。

対処少し待ち、端末の電源と接続を確認してから再試行します。ネットワークの切断を参照してください。

「端末がリクエストを受け付けませんでした。再試行する前に端末設定を確認してください。」

原因端末がリクエストを拒否したか、このサービスに対応していません。多くの場合、設定やアカウント構成の問題です。

対処設定 › 端末でテストを実行します。端末ペアリングと設定を参照してください。テストに成功する場合は、端末の構成確認を Adyen に依頼してください。

「再度請求しないでください。この決済は成功しています。」

原因端末はキャンセルを報告しましたが、決済は承認されています。

対処再請求しないでください。お客様が支払うべきでない場合は返金します。

目次に戻る

ウォレットスキャンが表示されない、または失敗する

ウォレットをスキャンがない

設定 › 端末でウォレットを更新をタップします。照会が成功しても対象 POS ウォレットがなければ、ボタンは表示しません。端末の店舗、現在の通貨、任意の照会権限を確認します。Tap to Pay とプリオーソリでは使えません。

ウォレット照会のエラー

エラーは設定だけに表示し、通常の支払いを妨げません。認証情報、環境、読み取り権限を確認してください。設定が同じなら、一時的な更新失敗では最後に確認した一覧を維持します。正常な空の結果やアクセス失敗では削除します。起動、設定変更、手動更新だけで照会し、毎回の販売前には照会しません。

コードが無効、または受信できない

プロフィール、設定転送、領収書 QR ではなく、お客様の支払いコードと正しいウォレットを選びます。端末スキャンは最大 30 秒です。再スキャンまたはカメラを使用を選び、求められたカメラ権限を許可してください。バックグラウンドから戻った場合も明示的な再開が必要です。

保存が拒否された、またはトークンがない

決済結果に従ってください。保存トークンがなくても承認済みの支払いは承認済みです。明確な拒否が確認された場合だけ、必要に応じて会計に戻り、カードを保存をオフにして新しいスキャンを始めます。自動で代替決済はしません。結果不明なら元の取引を確認します。

PayMe のスキャンが拒否された

PayMe の店舗側スキャンはベストエフォートで、Adyen の公開された制限と矛盾します。別の支払い方法をお願いするか、端末の通常のウォレット操作を使います。シミュレーターの承認は対応の証明ではありません。

ウォレット決済の手順を参照してください。履歴のリクエストしたウォレットは意図だけで、支払い成功や Adyen の実際の方法を証明しません。

目次に戻る

端末ペアリングや設定がうまくいかない

まずホームのメッセージを確認し、設定 › 端末でAPIをテストを実行します。物理端末では接続をテストも実行します。Tap to Pay では Payments アプリの登録状態を確認します。詳しい手順はAdyen に接続するを参照してください。

ホームに「端末設定に…を入力してください」と表示される

原因必須項目が空であるか、保存したキーをこのデバイスで読み取れません。

対処設定 › 端末で不足している項目を入力するか、キーを入力し直します。

API のテストに失敗する、またはアクセスの問題が表示される

原因APIキー、マーチャントアカウント、LIVE URLプレフィックスが誤っている、ロールが不足している、または認証情報が別の Company アカウントや環境のものです。

対処認証情報の要件に照らしてロールとアクセス範囲を確認します。LIVE では LIVE URLプレフィックスを確認します。

「加盟店アカウントが端末の現在の割り当てと一致しません。」

原因端末は Adyen で別のマーチャントアカウントに割り当てられています。

対処端末が割り当てられているマーチャントアカウントを入力するか、Customer Area で端末を割り当て直します。

Adyen 端末やネットワーク上の端末で接続テストに失敗する

原因共有キーが一致しないか、IP アドレスや端末ID（POIID）が古くなっています。

対処共有キーの識別子、パスフレーズ、バージョンを Customer Area と照合します。ネットワーク上の端末では、端末の「Device info」画面で IP アドレスと POIID を確認します。

環境の不一致で接続が拒否される

原因TEST と LIVE が混在しています。端末、アカウント、APIキーはすべて同じ環境のものが必要です。

対処ネットワークやクラウドの端末では、設定 › 端末の環境を確認します。Adyen 端末や Tap to Pay では、正しい環境のデバイスまたは Payments アプリを使います。

クラウドの端末に接続できない

原因端末がオフライン、POIID が誤っている、または APIキーに Cloud Device API role がありません。

対処端末の電源が入りオンラインであることを確認し、POIID と認証情報のロールを確認します。

「TEST版とLIVE版のAdyen Paymentsアプリが両方インストールされています」

原因Tap to Pay では Payments アプリを 1 つだけ使います。

対処使わない方をアンインストールし、登録を完了して共有キーを入力します。設定チェックの成功はカード決済のテストではないため、TEST 決済を行ってください。

「新しいキーを保存しました。この端末で…設定を更新してください」

原因暗号化キーは Adyen で作成されましたが、端末がまだ読み込んでいません。

対処端末で Admin menu › Config › Update を開き、Mini mPOS に戻ってもう一度確認をタップします。作成が中断した場合はキー設定を再開をタップします。2 つ目のキーは作成されません。キーの作成と Adyen の設定更新ガイドを参照してください。

以前の決済の操作がブロックされる

原因その決済の後で、マーチャントアカウント、環境、端末が変わりました。

対処その決済を受け付けたときの設定に戻すか、Customer Area で処理します。別のアカウントで処理しないでください。

目次に戻る

接続が切れる、または端末が応答しない

重要

接続が切れたときに決済の途中だった場合は、再請求の前にその結果を確認してください。

「端末から応答がありませんでした」と表示される、またはネットワーク上の端末がときどきつながらない

原因端末の IP アドレスが変わった、デバイスが別のネットワークに移った、またはネットワークが接続を遮断しています。

対処

  1. 端末の「Device info」画面で IP アドレスを確認し、設定 › 端末で更新します。
  2. デバイスと端末を同じネットワークに接続します。デバイスを分離することが多いゲスト Wi-Fi は避けてください。
  3. 両者間の TCP 8443 の許可と、端末の IP アドレスの予約をネットワーク管理者に依頼します。ネットワークの要件を参照してください。
どの構成でも決済や API のテストに失敗する

原因デバイスや端末がインターネットに接続できないか、ファイアウォールが Adyen への通信を遮断しています。

対処インターネット接続を確認し、Adyen のドメインへの TCP 443 の HTTPS 通信が許可されていることを確認します。

クラウド決済がタイムアウトする

原因端末のインターネット接続が切れています。

対処端末の Wi-Fi、イーサネット、モバイルデータを確認し、接続をテストを実行します。

目次に戻る

キャプチャや調整が失敗した、または結果が不明

取引履歴で元の項目を開き、理由を確認します。Checkout API の設定が不足していれば完了させ、アカウントや環境が変わっていれば元に戻します。

キャプチャ失敗またはキャプチャ結果不明

対処キャプチャを再試行をタップします。同じキャプチャを安全に再送します。新しい決済は作らないでください。

金額調整が未解決のまま

対処同じ金額で再試行します。別の金額は別のリクエストとなり、最初のリクエストが解決するまでブロックされる場合があります。

チップが保存されない

原因20% を超えるチップのための確保額の増額を、カード発行会社が拒否しました。

対処少ないチップを入力するか、チップなしをタップします。

キャプチャ要求済みや返金要求済みが変わらない

原因これは Adyen がリクエストを受け付けたという意味です。Mini mPOS にはサーバーがないため、最終確認を受け取りません。

対処最終結果は Customer Area で確認してください。

確保には期限があるため、速やかに解決してください。通常の手順は予約金と領収書のチップを参照してください。

目次に戻る

支払いリンクが表示されない、更新されない

会計に支払いリンクを作成がない

原因Checkout API の設定が完了していないか、プリオーソリまたは領収書のチップの会計です。

対処設定 › 端末で Checkout API の設定を完了します。リンクは販売専用です。オフラインのデモは支払いリンクを参照してください。

支払済みのリンクが支払い待ちのまま

原因アプリはリンク画面を開いている間だけ確認します。

対処取引履歴で項目を開き、支払いを確認をタップします。

リンクの作成が中断した

対処元の項目を開いて支払いを確認をタップします。元のリクエストで再試行するため、リンクを得るためだけに別の販売を作らないでください。

支払済みリンクの返金はCustomer Area › Payments › Payment listで行います。

目次に戻る

プリンターや領収書のメール送信が動かない

印刷されない、または領収書を印刷がない

原因端末にプリンターがない、プリンターが検出されていない、または接続が切れています。AMS1 端末と Tap to Pay のスマートフォンにはプリンターがありません。

対処

  1. 設定 › アプリ情報でプリンターがありになっていることを確認します。なっていなければ、設定 › 端末で接続をテストを実行します。
  2. 設定 › 領収書でプリンターを自動検出にし、決済後に自動印刷を確認します。
  3. テスト領収書を印刷をタップします。印刷されない場合は、端末のロール紙を確認します。
レイアウトが切れる、折り返しがおかしい

対処設定 › 領収書で1行の文字幅を変更し、テスト領収書を印刷します。

テストメールの送信に失敗する

原因サーバー、ポート、セキュリティ方式、パスワードが誤っているか、プロバイダーが SMTP やパスワードでのログインを禁止しています。

対処設定 › メール（SMTP）でサーバー、ポート、STARTTLS または SSL/TLS、ユーザー名、パスワードを確認します。プロバイダーによっては SMTP の有効化やアプリパスワードが必要です。メール設定を参照してください。

テストメールは届くが、お客様に領収書が届かない

対処設定 › 決済 › 領収書のメール送信で、メールを尋ねるタイミングと自動送信の有無を確認します。

PIN や設定転送の問題

スタッフがマネージャーPINを忘れた

対処管理者が設定 › セキュリティで変更・削除できます。管理者PINとマネージャーPINは保護する操作が異なり、一方で他方を解除することはできません。

管理者PINを忘れた

原因PIN の復旧機能はありません。

対処唯一の方法は、Android でアプリのデータを消去することです。

警告

アプリのデータを消去すると、デバイスのすべての商品、設定、キー、決済履歴が削除されます。先に未完了の決済を解決し、必要な記録を保存してください。設定転送では履歴を復元できません。

転送コードが拒否される、またはインポート後にキーがない

原因コードがこの QR コードのものではないか、空欄でした。

対処新しく生成したコードではなく、この QR コードと一緒に表示されたコードを使います。すべての転送にコードが必要です。誤ったコードでも空欄でも何も取り込みません。コピー後は、新しいデバイスの決済先と認証情報を確認します。追加デバイスを参照してください。

各 PIN が保護する操作はスタッフの PINを参照してください。

目次に戻る

端末にアプリをインストールできない

INSTALL_PARSE_FAILED_NO_CERTIFICATES

原因APK が署名されていません。

対処最新リリースの署名済み minimpos-<version>.apk をアップロードします。

INVALID_SIGNING_CERTIFICATE_MISMATCH

原因APK が以前のアップロードと異なるキーで署名されています。

対処元の署名元を使います。変更が必要な場合は、旧バージョンの削除を Adyen サポートに相談してください。

Android のバージョンが非対応

原因Mini mPOS には Android 9 以降が必要です。旧 S1E は Android 7.1 です。

対処対応する端末を使います。インストールを参照してください。

目次に戻る

まだ解決しない場合

Adyen アカウント、端末の配布、決済方法、最終的な決済結果については Adyen に問い合わせてください。アプリの問題はGitHub issueで、アプリのバージョン、デバイスのモデル、構成、TEST または LIVE、再現手順を知らせてください。

重要

キー、パスワード、PIN、顧客情報は絶対に含めないでください。脆弱性の疑いはセキュリティポリシーに従って非公開で報告します。
