決済や返金の結果が不明

応答がないという理由だけで、もう一度請求・返金しないでください。リクエストは Adyen に届いている可能性があります。元の操作を確認します。

  1. 取引履歴 › 要確認で元の決済・返金を開きます。
  2. 結果を再確認をタップします。ローカルやクラウド端末では元の取引結果を問い合わせます。
  3. 不明のままなら、参照ID、時刻、金額でCustomer Area › Payments › Payment listを確認してから次の操作を決めます。

クラッシュや再起動で中断した操作は、不明として残ります。アプリデータを消去して解決しようとしないでください。

Tap to Pay から応答なしで戻った

Payments アプリには取引状態を問い合わせられません。結果を再確認は遅れて届いた応答を使えますが、リモートで取得はできません。応答がなければ再請求前に Customer Area を確認します。

端末が使用中

ほかの決済を終えるか管理メニューを閉じます。結果画面に端末の現在の取引をキャンセルがある場合、その取引を止める意図があるときだけ使い、結果を確認してから再試行します。Tap to Pay はこの操作に対応しません。

決済の設定が未完了、または端末に接続できない

ホームの設定メッセージから設定 › 端末を開き、番号付き手順を完了して接続と API をテストします。必要なら構成別の接続手順を参照してください。

この端末、またはネットワーク上の端末
共有キーの識別子、パスフレーズ、バージョンを Customer Area と照合します。ネットワークでは現在の IP アドレス、POIID、同じネットワークで相互接続できることも確認します。
クラウド
マーチャントアカウント、POIID、認証情報の Cloud Device API と Checkout webservice ロールを確認します。端末がオフラインならクラウド決済はできません。
Tap to Pay
対象環境のPaymentsアプリを入れ、TESTとLIVEの両方は入れないでください。登録と共有キーの入力を完了します。設定チェックの成功はカード決済のテストではありません。
Checkout API
すべての実決済構成で必要です。アカウントとキーを確認し、LIVEではlive URL prefixも入力します。保存キーを読み取れなければ再入力します。
環境が違う
ネットワークやクラウドの端末では設定 › 端末の手順1で環境を確認し、同じ環境の端末、アカウント、APIキーを使います。証明書が一致しなければ接続を拒否し、API呼び出しは環境を自動変更しません。Adyen端末やTap to Payでは正しいデバイスまたはPaymentsアプリを使います。設定手順を参照してください。

アカウント、環境、端末を変えると、以前の決済の操作がブロックされる場合があります。その決済時の設定に戻すか Customer Area で処理してください。別アカウントで処理しようとしないでください。

キャプチャや調整が失敗、または結果が不明

取引履歴の元の項目で理由を確認します。不足する Checkout API 設定を直すか、元のアカウント・環境に戻します。

  • キャプチャを再試行は保存した同じ要求を同じ識別子で送ります。新しい決済を作らず、この操作を使ってください。
  • 未解決の調整は元の金額で再試行します。別の金額は別操作であり、先の操作を解決するまでブロックされる場合があります。
  • 発行会社がチップ増額を拒否した場合は少額かゼロを選びます。拒否された増額ではチップは保存されません。
  • キャプチャ要求済み、返金要求済み、非同期調整の受理は最終確認ではありません。Customer Area で確認してください。アプリは確認 webhook を受信できません。

要件は予約金と領収書のチップを参照してください。確保には期限があるので、速やかに解決します。

目次に戻る

支払いリンクが表示されない、更新されない

会計に支払いリンクを作成がない場合は設定 › 端末でCheckout APIの設定を完了します。リンクは自動で表示されます。実決済構成の販売専用で、プリオーソリ、領収書のチップ、シミュレーターでは使えません。

リンク画面が開いている間だけ確認し、バックグラウンドでは継続確認しません。取引履歴から開き直して支払いを確認します。支払い待ちは日計に含まれません。

リンク作成が中断し結果が不明な場合は元の項目を開き、支払いを確認をタップします。元の要求で作成を再試行します。リンクを得るためだけに別の販売を作らないでください。支払済みリンクの返金はCustomer Area › Payments › Payment listで行います。

通常の手順は支払いリンクの作成と管理を参照してください。

目次に戻る

領収書が印刷・メール送信できない

印刷：接続先に実際のプリンターがあるか確認します。設定 › アプリ情報を見て接続をテストし、設定 › 領収書の検出と自動印刷を確認してテスト領収書を印刷します。手動で使用可能に設定しても AMS1 や Tap to Pay のスマートフォンにプリンターは追加されません。

メール：設定 › メールからテストし、サーバー、ポート、STARTTLS/SSL、ユーザー名、指定パスワードを確認します。SMTP 有効化やアプリパスワードが必要、またはパスワード認証が禁止されている場合があります。設定 › 決済の自動送信とメール取得は別に確認します。メール設定と各社の説明を参照してください。

目次に戻る

PIN や設定転送の問題

マネージャーPIN：管理者が設定 › セキュリティで変更・削除できます。管理者PINとは保護対象が異なり、一方で他方が自動解除されることはありません。

管理者PINを忘れた場合：PIN の復旧機能はありません。Android のアプリデータ消去で PIN を削除できますが、全ローカル商品、設定、秘密情報、決済履歴も失います。未完了の決済を解決し、必要な記録を確保してください。設定転送は取引履歴を復元しません。この損失を受け入れる場合だけリセットします。

転送コード：その QR コードと一緒に表示されたコードを使います。新しく生成したコードは使えません。誤ったコードでは何も取り込まず、空欄では非秘密情報だけを取り込みます。保存失敗の表示を確認し、不足キーを再入力します。コピー後は受信側の決済先と認証情報を確認します。デバイスとデータを参照してください。

各 PIN の保護対象はスタッフの PIN 設定を参照してください。

目次に戻る

端末にインストールできない

INSTALL_PARSE_FAILED_NO_CERTIFICATES
APK が未署名です。最新リリースのメンテナー署名済み minimpos-<version>.apk をアップロードします。
INVALID_SIGNING_CERTIFICATE_MISMATCH
以前と署名キーが異なります。元の署名元を使い、意図的に変える場合は Adyen サポートに旧バージョン削除を相談します。
Android のバージョンが非対応
Android 9 以降が必要です。旧 S1E の Android 7.1 は非対応です。

デバイスに合ったインストール手順に従ってください。

目次に戻る

まだ解決しない場合

Adyen アカウント、端末配布、決済方法の有効化、最終結果は Adyen に問い合わせます。アプリの問題はGitHub issueで、アプリのバージョン、モデル、決済構成、TEST／LIVE、再現手順を知らせてください。

キー、パスワード、PIN、顧客情報を含めないでください。脆弱性の疑いはセキュリティポリシーに従って非公開で報告します。
