決済や返金が「結果不明」になった

警告

応答がないという理由だけで、もう一度請求・返金しないでください。リクエストは Adyen に届いている可能性があります。

  1. 取引履歴を開いて要確認で絞り込み、元の決済または返金を開きます。
  2. 結果を再確認をタップします。端末の場合、アプリはその取引の結果を端末に問い合わせます。
  3. それでも不明なら、参照ID、時刻、金額でCustomer Area › Payments › Payment list から決済を探します。確認してから次の操作を決めてください。

クラッシュや再起動で中断した操作は、不明として取引履歴に残ります。消すためにアプリデータを消去しないでください。

Tap to Pay では、Payments アプリに状態を問い合わせられません。結果を再確認は、すでに届いている遅れた応答だけを使います。応答がなければ、再請求の前に Customer Area を確認してください。

目次に戻る

決済が拒否された、または処理されなかった

結果画面には、状態、Adyen の理由、対処の案内が表示されます。案内に従ってください。

「このカードで再試行しないでください。別のカードまたは決済方法を購入者にお願いしてください。」

対処別のカードか決済方法をお願いします。拒否の理由は購入者の銀行が説明できます。表示された理由は Adyen の拒否理由で確認できます。

原因

カード発行会社が、変わることのない理由（カードの停止や制限、不正の疑いなど）でこのカードを拒否したか、このカードはこの決済に使えません。

「再試行できます。」

対処再試行をタップするか、別のカードをお願いします。

原因

決済がキャンセルされた、PIN が誤っていた、または残高不足など繰り返さない可能性のある理由でカードが拒否されました。

「端末で別の取引または管理メニューの操作中です。」

対処別の決済を終えるかメニューを閉じてから再試行します。画面に端末の現在の取引をキャンセル がある場合は、その取引を止めるときだけ使い、再試行の前に結果を確認します。

原因

端末が別の決済を処理しているか、管理メニューを表示しています。

「現在、端末を使用できません。」

対処少し待ち、端末の電源と接続を確認してから再試行します。ネットワークの切断を参照してください。

原因

端末またはカードリーダーが一時的に使用できません。

「端末がリクエストを受け付けませんでした。再試行する前に端末設定を確認してください。」

対処設定 › 端末でテストを実行します。端末ペアリングと設定 を参照してください。テストに成功する場合は、端末の構成確認を Adyen に依頼してください。

原因

端末が送信されたリクエストを拒否しました。多くの場合、設定の問題です。

「端末またはAdyenアカウントがこのリクエストに対応していません。有効になっているかAdyenサポートに確認してから再試行してください。」

対処マーチャントアカウントで有効になっているか、Adyen サポートに確認を依頼してください。Tap to Pay の場合は、Adyen Payments App role だけでなく Tap to Pay on Android も有効になっているか確認してください。その後、再試行します。

原因

端末または Adyen が、決済で求めた機能を提供していません。多くの場合、アカウントで有効になっていないためです。

「再度請求しないでください。この決済は成功しています。」

対処再請求しないでください。購入者が支払うべきでない場合は返金します。

原因

端末はキャンセルを報告しましたが、決済は承認されています。

目次に戻る

任意の端末機能が使えない、または合計が一致しない

端末機能が表示されない、または拒否される

決済先とAdyen機能 を確認し、端末設定を再取得します。APIロールとAdyenのアカウント設定も確認してください。ローカルのスイッチだけではAdyen側のサービスは有効になりません。Tap to Payでは物理端末向けフローは使えません。チップは端末チップと領収書のチップ を比較してください。

金額の一部だけが承認された

結果画面から一部承認の手順 に従ってください。元の全額を再請求しないでください。次の決済が結果不明の場合は、追加決済の前に結果を確認します。

端末の合計がMini mPOSと一致しない

端末集計照合 で、集計期間、同じ端末を使う別のデバイス、保存済み履歴、未解決取引を確認します。期間を締めても差異は修正されず、精算の確認にもなりません。

オフライン販売にPSP参照IDがない、または未確認バッチが残る

オフライン決済の確認手順 に従います。端末とAdyenの接続を復旧し、Customer Areaでアップロードされた決済を確認してください。PSP参照IDがないだけで承認済みの決済を再請求しないでください。

目次に戻る

ウォレットスキャンが表示されない、または失敗する

ウォレットをスキャンがない

設定 › 端末でウォレットを更新をタップします。照会が成功しても対象 POS ウォレットがなければ、ボタンは表示しません。端末の店舗、現在の通貨、APIキーのロールを確認します。Tap to Pay とプリオーソリでは使えません。

ウォレット照会のエラー

エラーは設定だけに表示し、通常の支払いを妨げません。認証情報、環境、読み取り権限を確認してください。設定が同じなら、一時的な更新失敗では最後に確認した一覧を維持します。正常な空の結果やアクセス失敗では削除します。起動、設定変更、手動更新だけで照会し、毎回の販売前には照会しません。

コードが無効、または受信できない

プロフィール、設定転送、領収書 QR ではなく、購入者の支払いコードと正しいウォレットを選びます。端末スキャンは最大 30 秒です。 再スキャンまたはカメラを使用を選び、求められたカメラ権限を許可してください。バックグラウンドから戻った場合も明示的な再開が必要です。

保存が拒否された、またはトークンがない

決済結果に従ってください。保存トークンがなくても承認済みの支払いは承認済みです。明確な拒否が確認された場合だけ、必要に応じて会計に戻り、 カードを保存をオフにして新しいスキャンを始めます。自動で代替決済はしません。結果不明なら元の取引を確認 します。

ウォレット決済の手順を参照してください。履歴のリクエストしたウォレットは意図だけで、支払い成功や Adyen の実際の方法を証明しません。

目次に戻る

端末ペアリングや設定がうまくいかない

まずホームのメッセージを確認し、設定 › 端末の最後の接続をテストで API アクセスと連携が対応する接続チェックを確認します。ネットワーク端末とクラウド端末では設定する端末を検索で API アクセスを確認し、端末を一覧表示します。端末本体と Tap to Pay ではAPIをテストも利用できます。詳しい手順はAdyen に接続するを参照してください。

すべての連携で設定 › ヘルプとトラブルシューティング › トラブルシューティングの詳細を開けます。設定不足、API アクセス、対応する接続チェック、時刻、デバイス情報を表示し、非対応のチェックを明示します。決済・返金・印刷の成功は保証せず、決済、端末登録、キー変更は行いません。機密情報を除いたレポートを共有 で表示中の詳細を共有できます。加盟店、端末、インストール、認証情報の ID は残し、秘密の値、非構造化メッセージ、購入者データは除外します。

ホームに「決済の設定が完了していません」と表示される

対処決済の設定を完了をタップします。設定 › 端末で不足している項目を入力するか、キーを入力し直し、 接続をテストをタップします。

原因

必須項目が空であるか、保存したキーをこのデバイスで読み取れないか、設定の変更後に接続テストが成功していません。それまでは、決済、返金、印刷などのAdyen操作は実行されず、この説明が表示されます。

API のテストに失敗する、またはアクセスの問題が表示される

対処認証情報の要件に照らしてロールとアクセス範囲を確認します。LIVE では LIVE URLプレフィックスを確認します。

原因

APIキー、マーチャントアカウント、LIVE URLプレフィックスが誤っている、ロールが不足している、または認証情報が別の Company アカウントや環境のものです。

「加盟店アカウントが端末の現在の割り当てと一致しません。」

対処端末が割り当てられているマーチャントアカウントを入力するか、Customer Area で端末を割り当て直します。

原因

端末は Adyen で別のマーチャントアカウントに割り当てられています。

Adyen 端末やネットワーク上の端末で接続テストに失敗する

対処共有キーの識別子、パスフレーズ、バージョンを Customer Area と照合します。ネットワーク上の端末では、端末の「Device info」画面で IP アドレスと POIID を確認します。

原因

共有キーが一致しないか、IP アドレスや端末ID（POIID） が古くなっています。

環境の不一致で接続が拒否される

対処ネットワークやクラウドの端末、Tap to Pay では、設定 › 端末の環境 を確認します。Adyen 端末では、正しい環境のデバイスを使います。

原因

TEST と LIVE が混在しています。端末、アカウント、APIキーはすべて同じ環境のものが必要です。

クラウドの端末に接続できない

対処端末の電源が入りオンラインであることを確認し、POIID と認証情報のロールを確認します。

原因

端末がオフライン、POIID が誤っている、または APIキーに Cloud Device API role がありません。

選択した環境の Payments アプリがない

対処設定 › 端末 › 環境を確認し、Google Play から対応するアプリをインストールします。両方をインストールできます。登録を完了し、対応する共有キーを入力して TEST 決済で確認してください。

原因

選択した TEST または LIVE 環境の Payments アプリがインストールされていません。

カードをかざす前に Tap to Pay が UnavailableService を返す

Payments アプリがリクエストを完了できませんでした。この汎用エラーだけで Adyen の障害やクライアントキー不足とは判断できません。

設定 › 端末で接続をテストを実行します。確認結果の簡潔な表と機密情報を除いたレポートは、設定 › ヘルプとトラブルシューティング › トラブルシューティングの詳細を開きます。

Tap to Payを設定で、メインの API キーを使い登録用認証情報とクライアントキーを自動作成します。拒否された場合は 必要なロールを確認してください。新しいキーの反映まで数分待ち、もう一度接続をテスト します。それでも復旧できなければ後で再試行するか、Adyen サポートに対応する TEST Customer Area または LIVE Customer Area の確認を依頼してください。 Adyen Payments アプリの要件 も参照してください。

登録に使った同じ認証情報のキーが必要です。

機密情報を除いたレポートを共有は表示中の行だけを共有します。内容は、アプリのバージョン、API アクセスと接続の結果と確認日時 (UTC)、連携方法と環境、アカウント・店舗・インストール・共有キーの ID、Android・デバイス・Payments アプリのバージョン、Tap to Pay ではクライアントキーと登録の確認結果と確認済み認証情報です。

「新しいキーを保存しました。この端末で…設定を更新してください」

対処端末で Admin menu › Config › Update を開き、Mini mPOS に戻ってもう一度確認 をタップします。作成が中断した場合はキー設定を再開をタップします。2 つ目のキーは作成されません。 キーの作成と Adyen の設定更新ガイド を参照してください。

原因

暗号化キーは Adyen で作成されましたが、端末がまだ読み込んでいません。

以前の決済の操作がブロックされる

対処その決済を受け付けたときの設定に戻すか、Customer Area で処理します。別のアカウントで処理しないでください。

原因

その決済の後で、マーチャントアカウント、環境、端末が変わりました。

目次に戻る

接続が切れる、または端末が応答しない

重要

接続が切れたときに決済の途中だった場合は、再請求の前にその結果を確認してください。

「端末から応答がありませんでした」と表示される、またはネットワーク上の端末がときどきつながらない

対処

  1. 端末の「Device info」画面で IP アドレスを確認し、設定 › 端末で更新します。
  2. デバイスと端末を同じネットワークに接続します。デバイスを分離することが多いゲスト Wi-Fi は避けてください。
  3. 両者間の TCP 8443 の許可と、端末の IP アドレスの予約をネットワーク管理者に依頼します。ネットワークの要件を参照してください。
原因

端末の IP アドレスが変わった、デバイスが別のネットワークに移った、またはネットワークが接続を遮断しています。

どの構成でも決済や API のテストに失敗する

対処インターネット接続を確認し、Adyen のドメインへの TCP 443 の HTTPS 通信が許可されていることを確認します。

原因

デバイスや端末がインターネットに接続できないか、ファイアウォールが Adyen への通信を遮断しています。

クラウド決済がタイムアウトする

対処端末の Wi-Fi、イーサネット、モバイルデータを確認し、接続をテストを実行します。

原因

端末のインターネット接続が切れています。

目次に戻る

キャプチャや調整が失敗した、または結果が不明

取引履歴で元の項目を開き、理由を確認します。Checkout API の設定が不足していれば完了させ、アカウントや環境が変わっていれば元に戻します。

キャプチャ失敗またはキャプチャ結果不明

対処キャプチャを再試行 をタップします。同じキャプチャを安全に再送します。新しい決済は作らないでください。

金額調整が未解決のまま

対処同じ金額で再試行します。別の金額は別のリクエストとなり、最初のリクエストが解決するまでブロックされる場合があります。

チップが保存されない

対処少ないチップを入力するか、チップなしをタップします。

原因

20% を超えるチップのための確保額の増額を、カード発行会社が拒否しました。

キャプチャ要求済みや返金要求済みが変わらない

対処最終結果は Customer Area で確認してください。

原因

これは Adyen がリクエストを受け付けたという意味です。Mini mPOS にはサーバーがないため、最終確認を受け取りません。

確保には期限があるため、速やかに解決してください。通常の手順は予約金と領収書のチップを参照してください。

目次に戻る

決済リンクが表示されない、更新されない

会計に決済リンクを作成がない

対処設定 › 端末で Checkout API の設定を完了します。リンクは販売専用です。オフラインのデモは 決済リンクを参照してください。

原因

Checkout API の設定が完了していないか、プリオーソリまたは領収書のチップの会計です。

支払済みのリンクが支払い待ちのまま

対処取引履歴で項目を開き、支払いを確認をタップします。

原因

アプリはリンク画面を開いている間だけ確認します。

リンクの作成が中断した

対処元の項目を開いて支払いを確認 をタップします。元のリクエストで再試行するため、リンクを得るためだけに別の販売を作らないでください。

支払済みリンクの返金はCustomer Area › Payments › Payment listで行います。

目次に戻る

プリンターや領収書のメール送信が動かない

印刷されない、または領収書を印刷がない

対処

  1. 設定 › アプリ情報でプリンターがありになっていることを確認します。なっていなければ、設定 › 端末 で接続をテストを実行します。
  2. 設定 › 領収書でプリンターを自動検出にし、自動で印刷を確認します。
  3. テスト領収書を印刷をタップします。印刷されない場合は、端末のロール紙を確認します。
原因

端末にプリンターがない、プリンターが検出されていない、または接続が切れています。AMS1 端末と Tap to Pay のスマートフォンにはプリンターがありません。

レイアウトが切れる、折り返しがおかしい

対処設定 › 領収書で1行の文字幅 を変更し、テスト領収書を印刷します。

テストメールの送信に失敗する

対処設定 › 領収書のメール送信でサーバー、ポート、STARTTLS または SSL/TLS、ユーザー名、パスワードを確認します。プロバイダーによっては SMTP の有効化やアプリパスワードが必要です。メール設定を参照してください。

原因

サーバー、ポート、セキュリティ方式、パスワードが誤っているか、プロバイダーが SMTP やパスワードでのログインを禁止しています。

テストメールは届くが、購入者に領収書が届かない

対処設定 › 領収書のメール送信で、メールを尋ねるタイミングと自動送信の有無を確認します。

PIN や設定転送の問題

スタッフがマネージャーPINを忘れた

対処管理者が設定 › セキュリティ で変更・削除できます。管理者PINとマネージャーPINは保護する操作が異なり、一方で他方を解除することはできません。

管理者PINを忘れた

原因PIN の復旧機能はありません。

管理者PINなしで最初から設定し直すには、ストレージの復旧手順に従ってください。リセット前にデータ削除の警告を確認してください。

転送コードが拒否される、またはインポート後にキーがない

対処新しく生成したコードではなく、この QR コードと一緒に表示されたコードを使います。すべての転送にコードが必要です。誤ったコードでも空欄でも何も取り込みません。コピー後は、新しいデバイスの決済先と認証情報を確認します。追加デバイス を参照してください。

原因

コードがこの QR コードのものではないか、空欄でした。

各 PIN が保護する操作はスタッフの PINを参照してください。

保存済みの設定や認証情報を読み書きできない

Mini mPOS は、読み取れない設定や認証情報を置き換えずに停止します。未完了の設定や決済の復旧記録を含むファイルを保持するためです。

警告

ストレージの消去やアンインストールは、ローカルの商品、設定、認証情報、PIN、履歴、未完了操作の復旧記録をすべて削除します。設定転送では履歴や復旧記録を復元できません。リセットしても、Adyen に送信済みの決済、返金、売上確定は取り消されません。

  1. デバイスを再起動し、Mini mPOS を開き直します。ストレージがいっぱいの場合は、先に Mini mPOS 以外で空き容量を確保してください。アプリのキャッシュを消去するだけでは、保存済みの設定はリセットされません。
  2. リセット前に必要な記録を保存し、未完了の決済、返金、売上確定、調整を解決してください。アプリを開けない場合は Customer Area で結果を確認します。結果不明 を参照してください。結果がまだ不明な場合はアプリのデータを保持し、先に Adyen と照合してください。アプリを開けないことを理由に同じ操作を再送しないでください。
  3. 問題が続き、すべてのローカルデータの削除を了承する場合は Mini mPOS をリセットします。スマートフォンやタブレットでは Android の設定 › アプリ › Mini mPOS › ストレージとキャッシュ › ストレージを消去を開くか（項目名はデバイスによって異なります）、Mini mPOS をアンインストールして 最新リリースから再インストールします。Adyen 端末では、端末アプリの管理者にリセットまたは削除後の再インストールを依頼してください。 Adyen のアプリ配布ガイドを参照してください。
  4. Mini mPOS を設定し直すか、信頼できる設定転送を取り込み、接続をテストを完了してから実際の決済を行います。 Adyen に接続を参照してください。

既存アプリへの上書き更新ではストレージはリセットされません。エラーが再発する場合はGitHub でアプリの問題を報告 してください。保存済みの設定ファイルや認証情報を添付しないでください。

エラーメッセージが表示される

各メッセージは問題と確認すべき点を示します。括弧内の詳細（IPアドレス、HTTPステータス、Adyenの原文など）はAdyenサポートの調査に役立つため、問い合わせの際に伝えてください。決済の途中だった場合は、ほかの対処の前に その結果を確認してください。

エラーメッセージ
「端末に接続できませんでした。端末の電源、同じネットワークにあること、IPアドレスを確認してください。」

対処接続の切断を参照してください。

原因

Mini mPOS が、保存されたIPアドレスのネットワーク端末に接続できませんでした。

「このアドレスは選択した環境のAdyen端末ではありません。IPアドレスとTESTまたはLIVEを確認してください。」

対処端末の「Device info」画面でIPアドレスを確認し、設定 › 端末の環境を確認してください。

原因

そのアドレスで応答がありましたが、選択した環境のAdyen端末ではありません。アドレスが別のデバイスに割り当てられたか、TESTとLIVEが混在しています。

「端末が共有キーを拒否しました。端末設定でキー識別子、バージョン、パスフレーズを確認してください。」

対処Customer Area と照合するか、キーを設定し直してください。

原因

共有キーの識別子、バージョン、パスフレーズが端末のものと異なります。

「端末の応答を検証できませんでした。端末設定で共有キーを確認してください。」

対処再請求の前に結果を確認し、その後で共有キーを修正してください。

原因

端末が別の共有キーで応答したため、リクエストは端末に届いた可能性があります。

「端末がAdyenに接続されていません。端末の電源とオンライン状態を確認してください。」

対処端末のWi-Fi、イーサネット、モバイルデータを確認してから、接続をテストを実行してください。

原因

クラウド端末の電源が切れているか、インターネットに接続されていません。

「AdyenがAPIキーを受け付けませんでした。端末設定で確認してください。」

対処キーを入力し直し、認証情報の要件と照合してください。

原因

APIキーが間違っているか、無効化されたか、別の環境のものです。

「APIキーに必要なロール、またはこのマーチャントアカウントへのアクセス権がありません。Customer AreaでAPI認証情報を確認してください。」

対処Customer Area でロールまたはアカウントへのアクセス権を追加してください。認証情報の要件 を参照してください。

原因

認証情報に必要なロール、またはこのマーチャントアカウントへのアクセス権がありません。不足しているロールが分かる場合は括弧内に表示されます。

「Adyenが混雑しているか、一時的に利用できません。」

対処しばらく待ってから再試行してください。決済、キャプチャ、決済リンクの場合は、先にその結果を確認してください。

原因

Adyenがリクエストを制限しているか、一時的に利用できません。

「時間内に応答がありませんでした。」

対処結果を確認してください。結果が分かるまで再請求しないでください。

原因

リクエストは送信されましたが応答がなかったため、結果は不明です。

「Paymentsアプリからの応答はまだ届いていません。結果を問い合わせることはできないため、Customer Areaで決済を確認してください。」

対処再請求の前に、Customer Area で決済を確認してください。

原因

Tap to Payでは、Paymentsアプリに結果を問い合わせることができず、遅れて届く応答もまだありません。

「Adyen Paymentsアプリを開けませんでした。インストールされているか確認してください。」

対処環境に合ったPaymentsアプリをインストールしてから、再試行してください。Adyenに接続 を参照してください。

原因

Paymentsアプリがインストールされていないか、削除されました。

「メールサーバーがユーザー名またはパスワードを受け付けませんでした。「設定 › 領収書のメール送信」で確認してください。」

対処修正してから、テストメールを送信してください。

原因

SMTPのユーザー名またはパスワードが間違っているか、プロバイダーがアプリパスワードを要求しています。

「このデバイスの安全な保存領域を使用できませんでした。再試行するか、デバイスを再起動してください。」

対処再起動しても続く場合は、キーとパスワードを入力し直してください。

原因

Androidのキーストアが、保存された秘密情報を暗号化または読み取れませんでした。
