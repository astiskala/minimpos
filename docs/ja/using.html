日々の業務の手順です。決済、返金、領収書、一日の精算を扱い、任意の業務フローは最後にまとめています。

商品、税、スタッフの権限を準備する

Adyen に接続した後に一度だけ行います。

通貨と税を設定する

  1. 設定 › 決済で、Adyen アカウントが対面決済で受け付ける通貨を選びます。
  2. 設定 › 税で、税率、税込価格か会計時に税を加えるか、新商品の初期税率を確認します。

すべての商品に税率があり、非課税の商品には 0% の税率を使います。税を適用をオフにすると税はかかりませんが、税率は保持されます。

重要

通貨を変更しても価格の数値はそのままで、為替レートでは換算されません。変更後に商品価格を確認してください。

商品を追加する

  1. 商品を開き、+ をタップします。
  2. 名前、価格、税率を入力します。必要ならカテゴリーとバーコード（入力またはスキャン）を追加します。
  3. 予約金の商品はプリオーソリ商品をオンにし、プリオーソリだけに表示されるようにします。

スタッフの PIN を設定する

  1. 設定 › セキュリティで管理者PINを設定をタップします。設定と商品を保護します。再ロックまでの時間を選びます。
  2. 任意でマネージャーPINを設定をタップします。以後、返金、取消、キャプチャ、金額調整、チップ入力に必要になります。

管理者PINを変更・削除するには管理者PINを変更または管理者PINを削除を使います。削除するとマネージャーPINも削除されます。誤入力を繰り返すと一時的に入力がロックされます。PIN を忘れた場合は PIN の問題を参照してください。

目次に戻る

カード決済を受け付ける

  1. ホームで新規販売をタップします。商品をタップするか、バーコードをスキャンをタップするか、任意の商品を追加します。
  2. 会計ボタンをタップします。商品、税、合計を確認し、参照IDやメール欄を入力します。
  3. 決済ボタンをタップします。端末（Tap to Pay では Adyen Payments アプリ）がお客様に支払いを案内します。
  4. 結果を待ちます。結果が表示されるまで次の決済を始めないでください。
  5. 自動で届けていない場合は、領収書を印刷、領収書をメール送信、領収書を共有で領収書を渡します。

注記

カードは端末が読み取り、Mini mPOS がカードの全情報を受け取ることはありません。端末と Adyen アカウントに応じて、お客様はカードの挿入やタッチ、スマートフォンや腕時計のタッチで支払えます。非接触（NFC）決済では、端末が確認するまでカードやスマートフォンを非接触マークに近づけたままにします。Tap to Pay では Adyen Payments アプリの案内に従ってください。

警告

結果不明は失敗を意味しません。再請求する前に元の決済を確認してください。

顧客参照ID、カード保存、チップは任意です。参照IDとカード保存を参照してください。お客様自身のスマートフォンで支払う場合は支払いリンクを使います。決済が拒否された場合は拒否された決済を参照してください。

目次に戻る

お客様のウォレットコードをスキャンする

販売の会計でウォレットをスキャンを使い、お客様のウォレットアプリの支払いコードを読み取ります。商品バーコードや返金用領収書のスキャンとは別です。物理決済端末が必要で、Tap to Pay では使えません。ウォレット照会には任意の読み取り権限が必要です。

  1. 合計と会計欄を確認し、ウォレットをスキャンをタップします。領収書でのチップが選択されている場合は、それを使わず支払うことを確認します。ウォレットは合計を直ちに請求し、プリオーソリは行いません。
  2. お客様のウォレットを選びます。1 種類だけなら自動選択します。個別に設定されたものだけが表示され、Alipay+ の設定から GCash、DANA、Kakao Pay、TrueMoney の個別開通を推測しません。
  3. 内蔵スキャナーを確認できた端末では、その端末のスキャンボタンを押します。Mini mPOS のデバイスではなく、ネットワークやクラウドの決済端末の場合もあります。デバイスのカメラを使うにはカメラを使用をタップします。
  4. お客様の支払い QR コードまたは支払いバーコードをスキャンします。有効な 1 回のスキャンで直ちに決済が始まります。通常の結果を待ち、領収書を渡します。

キャンセルしてもカートと会計欄は残ります。無効なコードでは支払いません。再スキャンするかウォレットを変更してください。内蔵スキャンは最大 30 秒で終了し、その後は再スキャンまたはカメラを使えます。アプリを離れるとスキャンを停止し、戻ったら明示的な再開が必要です。コードの手入力や貼り付けはできません。

顧客参照IDと同意がある場合、カードを保存で支払い情報の保存を試みます。対応状況はウォレットによります。保存用トークンが返った場合だけ保存成功とし、トークンなしでも承認済みの決済は承認済みです。照会や決済の問題を参照し、結果不明の決済を再スキャンで置き換えないでください。

対象は GCash、DANA、Kakao Pay、TrueMoney、PayMe、Alipay、AlipayHK、Alipay+、WeChat Pay、PayPal、Venmo で、端末の店舗・国・通貨に対応した有効な POS 設定が必要です。PayMe のスキャンは意図的に未検証で、Adyen の公開された制限と矛盾し、拒否される場合があります。Adyen のウォレットガイドと PayPal/Venmo ガイドで開通状況と TEST 動作を確認してください。

S1F2 風の端末イラスト内の英語シミュレーターデモです。実際の支払いではなく、ウォレットや内蔵スキャナーの対応を証明するものではありません。

目次に戻る

決済を返金・取消する

返金
請求済みの決済が対象です。全額または一部を返します。
取消
キャプチャ前の確保中の決済が対象です。予約金はプリオーソリをキャンセル、チップ入力待ちの販売は決済をキャンセルをタップします。確保が解除されます。

返金の手順：

  1. ホームで返金をタップして領収書の返金用 QR コードをスキャンするか、取引履歴で元の販売を開きます。
  2. 全額、指定金額、商品単位のいずれかを選びます。商品単位の返金には、このデバイスに元の販売が必要です。
  3. 返金を確定し、求められたらマネージャーPINを入力します。

返金は必ず元の決済に紐づきます。元の決済がない返金には対応しません。支払済みの支払いリンクは Customer Area で返金します。

重要

返金要求済みは Adyen がリクエストを受け取ったという意味で、お客様への入金完了ではありません。最終結果は Customer Area で確認してください。返金の結果が不明な場合は、再試行の前に確認してください。

目次に戻る

領収書を印刷、メール送信、共有する

決済結果や取引履歴の項目で領収書を印刷または領収書をメール送信をタップします。タブレットやスマートフォンでは領収書を共有で、Android の共有メニューから画像を送れます。印刷にはプリンター付きの端末が必要です。

領収書をカスタマイズしてテストする

  1. 設定 › 領収書で店舗情報、ヘッダー、フッターを入力します。またはAdyenから店舗情報をインポートをタップし、Adyen の店舗情報で空欄を埋めます。端末に店舗がない場合は、マーチャントアカウントの法人名のみを取り込みます。これには任意の Management API — Stores read または Account read ロールが必要です。
  2. 決済後に自動印刷、加盟店控えを印刷する条件、返金用QRコードを表示するかを選びます。
  3. テスト領収書を印刷をタップして印字を確認します。画面のプレビューはプリンターの正確なレイアウトを示しません。

Adyen からのインポートは空欄だけを埋め、保存済みの文面を置き換えることはありません。そのほかの設定：

税額を表示
合計に含まれる税額、または加算する税額を表示します。課税額は変わりません。
税率別の内訳を表示
税率ごとの税額を表示します。税込価格で含まれる税額を表示するには必要です。
税率別の対象金額を表示
0% を含め、税率ごとに商品の合計を表示します。
参照IDを表示
初期設定でオンです。加盟店参照IDと入力済みの顧客参照IDを印刷し、領収書を決済と照合できるようにします。
印を付ける税率（%）
その税率の商品に商品の印と説明を付けます。空欄なら印を付けません。
1行の文字幅
細い領収書ロール向けに初期値は 32 です。テスト印刷でプリンターに合う幅を選んでください。

言語を設定する

英語、簡体字中国語、日本語に対応しています。Android 12 以前ではデバイスの言語に従い、Android 13 以降では Android のアプリごとの言語設定で選びます。Adyen のカード領収書の行は端末自体の領収書言語に従います。特に中国語・日本語では印字レイアウトをテストしてください。

領収書のメール送信を設定する

  1. 設定 › メール（SMTP）を開きます。プロバイダーを選ぶか、SMTP サーバー、ポート、差出人、ログイン情報を入力します。STARTTLS または SSL/TLS を使います。
  2. テストメールを送ります。
  3. 設定 › 決済 › 領収書のメール送信で、お客様のメールを尋ねるタイミングと自動送信の有無を選びます。

SMTP 情報はセットアップヘルパーでパソコンから入力することもできます。プロバイダーボタンはサーバー情報を入力するだけです。SMTP の許可と正しいパスワードについては各社の説明に従ってください。

  • Gmail
  • Microsoft 365
  • iCloud Mail
  • Yahoo Mail
  • Fastmail
  • Zoho Mail
  • Proton Mail

Mini mPOS はパスワード認証の SMTP を使い、OAuth は使いません。決済前に入力したメールは決済とともに Adyen にも送信します。決済後のメールは領収書専用です。

領収書を印刷・送信できない場合はプリンターとメールの問題を参照してください。

決済を探し、一日の精算をする

取引履歴は決済と返金を日別に表示し、日計も表示します。

  • 販売、チップ入力待ち、プリオーソリ、返金、要確認で絞り込み、カードブランドやウォレットは決済方法で選びます。
  • 参照ID、承認コード、顧客参照IDやメール、カード下4桁、ブランド、ウォレット、正確な金額で検索できます。すべての語が一致する必要があり、visa 34 は 34 の Visa 決済を探します。

画面の合計は検索とフィルターに従います。予約金や領収書のチップなど確保中の決済は、キャプチャが受理された日に売上として計上されます。

一日の精算をする

  1. 取引履歴を開いて要確認で絞り込み、各項目を解決します。結果が不明な場合を参照してください。
  2. チップ入力待ちとプリオーソリのフィルターを確認します。チップを入力し、確保の期限前に予約金をキャプチャまたはキャンセルします。
  3. 日付の横の印刷アイコンをタップし、ローカル日次集計を印刷します。
  4. Customer Area の Adyen レポートと照合します。Adyen の精算の照合を参照してください。

集計はフィルターを無視して一日全体を対象にし、売上、含まれるチップ、受理済みの返金、差引額、新規確保額、未解決の操作を通貨別に示します。TEST とシミュレーターの活動は明記されます。支払済みの支払いリンクと日付のわからないキャプチャは、日付不明の活動として別に表示されます。

重要

ローカル日次集計の対象は、このデバイスに保持された決済だけです。Adyen の最終的な精算（売上確定）ではなく、他のデバイスも含みません。Customer Area の情報が正となります。

警告

LIVE、TEST、シミュレーターを切り替えると、このデバイスのすべての決済履歴とレポートデータが完全に削除されます。未完了の決済がある場合は、もう一度警告が表示されます。Adyen 側では何も取り消されませんが、ローカルの復旧と安全な再試行データは失われます。商品と設定は残ります。

参照IDを使い、カードを保存する

加盟店参照ID
予約番号や注文番号を記録するには、設定 › 決済 › 加盟店参照IDの入力を求めるをオンにします。この番号は Adyen で決済を識別します。空欄なら一意の参照IDを生成します。
購入者参照ID
設定 › 決済で購入者参照IDを、会計で入力する顧客参照ID（初期設定）、お客様のメール、なしから選びます。すべての決済とともに Adyen に送信します。メールの参照IDは初期設定でハッシュ化されます。すべてのデバイスで同じソルトを使ってください。
カード保存
購入者参照IDを設定したうえでカード保存の選択肢を表示をオンにし、Adyen の設定に合った継続課金モデルを選びます。次回の決済用にカードを保存を選ぶ前にお客様の同意を得てください。Mini mPOS は保存したカードで請求できません。

目次に戻る

リンクで支払ってもらう

前提条件

  • 設定 › 端末で Checkout API の設定が完了していること（シミュレーターのデモでは不要）
  • LIVE で使う前に、利用規約を含む Adyen アカウントの Pay by Link の要件を満たしていること
  1. 販売の会計で支払いリンクを作成をタップします。
  2. QR コードを見せるか、リンクをメール送信、リンクを印刷、またはタブレットやスマートフォンでリンクを共有をタップします。
  3. リンク画面を開いたままにして入金を確認するか、後で取引履歴の項目で支払いを確認をタップします。
  4. リンクが不要になったらリンクを取り消すをタップします。

リンクが支払われる、期限切れになる、または取り消されるまで、項目には支払い待ちと表示されます。リンクの有効時間は設定 › 決済 › 支払いリンクで設定します。リンクは販売専用で、予約金や領収書のチップには使えません。

重要

有効期間中は、実際のリンクを持つ人なら誰でも支払えます。支払済みリンクの返金はCustomer Area › Payments › Payment listで行います。アプリからは返金できません。

シミュレーターでは、デモリンクに認証情報は不要です。支払いをシミュレートをタップすると完了します。QR コードで支払いはできず、領収書にはデモと明記されます。

リンクが表示されない、更新されない場合は支払いリンクの問題を参照してください。

目次に戻る

予約金を確保し、回収する

前提条件

  • Adyen サポートが決済方法のプリオーソリゼーションを有効化済み。Adyen のプリオーソリゼーションガイドを参照してください
  • Checkout API の設定が完了していること

プリオーソリゼーションはカードに金額を確保し、すぐには請求しません。アカウント全体を手動キャプチャにする必要はなく、Mini mPOS はこの決済だけに手動キャプチャを指定します。

  1. ホームで新規プリオーソリをタップします。プリオーソリ商品を選ぶか、バーコードをスキャンするか、金額を入力します。1 件につき 1 商品です。
  2. 会計でプリオーソリのボタンをタップします。領収書に確保額が表示されます。
  3. 準備ができたら取引履歴で項目を開き、操作を選びます。
キャプチャ
必要な金額を回収します。少ない金額なら残りを解除し、多い金額なら先にカード発行会社に確保額の増額を求めます。キャプチャを要求した後は返金できます。
金額を調整
請求せずに確保額を変更します。同じ金額を送るとオーソリゼーションを更新します。
プリオーソリをキャンセル
確保を解除します。Customer Area でキャプチャ済みの場合は、Adyen が代わりに全額を返金します。

キャプチャ要求済みは最終確認ではありません。Customer Area で確認してください。金額調整の結果をすぐに受け取るには、Adyen の調整ガイドに従い Return adjust authorisation data を有効にします。

警告

確保には期限があります。プリオーソリのフィルターを毎日確認し、速やかにキャプチャまたはキャンセルしてください。失敗や結果不明の操作はキャプチャの問題を参照してください。

目次に戻る

領収書に書かれたチップを回収する

前提条件

  • プリンター付きの端末
  • Adyen サポートがプリオーソリゼーションと overcapture を有効化済み。Adyen の領収書のチップを参照してください

設定 › 決済 › チップで有効（初期値オフ）か有効（初期値オン）を選び、会計のスイッチの初期状態を決めます。初期設定の無効ではスイッチを表示しません。一部のデビットカードやウォレットはこのフローに対応していません。

  1. 販売の会計で領収書にチップを記入をオンにし、決済ボタンをタップします。代金は確保され、請求されません。
  2. 領収書を印刷します。チップと合計の空欄があり、加盟店控えには署名欄があります。
  3. お客様が記入したら、結果画面か取引履歴のチップ入力待ちでチップを入力をタップします。
  4. チップまたは合計を入力するかチップなしをタップし、確定します。

アプリは代金とチップの合計をキャプチャします。20% を超えるチップでは、先にカード発行会社による確保額の増額が必要です。拒否された場合は、少ないチップかゼロを入力してください。保存したチップは変更できません。チップ入力前は返金ではなく決済をキャンセルし、入力後の返金にはチップが含まれます。

警告

ゼロも含め、チップは速やかに入力し、確保の期限前にキャプチャしてください。キャプチャの失敗や結果不明はキャプチャの問題を参照してください。

追加のデバイスを設定し、データを管理する

  1. 設定済みのデバイスで設定 › データ › 別のデバイスに共有を開きます。カタログ、設定、パスワードとキーから選び、QRコードを表示をタップします。
  2. 新しいデバイスで別のデバイスから設定を選び、すべてのコードを任意の順で読み取ります。カタログを統合するか置き換えるかを選びます。
  3. パスワードとキーをコピーするには、最初のデバイスに表示された転送コードを入力します。インポートをタップします。
  4. 価格と税を確認し、設定 › 端末で接続をテストして、テスト領収書を印刷します。

新しいデバイスは、自身の決済先、端末、環境、Tap to Pay の登録を保持します。共有キーを別の端末で使えるのは、Adyen がその端末に同じキーを割り当てている場合だけです。

重要

これは一度きりのコピーで、同期や決済履歴のバックアップではありません。各デバイスがそれぞれの決済を保持します。Android でアプリのデータを消去すると、デバイスのすべての商品、設定、履歴が削除されます。

設定 › データで取引の保存期間を設定するか、完了した履歴を消去をタップします。未解決の決済は常に残ります。更新は最新リリースから、最初のインストールと同じ方法で行ってください。

取り込みの問題は PIN と転送の問題を参照してください。
