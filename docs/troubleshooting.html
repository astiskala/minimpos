A payment or refund has an unknown result

Do not charge or refund again just because the app has no answer. The request may have reached Adyen. Check the original operation first.

  1. Open History › Needs attention and select the original payment or refund.
  2. Tap Check result again. For local or cloud terminals, the app asks for the original transaction's outcome.
  3. If it remains unknown, check Customer Area › Payments › Payment list using the reference, time and amount before deciding what to do next.

A crash or restart leaves interrupted operations visible as unknown. Do not clear app data to fix them.

Tap to Pay returned without an answer

The Payments app cannot be asked for a transaction's status. Check result again can use an answer that arrived late, but it cannot fetch one remotely. If none is available, check the Customer Area before charging again.

The terminal is busy

Finish the terminal's other payment or leave its admin menu. If the result screen offers Cancel the terminal’s current transaction, use it only when you intend to stop that transaction, then check its outcome before retrying. Tap to Pay does not support this command.

Payments are not set up or cannot reach the terminal

Start with Home's setup message, then Settings › Terminal. Complete its numbered steps and run the connection and API checks. Follow your setup's connection instructions if needed.

This terminal or one on your network
Match the shared key's identifier, passphrase and version to the Customer Area. On the network, check the terminal's current IP address and POIID, and that both devices can reach each other on the same network.
Cloud
Check the merchant account, terminal POIID and API credential's Cloud Device API and Checkout webservice roles. Confirm the terminal is online; a disconnected terminal cannot take a cloud payment.
Tap to Pay
Install the Payments app for the intended environment, not both TEST and LIVE apps. Complete registration and enter its shared key. A successful setup check does not test a card payment.
Checkout API
Every real-payment setup needs it. Verify the merchant account and key; LIVE also needs the live URL prefix. If a stored key cannot be read, enter it again.
Wrong environment
For a network or cloud terminal, check step 1, Environment, in Settings › Terminal. Use a matching terminal, merchant account and API key; a network certificate mismatch is rejected and API calls never switch environments automatically. On an Adyen terminal or with Tap to Pay, use the correct device or installed Payments app. See the setup steps.

After changing merchant account, environment or terminal, actions on an old payment may be blocked. Restore the setup that took that payment or handle it in the Customer Area; do not try to process it under another account.

A capture or adjustment failed or is unknown

Open the original entry in History and read its reason. Fix missing Checkout API settings or restore the payment's original account/environment.

  • Retry capture sends the same stored capture again with the same identity. Use this action rather than creating a new payment.
  • For an unresolved adjustment, retry the original amount; a different amount is a separate operation and may be blocked until the first is resolved.
  • If the issuer refused an increase for a tip, choose a smaller tip or no tip. A refused increase leaves the tip unsaved.
  • Capture requested, Refund requested and asynchronous adjustment acceptance are not final confirmation. Check the Customer Area; Mini mPOS cannot receive the confirming webhooks.

For workflow requirements, see deposits and tips on the receipt. Holds expire, so resolve them promptly.

Payment links are missing or not updating

If checkout has no Create payment link on a real-payment setup, complete Checkout API setup in Settings › Terminal. Links are offered automatically for sales, not pre-authorizations or tips on the receipt. For offline demos, see payment links.

The app checks while the link screen is open, not continuously in the background. Reopen it from History and tap Check payment. An awaiting-payment entry does not contribute to totals.

If link creation was interrupted and its result is unknown, open the original entry and tap Check payment. It retries creation with the original request; do not create another sale merely to get a link. Paid links must be refunded in Customer Area › Payments › Payment list.

See how to create and manage payment links for the normal workflow.

Receipts do not print or email

Printing: check that the connected terminal actually has a printer. Look in Settings › About and run a connection test. Review Settings › Receipts for printer detection and automatic printing, then try Print test receipt. Setting printer availability manually cannot add a printer to an AMS1 or Tap to Pay phone.

Email: send a test from Settings › Email. Check the server, port, STARTTLS/SSL, username and provider-required password. Your provider may require SMTP access or an app password, or block password authentication. Check automatic delivery and email capture in Settings › Payments separately. See email setup and provider instructions.

PIN and setup-transfer problems

Manager PIN: an administrator can replace or remove it in Settings › Security. The admin PIN and Manager PIN protect different actions; one does not automatically unlock the other.

Forgotten admin PIN: there is no PIN recovery. Clearing Android app data removes the PIN, but also all local products, settings, secrets and payment history. Resolve outstanding payments and preserve needed records first. A setup transfer does not restore transaction history. Reset only if you accept that loss.

Transfer code: use the code shown with those QR codes, not a newly generated one. A wrong code imports nothing; leaving it blank imports non-secret content only. Review any reported secret-storage failure and enter missing keys again. After copying setup, check the receiving device's destination and credentials; see devices and data.

See staff PIN setup to review which actions each PIN protects.

The app will not install on a terminal

INSTALL_PARSE_FAILED_NO_CERTIFICATES
The APK is unsigned. Upload the maintainer-signed minimpos-<version>.apk from the latest release.
INVALID_SIGNING_CERTIFICATE_MISMATCH
The upload uses a different signing key from earlier uploads. Keep the original signing source; ask Adyen Support about removing earlier versions if you intentionally need to change it.
Unsupported Android version
Mini mPOS needs Android 9 or later. The older S1E's Android 7.1 is not supported.

Follow the installation instructions for your device.

Still need help?

For Adyen accounts, terminal deployment, payment-method enablement or final payment outcomes, contact Adyen. For an app problem, open a GitHub issue with the app version, device model, payment setup, TEST/LIVE environment and steps to reproduce.

Do not include keys, passwords, PINs or customer data. Report suspected vulnerabilities privately under the security policy.
