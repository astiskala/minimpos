指南

快速入门

从 Adyen 账户到终端上的第一笔支付。大部分配置只需在 Adyen 商户后台和 Mini mPOS 的设置中完成一次。请预留约半小时，另加 Adyen 部署应用所需的时间。

1. 开始之前

  • 一个已开通线下支付（Terminal API）的 Adyen 账户，以及能够查看设备设置、上传应用和管理支付的商户后台用户。
  • 运行 Android 9 或更高版本的 Adyen Android 支付终端，例如 S1F2、S1F4Pro、S1E4Pro、S1E2L、AMS1、S1U2 或 SFO1。打印需要终端配备打印机；扫描收据、条形码和另一台终端的设置二维码需要摄像头。
  • 或者一台 Android 平板电脑或手机，用于通过本地网络或互联网在终端上收款，或使用 Tap to Pay 收款（见在平板电脑或手机上使用）。
  • 可选：如果要通过电子邮件发送收据，请准备一个 SMTP 邮件服务器及其主机地址、端口、用户名和密码。
  • 可选：如果希望应用直接为收据小费和预授权扣款，请准备 Adyen Checkout API 的 API 凭据（参见扣款与 Checkout API）。

Mini mPOS 是独立项目，并非 Adyen 产品。在接受真实支付之前，请先在 TEST 终端上充分测试。

2. 没有终端也能试用

在 Android 模拟器或手机上，Mini mPOS 使用内置支付模拟器模拟支付，让您先体验所有界面。通过源代码安装：

git clone https://github.com/astiskala/minimpos.git
cd minimpos
./gradlew :app:installDebug

在设置 › 模拟器中，可以选择模拟支付的结果：成功、被拒绝、已取消、超时或终端忙碌。模拟器也会模拟 Checkout API，因此还可以试用小费和扣款功能。

3. 创建共享密钥

Mini mPOS 使用共享密钥加密发送给终端的每个请求。请在商户后台创建密钥：

  1. 为将运行 Mini mPOS 的终端（或所属门店或账户）打开 Devices › Device settings › Integrations › Terminal API › Encryption key。
  2. 创建密钥，记下密钥标识符、密钥口令和密钥版本。以后可以点击铅笔图标再次查看。

4. 将应用安装到终端

  1. 从最新发布版本下载 minimpos-<version>.apk。该文件已由维护者签名，这是 Adyen 的要求；未签名的 APK 可以上传，但终端会拒绝安装。
  2. 按照 Adyen 的应用部署指南上传文件并部署到终端。Adyen 会转换应用，并安装到您选择的终端。

也可以自行构建并签名 APK；参见 README。无论选择哪种方式，都请保持一致：商户后台只接受使用同一密钥签名的后续版本。

5. 连接支付终端

  1. 在终端上打开 Mini mPOS，点击首页的连接此终端，或进入设置 › 终端。
  2. 输入密钥标识符和密钥口令；如果密钥版本不是 1，也需要填写版本。
  3. 点击保存并测试，或键盘的“完成”键。结果会立即显示。

应用会自动检测终端 ID（POIID）、地址以及 TEST 或 LIVE 环境，无需填写其他信息。设置 › 关于会显示检测结果；TEST 终端的系统状态栏也会显示 TEST。

如果要从手机或模拟器连接真实终端，请将支付目标设为同一网络中的终端，并输入终端的 IP 地址和 POIID（见终端的 Device info 界面）。

在平板电脑或手机上使用

Mini mPOS 也可以在 Android 平板电脑和手机上运行：安装同一个 APK，然后在设置 › 终端 › 支付目标中选择：

同一网络中的终端
柜台平板电脑的推荐方式。平板电脑通过本地网络向终端发送请求，并使用共享密钥加密，因此无需 API 密钥。除共享密钥外，还需输入终端的 IP 地址和 POIID。终端上无需安装 Mini mPOS。
通过互联网连接的终端（云端）
适用于平板电脑和终端不在同一网络的情况。请求经由 Adyen 的 Cloud device API 发送，使用 API 密钥代替共享密钥。请在商户后台的 Developers › API credentials 中为本设备创建具有 Cloud Device API 角色的凭据（如需应用为小费和预授权扣款，再加上 Checkout webservice role）。在 Adyen API 下输入商家账户和 API 密钥，然后点击查找已连接的终端并选择终端（或输入其 POIID）。连接时会自动判断密钥属于 TEST 还是 LIVE，以及要使用的数据中心。
在本手机上使用 Tap to Pay
顾客在本手机上的 Adyen Payments 应用中轻触银行卡或手机付款；没有打印机，收据通过电子邮件发送。手机需支持 NFC、运行 Android 12 或更高版本，并通过 Google 认证。请让 Adyen 支持团队开通 Tap to Pay on Android 和 Adyen Payments app role，并从 Google Play 安装 Adyen Payments Test（TEST）或 Adyen Payments（LIVE）。输入共享密钥和商家账户，然后在 Tap to Pay 下输入 Payments 应用 API 密钥（仅具有 Adyen Payments app role 的凭据）；如只为一家门店设置，还需输入门店 ID。点击设置 Tap to Pay，Payments 应用会打开以注册本手机。之后每笔付款都会打开 Payments 应用，再返回 Mini mPOS。如要停用，请点击移除本手机。

在云端模式和 Tap to Pay 模式下，Adyen API 密钥会保存在设备上，并通过 Android Keystore 加密。Adyen 建议将 API 密钥保存在服务器上，而 Mini mPOS 没有服务器：请为本设备使用专用凭据，设置管理员 PIN，并在设备丢失时于商户后台撤销该密钥。

6. 设置您的业务

以下选项均位于设置中。

支付
币种（Adyen 支持的 138 种币种；自动选择会跟随设备所在国家或地区）、是否在结账时询问交易识别号及其前缀、保存卡片设置（普通销售和预授权的默认开关、循环扣款模式、购物者识别号来自客户识别号还是电子邮箱）、何时询问购物者的电子邮箱，以及结账时是否默认启用在收据上填写小费。
税
自定义名称的税率（例如 GST 10% 和 GST-free 0%）、价格是否含税、新商品的默认税率，以及收取税费开关。
收据
商家名称、地址、税号、电话、标题和页脚；收据显示内容（税费明细、识别号、退款二维码）；终端是否配有打印机（默认自动检测）、自动打印、商家联以及每行字符宽度。
电子邮件（SMTP）
邮件服务器、发件人、可选密送地址和邮件主题，以及测试邮件功能。
安全
用于保护设置和商品管理的管理员 PIN，以及自动重新锁定的时间。请在把终端放到柜台上之前设置 PIN 码。
数据
销售和退款记录的保留时间、清空交易记录，以及用此终端设置其他终端（参见更多终端）。

语言与收据

Mini mPOS 支持英语、简体中文和日语。在 Android 12 及更早版本上，应用跟随设备语言；在 Android 13 及更高版本上，可通过 Android 系统的应用语言设置选择语言。

新安装会使用本地化的收据默认值和示例标签。切换语言不会翻译或覆盖已有的收据标题、页脚、税率名称、邮件主题或传输导入的商品目录。尤其在使用已有配置或从另一台终端导入后，请在设置 › 收据、设置 › 税、设置 › 电子邮件（SMTP）和商品中检查并按需修改。

Adyen 生成的支付收据数据保留原文，并遵循支付终端自身配置的收据语言。纯文本收据排版将中日文宽字符按两列计算。日语收据还按税率显示应税金额，标记为 税込（含税）或 税抜（不含税）。请使用设置 › 收据 › 打印测试收据检查实际打印效果。

Mini mPOS 提供的是收据，不是中国税务机关认可的发票，也不保证符合日本適格請求書或適格簡易請求書的要求。仅显示各税率合计并不等于完整支持发票制度。减低税率商品标记、税额舍入、税务登记及其他适用要求需另行核实。背景资料可参考日本国税厅的適格簡易請求書说明和国家税务总局全国增值税发票查验平台。这些链接仅供参考，不代表合规保证，也不是法律意见。

7. 添加商品

在商品中点击 +，输入名称、价格和税率，也可以添加分类和条形码（手动输入或扫描）。第二个标签页中的分类会对销售界面的商品进行分组。

商品也可以设为预授权商品，例如订金或租赁押金；参见预授权。

要将商品目录复制到另一台终端，请参见更多终端。

8. 销售与退款

  • 新建销售：点击商品、扫描条形码或添加自定义金额，然后点击收款。在结账时填写识别号，并在取得购物者同意后选择保存卡片，再点击支付并按终端提示操作。
  • 收据将商家抬头、商品、税费、卡片收据和退款二维码整合打印，也可以通过电子邮件发送。
  • 退款：扫描收据上的二维码，或在交易记录中打开销售记录。可以全额退款、按商品退款或输入退款金额。Adyen 异步处理退款，因此应用显示为已请求退款；最终结果请在商户后台查看。
  • 交易记录按日分组交易，并显示每日合计和小费。需处理会列出结果未确认的支付，您可以再次向终端查询结果。
  • 查找交易：在交易记录的搜索框输入内容（小屏终端请先点击搜索图标）：商家识别号、PSP 识别号、授权码、客户识别号、购物者电子邮箱、卡号后 4 位，或金额，例如 34 或 34.50。每个搜索词都必须匹配，因此 visa 34 会找到金额为 $34.00 的 Visa 支付；搜索原销售的购物者或卡片信息也能找到对应退款。筛选栏开头的付款方式可按卡品牌或钱包（Apple Pay、Google Pay、Samsung Pay）缩小范围。

9. 扣款与 Checkout API

收据小费和预授权使用手动扣款：在扣款前只冻结金额。Mini mPOS 可以通过 Adyen Checkout API 扣款并调整冻结金额，也可以由您在商户后台完成扣款。

  1. 在商户后台打开 Developers › API credentials，为终端创建仅具有 Checkout webservice role 的凭据，并生成 API 密钥。
  2. 在 Mini mPOS 中进入设置 › 终端 › Checkout API，输入商家账户和 API 密钥，然后点击保存并测试 API 密钥。密钥在终端上加密存储；测试不会更改支付。
  3. LIVE 终端还需要 live URL prefix，可在 Developers › API URLs 中找到。应用通过终端证书判断 TEST 或 LIVE 环境（云端模式根据 API 密钥判断，Tap to Pay 根据已安装的 Payments 应用判断）。
  4. 可选：在 Devices › Developer › Additional data › Return adjust authorisation data 中启用同步授权调整。这样应用能立即得知更高金额是否获批；否则需稍后在商户后台确认调整结果。

Adyen 异步确认扣款，因此应用会显示已请求扣款。Mini mPOS 没有接收 webhook 的后端，最终结果请在商户后台查看。结果未知的扣款可以从交易记录再次发送，不会重复扣款。

没有 API 密钥时，应用会记录待扣款金额并显示在商户后台扣款。请在 Payments › Payment list 中选择交易记录所示的 PSP 识别号，然后点击 Capture payment。

10. 收据小费

对于餐厅和酒吧等在支付后添加小费的场景，Mini mPOS 遵循 Adyen 的收据小费流程：先对账单金额进行预授权，由顾客在打印的收据上填写小费并签名，再对账单加小费的总额扣款。

在 Adyen 完成一次性设置

  • 请联系 Adyen Support，为您的付款方式配置预授权并启用 overcapture（超额扣款）：不超过账单金额 20% 的小费可在已授权金额之上直接扣款。钱包和借记卡可能不支持此流程。
  • 可选但建议：配置 Checkout API，让应用直接为小费扣款。

在 Mini mPOS 中操作

  1. 结账时开启在收据上填写小费（仅在有打印机的终端上显示；可在设置 › 支付 › 小费中设为默认开启），然后点击支付。
  2. 结果会显示待填写小费。打印收据，上面会有空白的小费和合计栏；商家联还会有持卡人签名栏（默认商家联设置下，在客户联之后打印）。
  3. 顾客填写后，在结果界面或稍后的交易记录中点击输入小费（待填写小费筛选会列出相关交易）。输入小费或总额，也可以点击无小费，然后确认。

应用随后会为账单加小费的总额扣款。超过账单金额 20% 的小费会先请求授权；如果发卡行拒绝，则不会扣款，您可以输入较少的小费或不收小费。小费一旦录入就不能更改，此后该销售可像其他销售一样退款，包括小费。在录入小费之前，只能从交易记录中取消该销售。

冻结金额会到期，请及时录入小费，例如在每个班次结束时处理。

11. 预授权

预授权会在购物者的卡上冻结一笔金额，而不立即扣款，例如活动、客房或设备租赁的订金。您可以稍后按实际应收金额扣款（在冻结额度以内），或取消预授权以解除冻结。

在 Adyen 完成一次性设置

  • 请联系 Adyen Support，为您的付款方式配置预授权。卡片是否支持取决于卡组织和您的商家类别码（MCC）；参见 Adyen 的预授权指南。
  • 无需将整个账户切换为手动扣款：Mini mPOS 仅对每笔预授权请求手动扣款（authorisationType=PreAuth 和 manualCapture=true），普通销售仍按账户原有设置扣款。
  • 可选：smart pre-authorization（商户后台的 Devices › Device settings › Payment features）可让终端在当前卡不支持时提示更换卡片。

在 Mini mPOS 中操作

  1. 在商品中编辑或添加商品，开启预授权商品。该商品不再出现在新建销售中。
  2. 首页会在新建销售旁显示预授权。每笔预授权包含一个商品，因此点击商品、添加自定义金额或扫描条形码后会直接进入结账；在那里点击预授权。
  3. 结账时默认启用保存卡片（设置 › 支付 › 保存卡片；需取得购物者同意），以便预授权扣款后收取后续费用。收据标题为预授权凭证，并显示冻结金额。

扣款、调整或取消

  • 扣款：在交易记录中打开预授权，点击扣款。默认金额为冻结金额；扣款金额较少会释放剩余额度，扣款金额更高则会先向发卡行请求授权。扣款后可以从交易记录退款。
  • 调整金额会更改冻结金额，但不扣款；提交相同金额会延长授权。
  • 这两项操作都需要 Checkout API。没有 API 时，请在商户后台扣款（Payments › Payment list，选择 PSP 识别号，再点击 Capture payment），然后在应用中点击记录扣款，以便交易记录反映该操作。
  • 取消：点击取消预授权。如果已经在商户后台完成扣款，Adyen 会改为全额退款。

冻结金额会到期，某些卡组织可能仅保留几天；在此期间，购物者的账单上会显示为待处理金额。请及时扣款或取消。交易记录的预授权筛选会列出这些交易，每日合计会显示仍冻结的金额。

12. 更多终端

配置好一台终端后，可以通过几个二维码设置其他终端，无需重复输入。请在所有终端上安装相同版本的 Mini mPOS。

  1. 在已配置的终端上进入设置 › 数据 › 共享至另一台终端，或打开商品菜单。选择要复制的商品目录、设置以及密码和密钥（共享密钥口令、Checkout API 密钥、Payments 应用 API 密钥、SMTP 密码和管理员 PIN），然后点击显示二维码。
  2. 在新终端的相同位置选择从另一台终端设置，用摄像头扫描二维码，顺序不限。
  3. 选择合并到此商品目录或替换此商品目录。要导入密码和密钥，请输入第一台终端在二维码上方显示的传输码；不输入时会导入其他内容，但跳过密码和密钥。点击导入。
  4. 在设置 › 终端中点击测试连接，检查连接。

导入的设置会替换新终端的设置，但不更改支付目标、终端自己的地址和 ID、Tap to Pay 设置、TEST/LIVE 环境或模拟器设置。共享密钥只有在商户后台为两台终端分配相同密钥时才适用（例如在门店或商家账户级别配置）；否则请分别输入各终端的密钥。每次传输都会生成新的传输码，并且只在第一台终端显示，因此仅拍摄二维码不会泄露密码。

13. 正式上线之前

  • 在 TEST 终端上使用 Adyen 的测试卡进行几笔销售和退款；如果使用小费或预授权，也请一并测试。
  • 在设置 › 收据 › 打印测试收据中检查收据布局。
  • 设置管理员 PIN，再将相同版本部署到 LIVE 终端，并输入它们的共享密钥。

14. 出现问题时

首页显示“无法连接支付终端”
将设置 › 终端中的密钥标识符、口令和版本与商户后台的信息核对，然后点击保存并测试。
终端拒绝安装应用
INSTALL_PARSE_FAILED_NO_CERTIFICATES 等错误表示 APK 未签名。请上传发布页面提供的已签名 minimpos-<version>.apk。
支付结果未知
从交易记录的需处理中打开该支付，点击重新查询结果。再次向购物者收款之前，请先检查商户后台。
扣款失败或结果未知
交易记录会显示原因。如有需要，请修正 Checkout API 设置，再点击重试扣款：再次发送不会重复扣款。
Tap to Pay 返回时没有结果
此时付款结果未知，且无法再次向 Payments 应用查询：在再次向顾客收款前，请先在商户后台（Payments › Payment list）中确认。
显示“无法读取二维码”
另一台终端可能运行更新的 Mini mPOS。请将两台终端更新到相同版本，再次扫描。

仍有问题？请在 GitHub 上提交 issue。
