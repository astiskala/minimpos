付款或退款的结果未知

不要仅因应用没有响应就再次收款或退款。请求可能已到达 Adyen，请先查询原操作。

  1. 打开交易记录 › 需处理，选择原付款或退款。
  2. 点击重新查询结果。对于本地或云端终端，应用会查询原交易的结果。
  3. 仍未知时，按识别号、时间和金额检查商户后台 › Payments › Payment list，再决定下一步。

崩溃或重启后，中断的操作仍以未知状态保留。不要通过清除应用数据解决此问题。

Tap to Pay 返回时没有响应

Payments 应用无法查询交易状态。重新查询结果可使用迟到的响应，但不能远程获取。若没有响应，再次收款前请检查商户后台。

终端忙碌

完成终端上的其他付款或退出管理菜单。若结果界面提供取消终端当前交易，仅在确实要停止该交易时使用，再查询结果后重试。Tap to Pay 不支持此命令。

付款未配置或无法连接终端

先看首页设置提示，再打开设置 › 终端，完成编号步骤并运行连接和 API 测试。必要时参阅对应配置的连接说明。

本终端或同一网络中的终端
将共享密钥的标识符、口令和版本与商户后台核对。网络模式下还需检查终端当前 IP 地址和 POIID，以及同一网络中的两台设备能否相互连接。
云端
检查商家账户、终端 POIID，以及凭据的 Cloud Device API 和 Checkout webservice 角色。确认终端在线；断线终端无法处理云端付款。
Tap to Pay
安装对应环境的 Payments 应用，不要同时安装 TEST 和 LIVE。完成注册并输入共享密钥。成功的配置检查并不测试银行卡付款。
Checkout API
所有真实付款配置都需要它。核对商家账户和密钥；LIVE 还需要 live URL prefix。保存的密钥无法读取时请重新输入。
环境错误
网络或云端终端请检查“设置 › 终端”步骤 1 的环境，使用匹配的终端、商家账户和 API 密钥。网络证书不匹配时会拒绝连接，API 调用不会自动切换环境。在 Adyen 终端上运行或使用 Tap to Pay 时，请使用正确的设备或 Payments 应用。参阅设置步骤。

更换商家账户、环境或终端后，旧付款的操作可能被阻止。恢复处理该付款时的配置，或在商户后台处理，不要尝试用另一个账户处理。

扣款或调整失败或结果未知

从交易记录打开原记录并查看原因。补全 Checkout API 设置，或恢复付款的原账户和环境。

  • 重试扣款使用相同标识再次发送已存储的扣款。使用此操作，而不是创建新的付款。
  • 未解决的金额调整应重试原金额；不同金额是独立操作，可能需先解决原操作。
  • 若发卡行拒绝小费增额，选择较少小费或无小费。增额被拒时小费不会保存。
  • 已请求扣款、已请求退款及异步调整被接受都不是最终确认。请检查商户后台；Mini mPOS 无法接收确认 webhook。

流程要求参见订金和收据小费。冻结金额会到期，请及时处理。

支付链接未显示或不更新

真实付款配置下，结账没有创建支付链接时，在设置 › 终端完成 Checkout API 设置。链接会自动为销售提供，不用于预授权或收据小费。离线演示请参阅支付链接。

应用仅在链接界面打开时查询，不会持续后台查询。从交易记录重新打开并点击查询支付状态。待支付记录不计入合计。

创建链接中断且结果未知时，打开原记录并点击查询支付状态，会使用原请求重试创建。不要仅为获取链接创建另一笔销售。已支付链接必须在商户后台 › Payments › Payment list退款。

正常流程请参阅创建和管理支付链接。

收据无法打印或发送邮件

打印：确认连接的终端确有打印机，查看设置 › 关于并测试连接。在设置 › 收据中检查打印机检测和自动打印，再打印测试收据。手动设置打印机可用并不能为 AMS1 或 Tap to Pay 手机添加打印机。

邮件：从设置 › 电子邮件发送测试，检查服务器、端口、STARTTLS/SSL、用户名和服务商要求的密码。服务商可能要求开通 SMTP、使用应用密码，或禁止密码认证。另行检查“设置 › 支付”的自动发送和邮箱采集。参见邮件设置及服务商说明。

PIN 和设置传输问题

经理 PIN：管理员可在“设置 › 安全”更换或移除。管理员 PIN 和经理 PIN 保护不同操作，其中一个不会自动解锁另一个。

忘记管理员 PIN：没有 PIN 恢复功能。清除 Android 应用数据会移除 PIN，也会删除全部本地商品、设置、秘密信息和交易记录。先解决未完成付款并保留所需记录。设置传输不能恢复交易记录。仅在接受数据丢失时重置。

传输码：使用与这些二维码一起显示的码，而不是新生成的码。错误码不会导入任何内容，留空仅导入非秘密内容。检查秘密信息存储失败提示，重新输入缺少的密钥。复制后检查接收设备的支付目标及凭据，参见设备和数据。

各 PIN 保护的操作请参阅员工 PIN 设置。

终端无法安装应用

INSTALL_PARSE_FAILED_NO_CERTIFICATES
APK 未签名。请上传最新版本中维护者签名的 minimpos-<version>.apk。
INVALID_SIGNING_CERTIFICATE_MISMATCH
本次上传的签名密钥与之前不同。保持原签名来源；确需更换时向 Adyen 支持团队咨询移除旧版本。
不支持的 Android 版本
Mini mPOS 需要 Android 9 或更高版本，不支持旧 S1E 的 Android 7.1。

请遵循对应设备的安装说明。
