付款或退款显示“结果未知”

警告

不要仅因应用没有响应就再次收款或退款。请求可能已到达 Adyen。

  1. 打开交易记录，筛选需处理，打开原付款或退款。
  2. 点按重新查询结果。对于终端，应用会向终端查询该交易的结果。
  3. 如果结果仍未知，请按识别号、时间和金额在商户后台 › Payments › Payment list中查找该付款。确认后再决定下一步。

崩溃或重启后，中断的操作会以未知状态保留在交易记录中。不要通过清除应用数据来移除它。

使用 Tap to Pay 时，无法向 Payments 应用查询状态。重新查询结果只能使用已经送达的迟到响应。若没有响应，再次收款前请检查商户后台。

付款被拒绝或未处理

结果界面会显示状态、Adyen 给出的原因和建议。请按建议操作：

“请勿使用此卡重试。请购物者使用其他卡片或付款方式。”

原因发卡行因不会改变的原因拒绝了此卡（如卡片被冻结、受限或疑似欺诈），或此卡不允许用于本次付款。

解决请顾客改用其他卡片或付款方式。顾客的银行可以说明拒绝原因；Adyen 的拒绝原因解释了显示的原因。

“可以重试。”

原因付款被取消、PIN 输入错误，或卡片因可能不会重复的原因被拒绝（如余额不足）。

解决点按重试，或请顾客换一张卡。

“终端正在处理其他交易或显示管理菜单。”

原因终端正在处理另一笔付款或显示管理菜单。

解决完成另一笔付款或退出菜单后重试。如果界面提供取消终端当前交易，仅在确实要停止该交易时使用，并在重试前查询其结果。

“终端暂时不可用。”

原因终端或其读卡器暂时不可用。

解决稍候，确认终端已开机并已连接，然后重试。参见网络中断。

“终端未接受请求。重试前，请检查终端设置。”

原因终端拒绝了请求或不提供此服务，通常是设置或账户配置问题。

解决在设置 › 终端中运行测试；参见终端绑定和设置。如果测试通过，请联系 Adyen 检查终端配置。

“请勿再次收款：此次支付已成功。”

原因虽然终端报告了取消，但付款已获批准。

解决请勿再次收款。如果顾客不应付款，请为其退款。

终端绑定或设置失败

先查看首页的提示，再打开设置 › 终端，运行测试 API和测试连接。完整步骤请参阅连接 Adyen。

首页提示“请在终端设置中输入”某项信息

原因必填字段为空，或本设备无法读取已保存的密钥。

解决在设置 › 终端中填写缺少的信息，或重新输入密钥。

API 测试失败，或设置提示访问问题

原因API 密钥、商家账户或 LIVE URL 前缀有误，缺少角色，或凭据属于其他 Company 账户或环境。

解决按照凭据要求检查凭据的角色和访问范围。LIVE 请检查 LIVE URL 前缀。

“商家账户与终端当前分配的账户不一致。”

原因终端在 Adyen 中被分配到其他商家账户。

解决输入终端所分配的商家账户，或在商户后台重新分配终端。

Adyen 终端或网络终端的连接测试失败

原因共享密钥不一致，或 IP 地址、终端 ID（POIID）已过时。

解决将共享密钥的标识符、口令和版本与商户后台核对。网络终端还需在终端的“Device info”界面核对 IP 地址和 POIID。

连接因环境不一致被拒绝

原因混用了 TEST 和 LIVE：终端、账户和 API 密钥必须属于同一环境。

解决网络或云端终端请在设置 › 终端中检查环境。在 Adyen 终端上运行或使用 Tap to Pay 时，请使用正确环境的设备或 Payments 应用。

无法连接云端终端

原因终端离线、POIID 有误，或 API 密钥缺少 Cloud Device API role。

解决确认终端已开机并在线，再检查 POIID 和凭据的角色。

“同时安装了 TEST 和 LIVE 版 Adyen Payments 应用”

原因Tap to Pay 只能安装一个 Payments 应用。

解决卸载不用的那个，再完成注册并输入共享密钥。设置检查通过并不代表测试了银行卡付款，请完成一笔 TEST 付款。

“新密钥已保存。请更新此终端的配置”

原因加密密钥已在 Adyen 创建，但终端尚未加载。

解决在终端上打开 Admin menu › Config › Update，然后返回 Mini mPOS 点按再次检查。如果创建中断，请点按继续密钥设置，不会创建第二个密钥。参见密钥创建及 Adyen 的配置更新。

旧付款的操作被阻止

原因该付款之后更换了商家账户、环境或终端。

解决恢复处理该付款时的配置，或在商户后台处理。不要用另一个账户处理它。

连接中断或终端未响应

重要

如果连接中断时有付款正在进行，再次收款前请查询其结果。

“终端未响应”，或网络终端时好时坏

原因终端的 IP 地址已变化、设备换到了其他网络，或网络阻止了连接。

解决

  1. 在终端的“Device info”界面查看 IP 地址，并在设置 › 终端中更新。
  2. 将设备和终端连接到同一网络。避免使用访客 Wi-Fi，它通常会隔离设备。
  3. 请网络管理员放行两者之间的 TCP 8443，并为终端保留 IP 地址；参见网络要求。
所有配置的付款或 API 测试都失败

原因设备或终端无法访问互联网，或防火墙阻止了 Adyen。

解决检查互联网连接，并确认已放行到 Adyen 域名的 TCP 443 HTTPS 连接。

云端付款超时

原因终端失去了互联网连接。

解决检查终端的 Wi-Fi、以太网或移动数据，然后运行测试连接。

扣款或调整失败或结果未知

在交易记录中打开原记录并查看原因。如果缺少 Checkout API 设置，请补全；如果账户或环境已更改，请恢复原配置。

扣款失败或扣款结果未知

解决点按重试扣款。它会安全地重新发送同一扣款请求；不要创建新的付款。

金额调整未解决

解决使用相同金额重试。不同金额是独立请求，可能需先解决第一个请求。

小费未保存

原因小费超过 20% 时，发卡行拒绝增加冻结金额。

解决输入较少的小费，或点按无小费。

已请求扣款或已请求退款一直不变

原因这表示 Adyen 已接受请求。Mini mPOS 没有服务器，无法收到最终确认。

解决请在商户后台确认最终结果。

冻结金额会到期，请及时处理。正常步骤请参阅订金和收据小费。

支付链接未显示或不更新

结账时没有创建支付链接

原因Checkout API 设置未完成，或本次结账是预授权或收据小费。

解决在设置 › 终端中完成 Checkout API 设置。链接仅用于销售。离线演示请参阅支付链接。

已支付的链接仍显示待支付

原因应用仅在链接界面打开时查询。

解决在交易记录中打开该记录，点按查询支付状态。

创建链接时中断

解决打开原记录并点按查询支付状态，会使用原请求重试；不要仅为获取链接创建另一笔销售。

已支付的链接请在商户后台 › Payments › Payment list中退款。

打印机或电子收据无法使用

无法打印，或没有打印收据

原因终端没有打印机、未检测到打印机，或连接中断。AMS1 终端和 Tap to Pay 手机没有打印机。

解决

  1. 在设置 › 关于中确认打印机显示可用。否则请在设置 › 终端中运行测试连接。
  2. 在设置 › 收据中将打印机设为自动检测，并检查支付后自动打印。
  3. 点按打印测试收据。如果仍无法打印，请检查终端的收据纸卷。
排版被截断或换行异常

解决在设置 › 收据中更改每行字符宽度，然后打印测试收据。

测试邮件发送失败

原因服务器、端口、安全方式或密码有误，或服务商禁止 SMTP 或密码登录。

解决在设置 › 电子邮件（SMTP）中检查服务器、端口、STARTTLS 或 SSL/TLS、用户名和密码。服务商可能要求开通 SMTP 或使用应用密码；参见邮件设置。

测试邮件正常，但顾客收不到收据

解决在设置 › 支付 › 电子收据中检查何时询问邮箱以及是否自动发送收据。

PIN 和设置传输问题

员工忘记了经理 PIN

解决管理员可在设置 › 安全中更换或移除。管理员 PIN 和经理 PIN 保护不同的操作，其中一个不会解锁另一个。

忘记了管理员 PIN

原因没有 PIN 恢复功能。

解决唯一的方法是在 Android 中清除应用数据。

警告

清除应用数据会删除设备上的全部商品、设置、密钥和交易记录。请先处理未完成的付款并保留所需记录。设置传输不能恢复交易记录。

传输码被拒绝，或导入后缺少密钥

原因传输码与这些二维码不匹配，或未填写。

解决使用与这些二维码一起显示的传输码，而不是新生成的码。错误的码不会导入任何内容；留空会跳过密码和密钥。复制后，请检查新设备的支付目标和凭据；参见更多设备。

各 PIN 保护的操作请参阅员工 PIN。

终端无法安装应用

INSTALL_PARSE_FAILED_NO_CERTIFICATES

原因APK 未签名。

解决上传最新发布版本中已签名的 minimpos-<version>.apk。

INVALID_SIGNING_CERTIFICATE_MISMATCH

原因APK 的签名密钥与之前上传的不同。

解决保持原签名来源。确需更换时，请向 Adyen 支持团队咨询移除旧版本。

不支持的 Android 版本

原因Mini mPOS 需要 Android 9 或更高版本；旧款 S1E 运行 Android 7.1。

解决使用受支持的终端；参见安装。
