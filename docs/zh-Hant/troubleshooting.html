付款或退款顯示“結果未知”

警告

不要僅因應用程式沒有回應就再次收款或退款。請求可能已到達 Adyen。

  1. 打開交易紀錄，篩選需處理，打開原付款或退款。
  2. 點按重新查詢結果。對於終端，應用程式會向終端查詢該交易的結果。
  3. 如果結果仍未知，請按參考編號、時間和金額在商戶後台 › Payments › Payment list中查找該付款。確認後再決定下一步。

崩潰或重啟後，中斷的操作會以未知狀態保留在交易紀錄中。不要通過清除應用程式資料來移除它。

使用 Tap to Pay 時，無法向 Payments 應用程式查詢狀態。重新查詢結果只能使用已經送達的遲到回應。若沒有回應，再次收款前請檢查商戶後台。

付款被拒絕或未處理

結果畫面會顯示狀態、Adyen 給出的原因和建議。請按建議操作：

“請勿使用此卡重試。請購物者使用其他卡或付款方式。”

原因發卡行因不會改變的原因拒絕了此卡（如卡被凍結、受限或疑似欺詐），或此卡不允許用於本次付款。

解決請顧客改用其他卡或付款方式。顧客的銀行可以說明拒絕原因；Adyen 拒絕原因解釋了顯示的原因。

“可以重試。”

原因付款被取消、PIN 輸入錯誤，或卡因可能不會重復的原因被拒絕（如餘額不足）。

解決點按重試，或請顧客換一張卡。

“終端正在處理其他交易或顯示管理選單。”

原因終端正在處理另一筆付款或顯示管理選單。

解決完成另一筆付款或退出選單後重試。如果畫面提供取消終端目前交易，僅在確實要停止該交易時使用，並在重試前查詢其結果。

“終端暫時不可用。”

原因終端或其讀卡器暫時不可用。

解決稍候，確認終端已開機並已連接，然後重試。參見網絡中斷。

“終端未接受請求。重試前，請檢查終端設定。”

原因終端拒絕了請求或不提供此服務，通常是設定或帳戶設定問題。

解決在設定 › 終端中運行測試；參見終端綁定和設定。如果測試通過，請聯繫 Adyen 檢查終端設定。

“請勿再次收款：此次支付已成功。”

原因雖然終端報告了取消，但付款已獲批准。

解決請勿再次收款。如果顧客不應付款，請為其退款。

沒有掃描錢包按鈕或掃描失敗

沒有掃描錢包按鈕

打開設定 › 終端，點按重新整理掃碼錢包。成功查詢後沒有符合條件的 POS 錢包時，按鈕會保持隱藏。核對終端店舖、目前貨幣和可選查詢權限。Tap to Pay 和預授權不提供此功能。

錢包查詢報錯

錯誤僅顯示在設定中，不會阻止普通支付。請檢查憑據、環境和只讀存取權限。設定未變時，臨時重新整理錯誤會保留最近驗證的錢包列表；成功查詢到空列表或存取失敗會移除它。只在啟動、設定改變或手動重新整理時查詢，不會在每筆銷售前查詢。

付款碼無效或未收到付款碼

請使用顧客的付款碼，而非個人資料、設定轉移或收據二維碼，並選擇正確的錢包。終端掃描最多持續 30 秒，之後點按重新掃描或使用相機。相機提示時請授予權限。應用程式從後台返回後需重新開始掃描。

儲存被拒絕或未建立代碼

請以支付結果為準。沒有儲存代碼的已批准付款仍然有效。僅在明確被拒絕後，如需重試，返回結帳，關閉儲存卡並明確開始新掃描。應用程式不會自動重新付款。結果未知時應查詢原交易。

PayMe 掃碼被拒絕

PayMe 商戶掃碼是盡力嘗試，與 Adyen 已發佈的限制相衝突。請顧客改用其他支付方式，或使用終端的普通錢包流程。模擬器批准不代表錢包實際支援此功能。

請參閱錢包支付步驟。交易紀錄中的請求錢包僅表示支付意圖，不證明付款成功或 Adyen 使用了該方式。

返回目錄

終端綁定或設定失敗

先查看首頁的提示，再打開設定 › 終端，運行測試 API。實體終端還需運行測試連接。Tap to Pay 則檢查 Payments 應用程式的註冊狀態。完整步驟請參閱連接 Adyen。

首頁提示“請在終端設定中輸入”某項資訊

原因必填欄位為空，或本設備無法讀取已儲存的密鑰。

解決在設定 › 終端中填寫缺少的資訊，或重新輸入密鑰。

API 測試失敗，或設定提示存取問題

原因API 密鑰、商戶帳戶或 LIVE URL 前置字元有誤，缺少角色，或憑據屬於其他 Company 帳戶或環境。

解決按照憑據要求檢查憑據的角色和存取範圍。LIVE 請檢查 LIVE URL 前置字元。

“商戶帳戶與終端目前分配的帳戶不一致。”

原因終端在 Adyen 中被分配到其他商戶帳戶。

解決輸入終端所分配的商戶帳戶，或在商戶後台重新分配終端。

Adyen 終端或網絡終端的連接測試失敗

原因共享密鑰不一致，或 IP 地址、終端 ID（POIID）已過時。

解決將共享密鑰的識別碼、口令和版本與商戶後台核對。網絡終端還需在終端的“Device info”畫面核對 IP 地址和 POIID。

連接因環境不一致被拒絕

原因混用了 TEST 和 LIVE：終端、帳戶和 API 密鑰必須屬於同一環境。

解決網絡或雲端終端請在設定 › 終端中檢查環境。在 Adyen 終端上運行或使用 Tap to Pay 時，請使用正確環境的設備或 Payments 應用程式。

無法連接雲端終端

原因終端離線、POIID 有誤，或 API 密鑰缺少 Cloud Device API role。

解決確認終端已開機並已連線，再檢查 POIID 和憑據的角色。

“同時安裝了 TEST 和 LIVE 版 Adyen Payments 應用程式”

原因Tap to Pay 只能安裝一個 Payments 應用程式。

解決解除安裝不用的那個，再完成註冊並輸入共享密鑰。設定檢查通過並不代表測試了銀行卡付款，請完成一筆 TEST 付款。

“新密鑰已儲存。請更新此終端的設定”

原因加密密鑰已在 Adyen 建立，但終端尚未載入。

解決在終端上打開 Admin menu › Config › Update，然後返回 Mini mPOS 點按再次檢查。如果建立中斷，請點按繼續密鑰設定，不會建立第二個密鑰。參見密鑰建立及 Adyen 設定更新指南。

舊付款的操作被阻止

原因該付款之後更換了商戶帳戶、環境或終端。

解決恢復處理該付款時的設定，或在商戶後台處理。不要用另一個帳戶處理它。

連接中斷或終端未回應

重要

如果連接中斷時有付款正在進行，再次收款前請查詢其結果。

“終端未回應”，或網絡終端時好時壞

原因終端的 IP 地址已變化、設備換到了其他網絡，或網絡阻止了連接。

解決

  1. 在終端的“Device info”畫面查看 IP 地址，並在設定 › 終端中更新。
  2. 將設備和終端連接到同一網絡。避免使用訪客 Wi-Fi，它通常會隔離設備。
  3. 請網絡管理員放行兩者之間的 TCP 8443，並為終端保留 IP 地址；參見網絡要求。
所有設定的付款或 API 測試都失敗

原因設備或終端無法存取互聯網，或防火牆阻止了 Adyen。

解決檢查互聯網連接，並確認已放行到 Adyen 域名的 TCP 443 HTTPS 連接。

雲端付款逾時

原因終端失去了互聯網連接。

解決檢查終端的 Wi-Fi、以太網或移動資料，然後運行測試連接。

返回目錄

扣款或調整失敗或結果未知

在交易紀錄中打開原紀錄並查看原因。如果缺少 Checkout API 設定，請補全；如果帳戶或環境已更改，請恢復原設定。

扣款失敗或扣款結果未知

解決點按重試扣款。它會安全地重新發送同一扣款請求；不要建立新的付款。

金額調整未解決

解決使用相同金額重試。不同金額是獨立請求，可能需先解決第一個請求。

小費未儲存

原因小費超過 20% 時，發卡行拒絕增加凍結金額。

解決輸入較少的小費，或點按無小費。

已請求扣款或已請求退款一直不變

原因這表示 Adyen 已接受請求。Mini mPOS 沒有伺服器，無法收到最終確認。

解決請在商戶後台確認最終結果。

凍結金額會到期，請及時處理。正常步驟請參閱訂金和收據小費。

返回目錄

支付連結未顯示或不更新

結帳時沒有建立支付連結

原因Checkout API 設定未完成，或本次結帳是預授權或收據小費。

解決在設定 › 終端中完成 Checkout API 設定。連結僅用於銷售。離線演示請參閱支付連結。

已支付的連結仍顯示待支付

原因應用程式僅在連結畫面打開時查詢。

解決在交易紀錄中打開該紀錄，點按查詢支付狀態。

建立連結時中斷

解決打開原紀錄並點按查詢支付狀態，會使用原請求重試；不要僅為取得連結建立另一筆銷售。

已支付的連結請在商戶後台 › Payments › Payment list中退款。

打印機或電子收據無法使用

無法列印，或沒有列印收據

原因終端沒有打印機、未檢測到打印機，或連接中斷。AMS1 終端和 Tap to Pay 手機沒有打印機。

解決

  1. 在設定 › 關於中確認打印機顯示可用。否則請在設定 › 終端中運行測試連接。
  2. 在設定 › 收據中將打印機設為自動檢測，並檢查支付後自動列印。
  3. 點按列印測試收據。如果仍無法列印，請檢查終端的收據紙捲。
排版被截斷或換行異常

解決在設定 › 收據中更改每行字元寬度，然後列印測試收據。

測試郵件發送失敗

原因伺服器、連接埠、安全方式或密碼有誤，或服務商禁止 SMTP 或密碼登入。

解決在設定 › 電子郵件（SMTP）中檢查伺服器、連接埠、STARTTLS 或 SSL/TLS、用戶名稱和密碼。服務商可能要求開通 SMTP 或使用應用程式密碼；參見郵件設定。

測試郵件正常，但顧客收不到收據

解決在設定 › 支付 › 電子收據中檢查何時詢問郵箱以及是否自動發送收據。

返回目錄

PIN 和設定傳輸問題

員工忘記了經理 PIN

解決管理員可在設定 › 安全中更換或移除。管理員 PIN 和經理 PIN 保護不同的操作，其中一個不會解鎖另一個。

忘記了管理員 PIN

原因沒有 PIN 恢復功能。

解決唯一的方法是在 Android 中清除應用程式資料。

警告

清除應用程式資料會刪除設備上的全部商品、設定、密鑰和交易紀錄。請先處理未完成的付款並保留所需紀錄。設定傳輸不能恢復交易紀錄。

傳輸碼被拒絕，或匯入後缺少密鑰

原因傳輸碼與這些二維碼不相符，或未填寫。

解決使用與這些二維碼一起顯示的傳輸碼，而不是新生成的碼。每次傳輸都需要傳輸碼。錯誤的碼或留空都不會匯入任何內容。複製後，請檢查新設備的支付目標和憑據；參見更多設備。

各 PIN 保護的操作請參閱員工 PIN。

返回目錄

終端無法安裝應用程式

INSTALL_PARSE_FAILED_NO_CERTIFICATES

原因APK 未簽名。

解決上傳最新發佈版本中已簽名的 minimpos-<version>.apk。

INVALID_SIGNING_CERTIFICATE_MISMATCH

原因APK 的簽名密鑰與之前上傳的不同。

解決保持原簽名來源。確需更換時，請向 Adyen 支援團隊咨詢移除舊版本。

不支援的 Android 版本

原因Mini mPOS 需要 Android 9 或更高版本；舊款 S1E 運行 Android 7.1。

解決使用受支援的終端；參見安裝。

出現錯誤訊息

每條訊息都會說明問題及需要檢查的內容。括號中的詳細資料（如 IP 地址、HTTP 狀態或 Adyen 的原文）有助 Adyen 支援團隊排查，尋求協助時請一併提供。如果有付款正在進行，請先查詢其結果，再處理其他問題。

“無法連接終端。請確認終端已開機、位於同一網絡，且 IP 地址正確。”

原因Mini mPOS 無法連接到所儲存 IP 地址上的網絡終端。

解決請參閱連接中斷。

“此地址不是所選環境中的 Adyen 終端。請檢查 IP 地址以及 TEST 或 LIVE。”

原因該地址有設備回應，但不是所選環境中的 Adyen 終端：該地址已分配給其他設備，或混用了 TEST 和 LIVE。

解決在終端的“Device info”畫面上核對 IP 地址，並檢查設定 › 終端中的環境。

“終端拒絕了共享密鑰。請在終端設定中檢查密鑰識別碼、版本及密碼短語。”

原因共享密鑰的識別碼、版本或密碼短語與終端上的不一致。

解決與商戶後台中的設定進行核對，或重新設定密鑰。

“無法驗證終端的回覆。請在終端設定中檢查共享密鑰。”

原因終端使用了不同的共享密鑰回覆，因此請求可能已送達終端。

解決再次收款前請先查詢結果，然後修正共享密鑰。

“終端未連接到 Adyen。請確認終端已開機並已連線。”

原因雲端終端已關機或沒有互聯網連接。

解決檢查終端的 Wi-Fi、以太網或流動數據，然後執行測試連接。

“Adyen 未接受 API 密鑰。請在終端設定中檢查。”

原因API 密鑰有誤、已被撤銷，或屬於另一個環境。

解決重新輸入密鑰，並對照憑證要求檢查。

“此 API 密鑰缺少所需角色或對此商戶帳戶的存取權限。請在商戶後台檢查 API 憑證。”

原因憑證缺少某個角色或對此商戶帳戶的存取權限。已知缺少的角色時，括號中會註明。

解決在商戶後台中新增該角色或帳戶存取權限；請參閱憑證要求。

“Adyen 繁忙或暫時無法使用。”

原因Adyen 正在限制請求，或暫時無法使用。

解決稍候片刻再重試。如果是付款、扣款或支付連結，請先查詢其結果。

“未能在限定時間內收到回應。”

原因請求已發出，但未收到回應，因此結果未知。

解決請查詢結果。在確認結果前，請勿再次收款。

“尚未收到 Payments 應用程式的回覆。無法向其查詢結果，請在商戶後台核實此次支付。”

原因使用 Tap to Pay 時，無法向 Payments 應用程式查詢結果，且尚未收到延遲的回覆。

解決再次收款前，請在商戶後台中查找此次付款。

“無法開啟 Adyen Payments 應用程式。請確認已安裝該應用程式。”

原因Payments 應用程式未安裝或已被移除。

解決安裝與您的環境對應的 Payments 應用程式，然後重試。請參閱連接 Adyen。

“郵件伺服器未接受使用者名稱或密碼。請在“設定 › 電子郵件”中檢查。”

原因SMTP 使用者名稱或密碼有誤，或郵件服務供應商要求使用應用程式專用密碼。

解決更正後傳送一封測試郵件。

“此設備的安全儲存空間無法使用。請重試或重啟設備。”

原因Android 金鑰庫無法加密或讀取已儲存的密鑰資料。

解決如果重新啟動後問題仍然存在，請重新輸入密鑰及密碼。
